## 二、段落 → 句子 → 词（从真实数据摘录）

### 段落

```jsonc
{
  "idx": 0,
  "text": "A multitasker is one who can perform two or more tasks effectively at the same time, which—apart from the obvious differences—is similar to what a computer does. The concept does indeed come from the ...",
  "sentences": [ /* 见下 */ ]
}
```

> 注意 `text` 里的破折号是**长破折号 `—`**（U+2014），不是 `-`。它算 1 个 UTF-16 code unit，但**不是 1 个字节**。这就是为什么必须用 code unit 而不是字节算偏移。

### 句子（真实数据，可直接对照）

```jsonc
{
  "idx": 0,
  "start": 0,
  "end": 161,
  "text": "A multitasker is one who can perform two or more tasks effectively at the same time, which—apart from the obvious differences—is similar to what a computer does.",
  "tokens": [ /* 见下 */ ],
  "analysis": { /* 见 §三 */ }
}
```

**手算验证**：`paragraph.text.slice(0, 161)` 应恰好得到上面这句 `text`。

### 词的偏移怎么算（最容易错的一步）

```jsonc
"tokens": [
  { "start": 0,  "end": 1,   "surface": "A",            "normalized": "a",            "isWord": true },
  { "start": 2,  "end": 13,  "surface": "multitasker",  "normalized": "multitasker",  "isWord": true },
  { "start": 14, "end": 16,  "surface": "is",           "normalized": "is",           "isWord": true },
  { "start": 17, "end": 20,  "surface": "one",          "normalized": "one",          "isWord": true },
  { "start": 21, "end": 24,  "surface": "who",          "normalized": "who",          "isWord": true }
]
```

**算法（照这个做，不要目测）**：

```javascript
// 给定句子原文 text，切出所有 token
const text = "A multitasker is one who can perform two or more tasks ...";
const tokens = [];
const re = /[A-Za-z0-9'’\-]+(?:[.,;:!?"()\[\]—–]|$)?/g;  // 粗略，实际按 §七 口径切
let m;
while ((m = re.exec(text)) !== null) {
  tokens.push({
    start: m.index,             // ← 就是 match.index，天然正确
    end:   m.index + m[0].length,
    surface: m[0],
    normalized: /* 你的归一化规则 */,
    isWord: /* 是否单词 */
  });
}
```

**关键**：用正则的 `match.index` / `match[0].length` 得到偏移，**绝对不要手数**。手数 350 个 token 必错。

**切分口径回顾**（详见 `01-数据结构规范.md` §五）：
- 空格**不属于任何 token**（所以 `A` 是 `[0,1)`、`multitasker` 是 `[2,13)`，位置 1 是空格）
- 标点单独成 token（`isWord: false`）
- 数字（`1997`、`150`）单独成 token（`isWord: false`）
- 选词填空的空号数字也是单独 token

### 标点 token 的样子

```jsonc
{ "start": 108, "end": 109, "surface": ".", "normalized": null, "isWord": false }
{ "start": 26,  "end": 27,  "surface": "\"", "normalized": null, "isWord": false }
```

> `normalized` 用 `null`（现有 6699 个 token 里 879 个标点如此）。空串 `""` 也接受，但 `null` 更规范。

## 三、`analysis`（六段，真实数据）

```jsonc
"analysis": {
  "translationLiteral": "多任务处理者是指能够同时有效完成两项或更多任务的人，这——除了明显的差异之外——与计算机所做的相似。",
  "translationNatural": "所谓“多任务处理者”，就是能同时高效做两件以上事的人；除了显而易见的差别，这跟电脑干的事很像。",

  "structMarkup": "【A multitasker】 _is_ ~one {who can perform two or more tasks effectively at the same time}~, {which—apart from the obvious differences—is similar to what a computer does}.",

  "structureSummary": "主系表 + 定语从句（who 修饰 one）+ 非限制性定语从句（which 指代前句）",

  "components": [
    { "part": "A multitasker", "role": "主语", "note": "a + 单数可数名词，表示「一类人」" },
    { "part": "is", "role": "系动词", "note": "主系表结构" },
    { "part": "one", "role": "表语", "note": "代词 one 指代 a person" },
    { "part": "who can perform two or more tasks effectively at the same time", "role": "定语从句", "note": "who 指代 one，作从句主语" }
  ],

  "clauses": [
    "who 引导定语从句，修饰 one，在从句中作主语。",
    "which 引导非限制性定语从句，指代前面整个主句内容。",
    "what a computer does：what 引导宾语从句（作 to 的宾语），what 在从句中作 does 的宾语，不能用 that。"
  ],

  "phrases": [
    {
      "text": "at the same time",
      "meaning": "同时",
      "usage": "作时间状语；也可表示让步「然而（用于对比）」：At the same time, we must be careful.",
      "example": "She was cooking and talking on the phone at the same time. 她一边做饭一边打电话。"
    }
  ],

  "pitfalls": [
    "which 前有逗号 → 非限制性定语从句，不能用 that。",
    "what a computer does：what 引导宾语从句，不能用 that。"
  ],

  "paragraphRole": "开篇定义“多任务处理者”，并用电脑类比，为后文质疑埋下伏笔。"
}
```

**注意几点**：
- `structMarkup` 里 `~one {who ...}~` 是**宾语标记包住从句**（`~...~` 在外、`{}` 在内），项目按**外层**切，解析为一个「宾语」段。这是允许的嵌套写法。
- `structMarkup` 去掉 `_` 和 `~` 后，**必须**与句子 `text` 一字不差（`【】{}()` 保留）。
- `translationLiteral` 故意保留英文语序（「这——除了明显的差异之外——与计算机所做的相似」），`translationNatural` 才写顺。**这两栏不能一样**。

## 四、题目（三种题型）

### 仔细阅读（careful）：4 选项

```jsonc
{
  "no": 51,
  "stem": "What does a \"multitasker\" originally refer to?",
  "options": [
    { "key": "A", "text": "An operating system capable of doing several tasks at once." },
    { "key": "B", "text": "A skilled worker executing more than one task at the same time." },
    { "key": "C", "text": "A sophisticated technology doing several tasks effectively at once." },
    { "key": "D", "text": "An efficient person able to perform multiple tasks at the same time." }
  ],
  "answer": "A"
}
```

> 题干里的引号要转义：`\"multitasker\"`。

### 长篇阅读（long）：**无选项**，答案是段落字母

```jsonc
{
  "no": 36,
  "stem": "In the absence of Federal legislation, some states in the US have passed laws concerning paid family leave.",
  "options": [],
  "answer": "D"
}
```

> `options` 必须是空数组。`answer` 是这句陈述出自的段落字母（`A`~`Z`）。
> **这一步最容易错**：把 long 型当 careful 型写成 4 个选项。

### 选词填空（cloze）：15 选项 + 空号解析


## 六、长篇阅读（long）与仔细阅读的唯一差别

| 项 | careful | long |
|---|---|---|
| `meta.section` | `仔细阅读` | `长篇阅读` |
| `meta.passageLabel` | `Passage One` / `Passage Two` | `信息匹配` |
| `questions[].options` | 4 项 A~D | **`[]` 空数组** |
| `questions[].answer` | `A`~`D` | **段落字母**（`A`~`Z`） |
| `questions[].stem` | 问句 | **一句陈述**（从某段摘出） |
| 段落数 | 4~8 | 12~17（每个字母段一个 paragraph） |
| 有 `blanks`/`wordBank` | 无 | 无 |

**long 型的段落与答案对应**：段落 `idx=0` 对应字母 `A`、`idx=1` → `B`、…… `answer: "D"` 表示那句陈述出自第 4 段（`idx=3`）。

## 七、一整句的完整对照（自查时照这个看）

以 `A multitasker is one who can perform two or more tasks effectively at the same time, which—apart from the obvious differences—is similar to what a computer does.` 为例：

| 检查项 | 值 |
|---|---|
| 句子长度（UTF-16） | 161 |
| `start` / `end` | `0` / `161` |
| 段落切片 `slice(0,161)` | == 句子 `text` ✅ |
| token 数 | 27（含 2 个逗号、1 个长破折号×2、1 个句号） |
| 首个 token | `A` `[0,1)` `isWord=true` `normalized="a"` |
| 标点 token | `,` `/` `.` `isWord=false` `normalized=null` |
| 符号句去 `_`/`~` 后 | == 句子 `text` ✅ |
| `_` 出现次数 | 1（`_is_` → 2 个下划线，偶数 ✅） |
| `~` 出现次数 | 2（`~one {...}~`，偶数 ✅） |

**手工验算符号平衡的方法**（写代码时也用这个）：

```javascript
const count = (s, ch) => s.split(ch).length - 1;
console.assert(count(structMarkup, "_") % 2 === 0, "下划线必须成对");
console.assert(count(structMarkup, "~") % 2 === 0, "波浪线必须成对");
// 括号类必须左=右
for (const [o, c] of [["【","】"],["{","}"],["(",")"]]) {
  console.assert(count(structMarkup, o) === count(structMarkup, c), `${o}${c} 不配对`);
}
```

## 八、生成顺序建议（减少返工）

1. **先切段落**：把原文按自然段拆开，每段一个 `paragraph`，`idx` 从 0 连续
2. **再切句子**：每段按 `.!?` 断句，算 `start`/`end`（**用正则 `match.index`**）
3. **再切 token**：每句按 §二 口径切，算偏移
4. **再写解析**：逐句填 `analysis` 九字段（这一步最花时间，也是最值钱的）
5. **最后写题目与词表**
6. **跑自检**：`node 04-self-check.mjs 你的文件.json`

先做完 1~3 就跑一次自检（此时 `analysis` 可以先填占位），**确认偏移全对**再投入时间写解析内容——否则解析写完才发现偏移错了，要重排。

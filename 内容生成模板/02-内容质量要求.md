# 02 · 内容质量要求

> 格式对了只是及格。这份文档管「内容好不好」——决定用户能不能真的靠它读懂句子。
> 项目定位：**点句看结构、点词看语境义**。所以解析的质量就是这个产品的质量。

---

## 一、三条核心标准（按优先级）

| 优先级 | 标准 | 说明 |
|---|---|---|
| 1 | **准确** | 语法判断、语义、答案都不能错。宁可少写，不能写错 |
| 2 | **完整** | 六段该有的都有；重点词有词条；每题有答案 |
| 3 | **简明** | 一段话说清一件事。不要堆术语，不要抄词典 |

**反例（准确性问题）**：把 `That's what important people say.` 的 `what` 从句说成「定语从句」——它是**表语从句**（`what important people say` 作表语）。这类错误会让用户学到错的东西，比不写更糟。

---

## 二、六段解析的写作要求

### ① 翻译：直译 + 顺译（本项目特色，别偷懒）

同一句给两种译法，**目的是让读者看清英文结构**：

| 类型 | 要求 | 例（`That's what important people say.`） |
|---|---|---|
| `translationLiteral`（直译） | **贴英文语序**，可以不像人话，要能看出「哪个词对应哪一块」 | 那是 重要人物所说的（话）。 |
| `translationNatural`（顺译） | 自然的汉语，能直接读懂 | 有身份的人才这么说。 |

**常见错误**：两栏写一模一样的句子。`直译` 要故意保留英文的语序痕迹（如「那是……所说的」），否则读者看不出结构。

### ② 符号句 `structMarkup` + 主干 `structureSummary`

**符号句的作用**：让读者一眼看到「哪块是主语、哪块是谓语、哪块是从句」。**必须与句子原文一字不差**（除括号保留、`_`/`~` 去掉）。

**成分判断口径**：

| 成分 | 标记 | 判断 |
|---|---|---|
| 主语 | `【】` | 谓语动词的主语（含主语从句、形式主语 it） |
| 谓语 | `_ _` | 限定动词（含情态动词/助动词 + 实义动词） |
| 宾语 | `~ ~` | 及物动词的宾语（含宾语从句） |
| 从句 | `{ }` | 定语从句、状语从句、同位语从句等**从属**分句 |
| 短语 | `( )` | 介词短语、不定式短语、分词短语（作状语/定语/补语） |

**`structureSummary` 写法**：一句话说清主干类型，格式 = 「主干类型 + （从句类型）」。例：
- `主谓 + 宾语从句（how 引导）`
- `主系表 + 表语从句（what 引导）`
- `主谓宾 + 定语从句（that 引导，修饰 studies）`
- `There be 句型 + 状语从句（when 引导）`

### ③ 成分表 `components`

每项 `{part, role, note}`：

```json
{"part":"A number of studies","role":"主语","note":"a number of + 复数，谓语用复数"}
{"part":"have looked at","role":"谓语","note":"look at 此处意为「研究、考察」"}
{"part":"how family life can affect productivity and satisfaction in the workplace","role":"宾语从句","note":"how 引导，用陈述语序"}
```

**要求**：
- 至少覆盖**主干**（主语 + 谓语 [+ 宾语]）
- `part` 是原文片段（可与符号句对应，但不必带标记符）
- `note` 写「为什么这么切」或「这里的用法特点」，**不要**只重复 `role`（写「主语」的 note 又写「主语」＝废话）

### ④ 从句 `clauses`

每项一句话，说清三件事：**引导词是什么**、**什么从句**、**修饰谁/作什么成分**。

```
✅ "how 引导宾语从句，用陈述语序（how family life can affect）。"
✅ "that 引导定语从句，修饰前面的 studies，that 在从句里作主语。"
❌ "这是一个从句。"                    （没说是什么从句）
❌ "how 引导从句。"                     （没说修饰谁、什么成分）
```

无从句填 `[]`。

### ⑤ 重点短语 `phrases`

每项 `{text, meaning, usage, example}`：

```json
{
  "text": "a number of",
  "meaning": "许多、若干",
  "usage": "谓语用复数；与 the number of（……的数量，谓语单数）不同。",
  "example": "A number of students were absent. 好些学生缺席。"
}
```

**要求**：
- `example` **必须带中文译文**（自检脚本会告警）
- `usage` 优先写**易混对比**（如 `a number of` vs `the number of`）或固定搭配限制
- 挑**真正值得记**的（动词短语、介词搭配、固定句式），不要挑 `in the` 这种

### ⑥ 易错点 `pitfalls`

一句话一个坑。例：
- `a number of 作主语，谓语用复数。`
- `not until 提前时主句要部分倒装。`
- `此处 that 不能换成 which（前面是不定代词 all）。`

### ⑦ 段落作用 `paragraphRole`

这句在段落里干什么。例如：
- `交代已有研究关注点（家庭生活），为下文「leisure 研究不足」做铺垫。`
- `举例支撑上一句的判断。`
- `转折：从「忙碌被尊重」转到「忙碌未必有效」。`
- `结论句，回应段落开头的提问。`

**不要**写「本句说明了……的意思」（等于没写）。

## 三、词条 `lexicon` 的写作要求

### 选词标准

**进词表的应该是「值得记的」**，不是所有词：
- ✅ 四级高频词、一词多义的词、易混词（`affect` vs `effect`）、固定搭配里的关键词
- ❌ `the` `is` `and`、专有名词（`Naomi Baron`）、纯数字

**规模参考**：仔细阅读 127~143 条 / 选词填空 79~103 条 / 长篇阅读 319~417 条。

### `sense` 写「语境义」优先

```json
"studies": {
  "sense": "研究（复数名词）；学习（动词 study 的第三人称单数）"   // 两种可能都写
}
```

```json
"looked": {
  "sense": "看；look at 此处作「研究、考察」"                      // 点明本文用法
}
```

### `examples` 必须带中文译文

```
✅ "A number of students were absent. 好些学生缺席。"
❌ "A number of students were absent."             （没译文，自检会告警）
```

### `more.roots` / `more.confusables`

- `roots`：词根词缀拆解（`able（能够）+ -ity`）
- `confusables`：易混对比（`ability to do（不是 of doing）/ capability（能力，偏完成复杂任务）`）

这两项可选，但**填了就填准**。

## 四、硬错误（脚本会拦，必须修）

| 错误 | 后果 | 怎么修 |
|---|---|---|
| `sentence.start/end` 切片 ≠ `sentence.text` | 高亮错位（用户点这句高亮到别处） | 重算偏移 |
| `token.start/end` 切片 ≠ `token.surface` | 点词高亮错一个字符 | 重算偏移 |
| `_` 或 `~` 出现奇数次 | 整串退化为纯文本，成分标注全丢 | 补闭合符 |
| `【】`/`{}`/`()` 不配对 | 多余符号露给用户 | 补闭合符 |
| `answer` 为空 / 不在 options 里 | 这道题无法判对错 | 补答案 |
| `answer` 与 `options` 数量不符（careful 应 4 项） | 选项渲染异常 | 补全 4 项 |
| `blankNos` 与 `blanks` 不对应 | 选词填空解析缺失 | 补齐 |
| 空号未在正文里字面出现 | 空格控件渲染不出来 | 正文改为字面数字 |
| `isWord=true` 但 `normalized` 空 | 生词本收藏无法聚合 | 补词形 |
| 文件有 BOM / NUL / BEL | 导入失败或文案出现乱码 | 存为 UTF-8 无 BOM |

## 五、软问题（只告警，但要能解释）

| 问题 | 为什么不好 | 建议 |
|---|---|---|
| 符号句标记奇数次 | 现有内容包有 7 句如此（已知白名单） | 新数据避免 |
| `wordCount` 与 token 数比例偏离 0.85~1.35 | 可能把 token 数当词数填了 | 按英文单词数填 |
| 词表里有正文没出现的词 | 可能是多余条目或拼写不一致 | 核对 `normalized` |
| `examples` 没中文译文 | 用户看不懂例句 | 补译文 |
| `clauses` 整个字段缺失（而非 `[]`） | 渲染成「本段暂无解析」，读者不知道是真没有还是忘了写 | 用 `[]` |

## 六、交付前内容自检（10 问）

1. **每句**都有 `analysis` 九字段吗？
2. **直译和顺译**是不是真的不一样？
3. **符号句**去掉 `_`/`~` 后，与句子原文一字不差吗？
4. **`components`** 的 `note` 是不是在讲「为什么」，而不是重复 `role`？
5. **`clauses`** 每项都说了「引导词 + 什么从句 + 修饰谁」吗？
6. **`phrases[].example`** 都带中文译文吗？
7. **词表**里有没有该进的词被漏掉、或不该进的凑数？
8. **`sense`** 有没有点明本文语境义（而不只是词典第一义）？
9. **题目**答案与原文能对上吗（尤其 long 型的段落字母）？
10. **选词填空**每个空都写了 `reason` + `distractors` 吗？

---

## 七、一句话总结

**格式由脚本兜底，内容由你负责。** 脚本能抓到「偏移错一位」「标记没闭合」，抓不到「从句类型说错了」——后者只能靠你自己核对。

不确定的地方**少写**，不要瞎编。写「此处结构较复杂，主干为 X」比编一个错的从句分析要好。

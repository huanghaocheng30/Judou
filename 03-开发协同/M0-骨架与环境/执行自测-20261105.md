## 八、一次真实故障、根因与修复（可复核）

**现象**：首次 `npm run tauri dev` 启动即崩：

```
thread 'main' panicked at tauri-2.12.5\src\app.rs:1444:11:
Failed to setup app: error encountered during setup hook: [db_error] 本地库执行迁移失败…
error: process didn't exit successfully: `target\debug\judou.exe` (exit code: 101)
```

**根因**（stderr 明细，dev 日志）：`[judou][db] 执行迁移: table schema_meta already exists in -- 001_init.sql …`——`db.rs` 的迁移框架先 `CREATE TABLE IF NOT EXISTS schema_meta`，而 `001_init.sql` 里 `schema_meta` 是 19 张表之一也 `CREATE TABLE`，同一事务内后建必然撞名。

**修复**（最小改动，两处）：
1. `db.rs::migrate` 不再预建表，改为查 `sqlite_master` 判断 `schema_meta` 是否存在，存在才读 `version`；**让 001 成为 schema 的唯一来源**。
2. 删除开发期脏库（02 §五 风险缓解已写明「开发期库可删」），重启后迁移一次成型。

**防回归**：`db.rs` 增 2 条 `cargo test` 用例——`open_creates_19_tables_and_version_1`（首次迁移 19 表 + version=1，**修复前必然报同一错**）与 `reopen_is_idempotent_and_settings_roundtrip`（二次打开不重跑迁移 + 设置往返）。连同 `commands.rs` 3 条校验用例，`cargo test` **5/5 pass**（`/cargo-test.log`）。

**影响面**：仅 `src-tauri/src/db.rs`（+ 单测）；前端与 SQL 未动；修复后 `cargo check` exit 0、`tauri dev` 两次启动零 panic。

## concerns

1. **AC3 只有静态断言，未真跑 manifest 生成**：`make-update-manifest.mjs` 的失败分支（无产物目录 / 无 `.exe` / 无 `.sig`）逻辑正确但未实测产出物——要实测必须有真打包产物 + 签名密钥，属人工级步骤（派工黑名单）。门禁只断言「五字段存在 + 无签名 `exit 1`」。**建议**：人工发版时首跑一次 `node scripts/make-update-manifest.mjs --url-base …` 验证。
2. **AC6「脚本不被 CI 执行」靠约定而非断言**：`verify-release.mjs` 未断言「workflows 里不出现 build-installer」。两个 workflow 肉眼与 `grep` 均无引用，但没有机器断言兜住后续回归。**建议**：下一包给 `verify:release` 加一条 `!/build-installer/.test(workflowText)`。
3. **AC7 的 CDP 三态实录缺失**（重要）：本轮未跑 CDP——需要 `tauri dev` 起真窗口（WebView2），单次构建远超 40 分钟预算。代码侧已按 `data-check-update` + `data-check-update-result`（`available`/`latest`/`failed`）落位，后端 `check_update` 三态由 6 条单测覆盖；但「设置页点一下显示文案」这一层没有任何运行时证据。**这是本包最大证据缺口，请审核员按 AC7 判**（要么接受单测+代码证据，要么打回补 CDP）。
4. **`target="_blank"` 外链在 Tauri webview 里可能被 CSP 拦**：`tauri.conf.json` 的 CSP 是 `default-src 'self'`，且本包未装 `tauri-plugin-opener`。有新版时按钮旁渲染的是 `<a target="_blank">下载页</a>`——点击大概率**不跳转**（不报错，只是无反应）。AC7 只要求「显示版本号 + 链接」，元素形态已满足；但「点了能打开浏览器」需要后续装 opener 插件。**建议**：M7 后续或下个修复包处理，或在按钮旁直接显示 URL 文本。
5. **`latest.json` 加了 `.gitignore`**：清单是每次发版重生成的产物，不入库。若将来想「清单随仓库发布」，需从 `.gitignore` 移除该行——当前门禁不断言它，两种选择都不破坏门禁。
6. **`ci.yml` 里没跑 DB/二进制类门禁**（`verify:import-user` / `verify:ai-import` / `verify:sql`）：它们需要本机 Rust bin 与临时库，在 3 平台 matrix 上跑会显著拉长 CI 且易受环境影响。AC4 要求的「全部 verify:*」按发布相关子集（release / ci / invoke / records）落地，已在 workflow 注释写明取舍。

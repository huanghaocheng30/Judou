## 二、6 条必判

### 2.1 AC7 证据缺口裁定（核心）→ **接受，转人工测试主测项**

**裁定：接受单测 + 静态属性，不打回补 CDP。** 理由三条：

1. **判据类型决定手段上限。** AC7 是展示层 AC（「显示什么文案」），CDP 只能证明「属性值随状态变化」，**证明不了文案是否说人话**——内容正确性的判定权本来就归人工。补 CDP 约需 `tauri dev` 起真窗口（WebView2，单次构建远超派工预算），成本与「它根本证明不了的那部分」不匹配。
2. **后端半边有硬证据。** `update.rs` 6 条单测覆盖 4 条真实路径（`available=true` 三字段齐 / `up-to-date` / `no-manifest` / 坏 JSON→`offline`），且 `cargo test` 110 passed 与「104 既有 + 6 新增」算术自洽。
3. **前端半边有可静态核验的挂点。** `data-check-update`（按钮）、`data-check-update-result={available|latest|failed}`、`data-check-update-link` 三个属性与三态文案一一对应，DOM 结构可读、无隐藏分支。

**代价与对冲**：把「三态实测」写进人工测试主测项第①条（§七），并要求按 3 个操作跑：坏 JSON → 看文案、无 manifest → 看文案、手放新版本 manifest → 看版本号+链接。**注意：这三步中的第一步会当场暴露 §2.2 的缺陷（现在会显示「已是最新版本」）**——这也是我判 AC7 fail 的直接依据。

> **展示层上限声明**：AC7 属展示/措辞类判据，**形状约束（属性存在、三态枚举齐）不构成内容正确性证据**。本节结论仅覆盖「结构齐备 + 后端路径覆盖」，文案与真实交互效果以人工实测为准。

### 2.2 AC7 第三态不可达 → **fail（承重缺陷，驳回项 B1）**

- 后端 `commands::check_update` 返回 `UpdateResult`（**不是 `Result`**）→ 永不 `Err`（`commands.rs:238-242`）。
- 前端 `Settings.tsx runCheckUpdate`：`available===true` → `available`；**其余一律 → `latest`（已是最新版本）**；`failed` 只在 `.catch()` 里（IPC 层异常）。
- 后果：真实失败路径 `reason="offline"`（manifest 读坏 / 权限不足）与 `no-manifest` 都被显示成**「已是最新版本」**——AC7 明写的「失败显示『检查失败，稍后再试』」在常规流程下**永不出现**，而用户会在文件损坏时被误导成「已最新」。
- 后端已经把 `reason` 分好三值（`up-to-date`/`no-manifest`/`offline`），前端一个都没消费 → 这是**契约产出被丢弃**，不是措辞问题。

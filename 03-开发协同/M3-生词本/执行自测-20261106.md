## 六、实现补充声明（每条都可一行回退）

**(a) 收藏时顺带快照 `phonetic` / `pos`** —— 02 D0 字面只列 `normalized`/`surface`/`sense_in_context`。
理由：D3 明确要渲染「音标 + 词性」，而这两列处在 `token_analysis`，收藏后文章被替换就永久丢失；同一条 INSERT、未新增列。
回退：删掉 `INSERT INTO vocab_entry` 的 `phonetic, pos` 两列与对应两个参数（`Snapshot` 少两个字段）。

**(b) 标签轴多一个「未打标签」组（固定排最后）** —— 02 D2 只要求「一词多组 + 空组不显示」。
理由：没有它，未打标签的生词在「按标签」视图里会整批消失（用户会以为词丢了）。
回退：`groupVocab` 的 tag 分支删掉 `row.tagNames.length === 0` 那三行 + `UNTAGGED_*` 常量。

**(c) AC9 门禁口径：写语句扫描排除 `#[cfg(test)] mod tests`** —— 见 §三.4。
理由：测试必须在临时库里造内容（`article`/`paragraph`/`sentence`/`token`/`token_analysis`）才测得了读路径；M2 的 `analysis.rs` 测试同样如此，不排除则同一口径在 M2 就已红。
**不使门禁变摆设**：D 段仍扫全部生产代码，并**打印**测试模块内的写目标表（本轮：`article, paragraph, sentence, token, token_analysis, vocab_entry`）供审核员审计。级联 `SET NULL` 需要 `DELETE FROM article`，因此不在 Rust 里测，改由 `scripts/verify-vocab.mjs` E⑩ 证明。

**(d) 页面断言先剥注释再扫** —— 文档里写「**不得**用 `data-has-note`」不该把门禁搞红。
理由：注释是纪律说明，不是用法。回退：`pageCode` 改回 `src.page`（附注：没有它就无法在源码里写明这条纪律）。

**(e) `VocabFilter` 本包只接收不消费**：`list_vocab` 保留 `groupBy`/`filter` 形参（AC1 契约），但分组筛选真源在纯函数层；结构体三个字段 `#[allow(dead_code)]` + 注释说明，避免「同一规则两处实现必然漂移」。
天花板（已写 `ponytail:` 注释）：单用户生词上万时把 `filter` 下推 SQL，命令签名不变。

**(f) `list_vocab` 排序 `updated_at DESC, id DESC`** —— D0 未规定序。理由：页面需要稳定序，同秒内以 id 兜底，断言可复算。

**(g) 新增 4 个错误码 + 1 个构造器**：`token_not_found` / `vocab_not_found` / `invalid_mastery` / `invalid_vocab_patch` / `CommandError::db_invariant`（「写后回读不到」的不变量破坏，与 `db` 同口径文案）。对 docs C3 的命令集偏离见 §七。

**(h) 测试里标签排序按 UTF-8 码点**：SQLite `ORDER BY` 是 BINARY 排序，「评估」(U+8BC4) 在「雅思」(U+96C5) 前；首轮我按拼音直觉写错期望值，`cargo test` 抓出（2 红 → 改期望 → 绿），已把这条写进测试注释。

## concerns

1. **编辑保存是两步写、非原子**：`update_vocab` 成功而 `set_vocab_tags` 失败时，字段已落库、标签未改，界面报「保存失败（输入已保留）」。重试是幂等的（两步各写一遍），但用户若直接关掉页面，标签那次改动就丢了。要真事务需把两命令合成一个（改 `vocab.rs`，超本批授权）——登记为 low 债务，建议 M4 若做词级批量写时一并收。
2. **失败路径无注入证据**：`VocabEditor` 的 catch 分支、`WordCard` 的收藏失败提示、`Vocab` 的移出失败提示、`getVocabByNormalized` 的 `.catch(() => null)` 降级、高亮定时器的卸载清理，都只由代码结构与审查覆盖，未做失败/时序注入（M2 的 `cdp-fail-inject.mjs` 只针对笔记）。如实标注，不当成已验证。
3. **两处本包不做的 UI 入口**：① `delete_tag` 命令在库、页面**无删标签入口**（02 §二 清单与 D3/D4 均未要求，M6 生词管理再补）；② `?token=` 高亮分支无生产产出路径、无 CDP 断言。两者都不是遗漏，但审查时容易被当成「命令有 UI 无」的不一致，特此写明。
4. **CDP 断言脚本自身修过 3 处 bug**（§三.3）：都发生在 `.tmp` 脚本、产品代码零改动，但说明「35/35」的可信度依赖脚本正确性——脚本已随证据留在 `.tmp/M3-生词本/cdp-m3b2.mjs`，可复跑复核。

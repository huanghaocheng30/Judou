## 二、中-1 新判据的可信度评估（是否恒真 / 期望值来源是否独立）

### 2.1 期望值来源：**独立，不是自证循环**

`verify-render.mjs` 的 ⑧ 段（`scripts/verify-render.mjs:154-200`）：

```js
const paragraphs = db.prepare("SELECT id, article_id, idx, text FROM paragraph ORDER BY article_id, idx").all();
…
for (const paragraph of paragraphs) {
  const parts = renderParagraph(paragraph.text, rows.map((row) => ({ start: row.start_offset, end: row.end_offset, text: row.text })));
  const rendered = parts.map((part) => part.text).join("");
  if (rendered === paragraph.text) paraOk += 1;
```

- **期望值**＝`paragraph.text`，来自**独立 SQL 查询**（`paragraph` 表列），不是 `renderParagraph` 的返回值；
- **被测量**＝`renderParagraph(...)` 的拼接结果。
- 两者来源不同 → **不恒真**（不存在「拿同一个函数算期望值」的自证循环）。✅ 这是本节的关键结论。

### 2.2 但要如实说明它**证明什么、不证明什么**（鉴别力分层）

`renderParagraph` 的 gap 本身就是 `text.slice(prev, sentence.start)`，句段用 `sentence.text`。因此数学上：**只要** `sentence.text === text[start..end]` 且句子区间按 start 递增且不重叠，拼接结果**必然**等于 `text`。也就是说 ⑧ 的鉴别力主要落在「**数据一致性**」（句子偏移与段落原文对齐）上，而不是「gap 算法是否写对」。这不削弱本次修复的证据力，因为：

1. **⑨ 补上了排除绕过的断言**：`if (sentenceParts !== sentences.length) fail(...)` → 274 个句段。若有人把 `renderParagraph` 改成「直接返回整段原文一次」，⑧ 仍会 90/90，但 ⑨ 会红（1 ≠ 274）。**⑧ 与 ⑨ 联合**才构成有效判据。
2. **「gap 必须非空」是推论而非缺口**：`gapNonEmpty = 184` 只统计不断言。但句间空格不属于任何 `sentence.text`（这已由红段 75/90 与第 1 轮审查实证），故若 gap 全为空，拼接必然短于原文 → ⑧ 必红。所以该推论由 ⑧ + ⑨ 覆盖，不需要额外断言。
3. **144 处空隙在真实 DOM 上被独立证明**：`cdp-reader-para.txt` 判据遍历 `spans[i-1].nextSibling` 到 `spans[i]`、累加 `node.textContent` → **纯 CSS `margin`/`::before` 不会产生兄弟节点的 textContent**，gap 会为空。实测 **184/184 非空、空隙集合 `[" "]`**。这是「空隙是真文本节点、不是 CSS 间距」的**直接证据** ✅
4. **数字自洽可复算**：184 = 274（句）− 90（段）——每段句间空隙数 = 段内句数 − 1，全部段求和恒等于 274 − 90。逐篇明细（5/7/5/12/5/3/17/6/8/4/14/4 段，共 90；15/8/4/30/12/7/22/13/13/5/44/11 对，共 184）我逐行相加核对 ✅
5. **遗留弱点（非本轮新增）**：CDP 脚本在 `.tmp/` 不入库（第 1 轮 §六.4-5 已登记），运行期那一层不可从仓库复跑；仓库内可复跑的是 ⑧⑨（我已独立复跑 exit 0）。

### 2.3 「代替修法① 是否等价或更好」 —— **更好**

| 维度 | 修法①（内联 5 行） | 开发员的 `renderParagraph` |

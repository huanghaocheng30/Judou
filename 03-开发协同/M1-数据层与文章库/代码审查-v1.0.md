### 中-1｜精读页丢失句间空格（用户可见的正文渲染缺陷）

- **位置**：`02-代码/src/pages/Reader.tsx:137-145`（`<p className="para">` 内 `.map` 句子）+ `02-代码/src/styles/app.css`（**无 `.sentence` 规则**）
- **问题**：段落正文由「句子 `text` 顺序拼接」重建，但**句间/句末的空格不属于任何句子**（`sentence.text` 是句子切片）。相邻 `<span className="sentence">` 之间没有任何空白字符，CSS 也没有 `.sentence` 的 `margin`/`::before` → 渲染结果把句子粘在一起（`…last word.First word of next…`）。
- **证据（可复算）**：`.tmp/M1-数据层与文章库/review-probe.mjs`（审核员只读探查，本次新增）输出：

  ```
  ── ① 段落 = 句子拼接？──
    相等 15 / 不等 75（共 90 段）
    样例: { article: "cet4-2023-12-set1A", pidx: 0, sentences: 7,
            holes: [" ", " ", " "], lenPara: 430, lenJoined: 424 }
  ```
  `grep -c "sentence" src/styles/app.css` → **0 处匹配**（句间无任何间距来源）。
- **为什么 AC6 没抓到**：AC6 的三条切片断言都是**句内**（`text` = 单个句子），`verify-render.mjs` 的 ⑦「节点拼回原文」也是**句级** `join === sentence.text`。段落级还原不在任何判据里 —— 这是判据盲点（见 §六）。
- **修法（两选一，推荐①）**：① 段落级忠实切片（约 5 行）：渲染时用 `paragraph.text` + `sentence.start/end` 补出句间空隙（数据已在报文里，与 `renderTokens` 同一思路）；② 最小改动：句子 span 之间插 `{" "}`（实测空隙目前全是单空格，但这是内容包事实、不宜当通用假设）；③ CSS 兜底 `.sentence + .sentence::before { content: " " }`（不随数据变化，行首/行尾无副作用）。
- **loadBearing：承重** —— 正文「不漏字、不粘连」是渲染的基本正确性，用户第一眼可见。
- **阻断性：非阻断** —— AC6 判据未要求段落级拼接，数据层与空格判定全对。**但建议调度员决策：进入「待人工测试」前修，或在验收小结的「前置注意事项」里明确披露**，避免用户实测时把它当新问题报成修复包（一轮修复包的成本高于此处 5 行改动）。

### 低-1｜`clearFilters` 不清搜索防抖定时器（250ms 竞态）

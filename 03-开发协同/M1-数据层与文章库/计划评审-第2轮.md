## 四、本轮新发现

### 驳回级

**N1（＝ B8 未闭合）· `startupError` 到前端的通道缺失，且 `setup` 的错误传播会让错误页不可达**

- **位置**：02 L17（AC1 末句）、L38（`lib.rs` 行「startupError 非空时传达到前端」）、L47（`App.tsx` 行）、L103（D2 产 `StartupError`）、L144-149（D4 四命令）。
- **事实**：① D4 命令清单只有 4 个、无任何 startup 查询通道；`api.ts` 封装清单同（§二 L41）→ `App.tsx` **拿不到** `startupError`；AC9 又禁止裸 `invoke(` → 实现者只能自创第 5 个命令，落在清单外（范围漂移边界模糊）。② 更硬：`lib.rs:16` 现为 `Db::open(...)?`、`:15` 为 `app.path().app_data_dir()?`（setup 闭包用 `?`）；一旦内容包/DB 失败向上返回 Err，`lib.rs:29` 的 `.expect("启动句读失败")` **直接 panic**，进程崩溃 → **错误页永远显示不出来**，AC1「不落进空文章库」不可达。修法只写了「产出类型 + 增列文件」，没写「错误必须被捕获而不传播」。
- **最小修法**（三处文字 + 一行清单）：
  1. §二 `commands.rs` 行改为「追加 **5** 个命令：`…` + `get_startup_error() -> Option<StartupErrorInfo>`」，`api.ts` 行同步加 `getStartupError()` 封装；
  2. §二 `lib.rs` 行写死：「setup 内 DB/内容包初始化失败**不得**向上返回 Err（否则 `run().expect` panic、错误页不可达）：捕获后 `app.manage(StartupState::Failed { .. })` 并**正常返回**」；
  3. §三.0 增一行 `StartupErrorInfo` 的 IPC 字段口径（`kind` / `message` / `file`，camelCase）；
  4. AC1 增一句错误页的 DOM 锚点与「`git grep get_startup_error` 存在」的双向断言（现在只有行为描述，无误证载体）。

**N2 · `verify-sql.mjs` 的版本口径与 AC2 自相矛盾，且 002 的 SQL 语法/空库起点无秒级门禁**

- **位置**：AC2 L18（「`verify-sql.mjs` 与 `check-tables.mjs` **双 exit 0**（两者版本断言同步改 `"2"`）」）、§四 L196（同口径）、§二 清单 L31-56（**无** `verify-sql.mjs` 行）。
- **事实**：`02-代码/scripts/verify-sql.mjs:16` 只读 `001_init.sql`（`:43` exec 单文件），`:72` 断言 `version !== "1"` 即 FAIL。002 落库后该脚本**仍是绿的**（它只跑 001）；若按 AC2 字面「同步改 `"2"`」→ **必红**；若保持 `"1"` → AC2 字面不满足，且**002 的 `ALTER TABLE` 语法正确性与「空库(001+002)起点」没有任何秒级门禁**（只能等 `tauri dev` 才暴露）。这正是 R5「两起点」在 (a) 侧的落空。
- **最小修法**：
  1. §二 增列 `02-代码/scripts/verify-sql.mjs`：「改为按 `migrations/` 目录顺序执行 001→002；001 段断言 19 表 + `version=1`（保留现有判据），002 段断言 `version=2` + 三列类型/默认值 + 表数仍 19（不加表）；即 AC2 的 (a) 空库起点」；
  2. AC2 的括号改为「`check-tables` 断言**运行期库** `version=2`；`verify-sql` 断言**空库全链**后 `version=2`（001 段仍断言 1）」；
  3. §四 AC2 行补 (b) 起点造库步骤（用旧代码启动一次得到 M0 库，或 `verify-sql` 的 001-only 模式建库后把 `version` 置 `1` 再启动新版），否则「M0 既有库」这条起点无法稳定复现。

**N3 · AC8「`app.css` 改动 ≤2 行」与 §二「精读页排版样式可新增」互斥**

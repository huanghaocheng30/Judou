## 七、安全约束（AC6）逐条落点

| 约束 | 实现落点 | 验证 |
|---|---|---|
| 只写 `app_data_dir` 下 | `create_dir_all` 后 `canonicalize(app_data_dir)` 与 `canonicalize(target)` 比对，越界返 `PermissionDenied` | `extraction_produces_loadable_pack` 断言目标 == `<app_data>/content-pack` |
| 拒绝含 `..` 的路径 | `extract_dir` 逐文件校验 `Component::Normal`（拒绝对路径 / `..` / 根前缀） | 代码路径，内嵌目录为扁平时不触发；与 `safe_join` 同一口径 |
| 不覆盖已存在文件 | `if dest.is_file() { continue; }` + 幂等分支（manifest 可解析即返回） | `extraction_is_idempotent`（mtime 与文件数不变）+ 真机二次启动实测 |
| 失败返回 `io::Error` 而非 panic | `ensure_pack_extracted -> io::Result<PathBuf>`；`resolve_pack_dir` 用 `map_err` 转 `StartupError::PackMissing`（错误页） | 无 `unwrap`/`expect`/`panic!`（可用 `grep -n 'unwrap\|panic!' src/pack.rs` 复核，仅测试块内有 `expect`） |

## concerns

1. **解压耗时未单独计时**：`301 ms` 是「解压 + 首次导入 12 篇」的合计（日志 `elapsed` 只覆盖 import）。02 风险表要求「解压若超 1 秒记录」。按 `.so` 内嵌、13 次 `write` 估算解压约 20~50 ms，但**未实测分离**——若要精确数字，需在 `ensure_pack_extracted` 里加一次性计时日志（本包未加，避免动生产日志口径）。
2. **解压失败文案未按 02 风险表细化**：02 写「复用 `pack_missing` 页，文案说明『存储空间不足』」，实际实现失败时仍映射到现有 `PackMissing`（文案「内置内容包缺失…请重新安装应用」），真实 `io::Error` 只进 `eprintln`。原因：避免为一种边缘态新增 `StartupError` 变体（会牵动 `info()` 与前端 `kind` 分支）。如审核认为必须细化，改动量约 10 行。
3. **二进制断言依赖 Android 产物**：`.so` 不存在时 `verify-pack.mjs` 跳过该条（否则未做过 Android 构建的机器会误红）。也就是说 CI 上「包真的进了二进制」这条**不是无条件门禁**，需要先 `tauri android build`。
4. **仅 arm64-v8a 验证**：按 02「不做多 ABI」，未验证 armeabi-v7a / x86_64。APK 253.5 MB 是 **debug**（含 debug symbols + 3.5 MB 未压缩内嵌包）；release strip 后未测。
5. **已装 v0.2.1 桌面安装版未重装验证**：AC3 只实测了 `npm run tauri dev`（第一级 `target\debug\content-pack`）。安装版走同一个 `resource_dir()` 分支、前两级代码路径未改，判定为不受影响，但**没有实机安装态日志**。
6. **Windows symlink 步骤仍失败**（开发者模式未开）：每次 Android 构建都要手工 `Copy-Item` + `gradlew`，与 M7 同款环境限制，非本包引入。
7. **真机只验证了 arm64-v8a 一台设备**（RMX5060）：列表页 12 篇 + 首篇精读页正文/20 句已端到端通过（§5.3），但**未在第二台设备/其他 Android 版本复测**；`app_data_dir` 路径按 `com.judou.app` 包名推导，换包名/多用户场景未覆盖。
8. **`ensure_pack_extracted` 的「半损坏包」行为**：只判 `manifest.json` 能否解析就短路返回；若用户手动删了某个篇目 JSON，不会自愈（要清应用数据）。02 未要求内容哈希校验（包随二进制走），记录为已知边界。

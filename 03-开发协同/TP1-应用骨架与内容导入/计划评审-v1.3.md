### 3.2 B9-②：02 列清单 ↔ 04 §六 L126 逐字段对比

04 §六 L126（权威）：`token_analysis | tokenId, phonetic, pos, senseInContext, collocationsJson, examplesJson, isCet4HighFreq | 1—1 token`

| # | 04 §六 字段 | 02 L95 落点 | 映射说明 | 判定 |
|---|---|---|---|---|
| 1 | `tokenId` | **复合主键 `(articleKey, paraIdx, sentIdx, idx)`**（与 `token` 表同键） | 不落普通列，作为 PK 承载身份 | ✅ 可接受（理由见下） |
| 2 | `phonetic` | `phonetic` | 同名 | ✅ |

| 6 | `examplesJson` | `examples(JSON)` | 同上（内容包键 `examples`） | ✅ 可接受 |
| 7 | `isCet4HighFreq` | `isCet4HighFreq(INTEGER 0/1)` | JSON 布尔 → SQLite 无布尔类型，标准落法（读取侧按 `true/false` 或 `1/0` 均可）；实测取值仅 `true`(166)/`false`(47)，**无 null、无第三值** | ✅ |
| 8 | （04 无） | `more(JSON)` | 02 已注明来源＝**内容包 `token.analysis` 实测第 7 键**，非新增需求 | ✅ 来源可追 |
| 9 | （04 无） | 同 token 四列 | 归属外键/主键列，不属于 04 的对象自有字段 | ✅ |

**四元主键替代 `tokenId` 为何可接受**（B9-② 明确要求说明）：

1. **关系语义等价**：04 §六要求 `token_analysis` 与 `token` 为 **1—1**；02 L93 的 `token` 表本身即以 `PK(articleKey, paraIdx, sentIdx, idx)` 为身份，`token_analysis` 沿用同四元键即天然一一对应，不引入代理键与二级映射表（少一张表、少一次 id 回填）。
2. **实测无撞键风险**：内容包 12 篇 6699 个 token 按 `(articleKey, paraIdx, sentIdx, 序号)` 组合为 **6699 个唯一键（dup=0）**，主键约束不会在建表/导入阶段失败（§八 T3，可复算）。
3. **层次差异合法**：04 §六 是**数据对象语义层**（用 `id` 表达对象身份），02 是**物理建表层**；「物理键形态」由 PK 约束等价承载身份语义，且本包无「按 tokenId 跨表查询」需求（TP2/TP3 才有，届时可用四元键查询或加索引）。
4. **不做代理键的额外收益**：导入时无需为 6699 行生成并维护自增 id 映射，降低单事务导入的复杂度（配合 AC2 `elapsedMs<2000`）。

> 结论：B9-② 的「七字段」在 02 全部有落点，无遗漏、无曲解、无非登记新增列。

# 复算命令（只读；PowerShell）。$dir 为内容包目录
$dir='E:\Judou\01-设计\CET4-阅读精读\内容包'

  if($j.blankNos){$bTot+=$j.blankNos.Count}

}

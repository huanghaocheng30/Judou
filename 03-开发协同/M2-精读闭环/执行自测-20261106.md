## 五、CDP 抓出的真实缺陷与修复（本批最有价值的发现）

**症状**：AC8「换句先 flush」第一轮断言失败：
```
FAIL | AC8 换句先 flush（未满 800ms 的输入不丢） | {"value":"笔记-翻译-测试","target":"sentence:4"}
```
期望 `flush-未满防抖`，实际读到**上一轮测试留下的旧值**。

**根因**：`useDebouncedSave` 换目标时用「旧 key + 旧草稿」调 `save`，而 `save` 是 `NoteEditor` 里捕获了 `targetId` 的闭包——
渲染新目标后 `saveRef.current` 已指向新 id，于是**旧草稿被写进了新句子**。库内物证（修复前）：
```
残留行: {"id":2,"sentence_id":5,"translation":"flush-未满防抖","grammar_note":"笔记-语法-测试","phrase_note":"笔记-短语-测试"}
```
—— `flush-未满防抖` 本该写句 4，却落在**句 5**（当时刚点过去的新目标）。

**修复**：`save` 签名改为 `(values, targetKey)`，NoteEditor 从 key 里解析 id（不再捕获 `targetId`）：
```ts
const save = useCallback((values: string[], key: string) => {
  const [kind, rawId] = key.split(":");
  const id = Number(rawId);
  if (!Number.isFinite(id)) return Promise.reject(new Error(`无效的笔记目标：${key}`));
  return kind === "sentence" ? upsertSentenceNote(id, …) : upsertWordNote(id, …);
}, []);
```
修复后断言通过：`{"value":"flush-未满防抖","target":"sentence:4"}`。
**测试残留已清理**（`sentence_note` 0 行 / `word_note` 0 行 / `vocab_entry` 0 行，清理命令见 §十）。

> 这条只有「真实 DOM + 跨目标切换」才抓得到——纯函数与 Rust 单测都覆盖不到 React 闭包与 targetKey 的错配。

## 九、concerns（第 2 批，3 条，均不阻塞）

**C-2-1 · AC7 的「构造 ≥300ms 延迟」在页面侧不可注入**
`window.__TAURI_INTERNALS__.invoke` 是**不可写、不可配置**属性（CDP 实测 `{"ok":false,"writable":false,"configurable":false}`），无法用 JS 包装给 IPC 加人为延迟；CDP 也无法拦截 IPC（走 WebView2 宿主通道，不是网络请求）。

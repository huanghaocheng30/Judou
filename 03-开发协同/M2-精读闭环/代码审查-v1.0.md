## 四、第 3 块 · 代码审查发现

> 每条含：文件:行 / 问题 / 严重度 / `loadBearing`（承重＝影响 02 的显式 AC 或红线；非承重＝可读性/风格/防御性）。

### R-1（**medium · 承重**）换目标 flush 失败会**静默丢旧草稿**

`02-代码/src/hooks/useDebouncedSave.ts:155-164` + `:94-116`

```ts
// useLayoutEffect：换目标
const previousDirty = dirtyRef.current;
keyRef.current = targetKey;
dirtyRef.current = false;                                   // ← ① 提前置 false
if (previousDirty && previousKey) saveNow(previousKey, previousDraft);
// saveNow 的 catch：
} catch {
  setStatus("error");                                        // ← ② 只改状态，不恢复 dirtyRef / draftRef
}
```

- ① 在 flush **之前**就清了 dirty；② 失败时既不复原 `dirtyRef`，也不保存 `previousDraft`，而父组件 `NoteEditor` 的 `useEffect`（`:67-91`）紧接着 `reset(...)` 覆盖 `draftRef`。
- 结果：**旧目标的最后一段输入永久丢失，且无任何提示**——`status="error"` 会显示在**新目标**的面板上（用户以为新笔记写失败了）。
- 与 AC8「保存失败 → 保留草稿 + 显示可重试提示 + 下次输入重试，**不静默丢**」直接冲突；02 风险表把它列为「用户数据丢失，最坏体验」。
- 这是**边界场景**（正常路径 flush 成功，CDP 已验）；但正是失败路径该被保障的地方。
- **修法方向**（实现由开发员决定，审核员不建议具体代码）：flush 失败时保留该 key 的待保存草稿（如 `pendingRef: Map<key, draft>`）并在下次切换/重试时重发；`status` 需与 key 绑定，失败提示不得落到新目标上。

### R-2（**low · 承重**）AC8 失败路径零证据（驳回项本体）

见 §二 AC8-f 与 §九 驳回项 B-1。代码实现存在但**从未被触发过**：CDP 脚本只断言了 `statusWhileTyping ∈ ["saving","saved","idle"]`（且实测值就是 `"idle"`，该断言几乎无鉴别力）、`saved`、`已清空`、换句 flush、两档一致——**没有任何一次让 save 抛错**。

### R-4（**low · 非承重**）`toSentenceCard(null)` 浅拷贝共享常量内部引用

`02-代码/src/lib/analysis.ts:256-272,280`：`{ ...EMPTY_SENTENCE_CARD, structure: {…} }` 只重建了 `structure`；`clauses`/`phrases`/`pitfalls` 三个数组与 `emptyFlags` 对象**仍与模块级常量同一引用**。当前所有消费者只读（核对 `SentenceCard.tsx` 无 mutate）→ 无实际缺陷，但一旦有组件 `sort()`/`push()` 会污染全局常量。

### R-5（**low · 承重**）嵌套 `role="button"` 的 a11y 反模式

`02-代码/src/pages/Reader.tsx:48-61`（句 `span role="button"`）内含 `:65-88`（词 `span role="button"`）。父级 `role="button"` 的子内容在无障碍树里被视为**表示性**，屏幕阅读器可能不再把每个词当作独立按钮（`aria-label="查看本句解析"` 会遮蔽整句内容）。键盘可达（Tab/Enter/Space）与 `:focus-visible` 已验 ✓，但「读屏用户能否逐词定位」未验且形态上不成立。02 AC10 只要求 Tab/焦点/颜色非唯一通道 → **不构成对 02 的违反**，属形态改进项（可用句容器不加 role、仅保留 click 命中区）。

### R-6（**low · 非承重**）`normalize_note` 落库存 TRIM 后的值，会吃掉用户缩进

`02-代码/src-tauri/src/analysis.rs:173-180`：`normalize_note` 既用于判空，也用于**生成落库值**（`:435-437` / `:485-487`）。多行笔记的前导缩进与尾部空行会被裁掉。02 D1 只要求「TRIM 后全空 → 删除」，未授权改写内容。建议：判空用 `trim()`，落库用原值（或仅去尾部换行）。

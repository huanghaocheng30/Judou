## 五、§十 4 条口径偏差逐条裁定

### 偏差 1：`phrases` 收两形态（`Vec<Value>` + 字符串→对象投影）

**事实核实**：02 §三.2.1 写 `string[]`；App 展示契约 `AnalysisPhrase{text,meaning,usage,example}`（`types.ts:152-158`，四项均 `string|null`）；内容包三包 `phrases[0]` 实测均为 `{text,meaning,usage,example}` 对象（`set1A`/`set1Long`/`set1Cloze` 逐一实测）；后端回读 `analysis.rs:39-47` 的 `PhraseItem` **`text` 必填、其余可选**，且 `json_list` 解析失败整列降级为空数组。

**判定**：
1. **不违反「`parse_payload` 只认 §三 契约字段、不做模糊猜测」**——没有猜字段别名、没有把别的字段当 `phrases`；这是对「契约形状（string[]）/ 内容包形状（对象）/ 展示形状（对象）」三处既有真实形状的对齐。
2. **投影是必要的，不是可选优化**：若只认字符串且不投影，写入 `phrases_json` 的字符串项会让 `analysis.rs` 的 `PhraseItem` 反序列化失败 → **整列降级为空数组**，M1/M2 已验收的六段式「④ 重点短语」段会整体消失。这一点开发员未写明，但它比「六段式不出现空字段」是更强的必要性理由。
3. **投影引入的行为分支**：`Vec<Value>` 宽进 → 任意 JSON（`123` / `{"foo":1}`）都会原样入库，回读时静默降级。影响仅限该段展示，不触碰结构、覆盖率与写库面。
4. **承重判定：非承重**（行为正确、正例含对象形态 phrases 且六段式 CDP 证过、单测 `phrases_string_is_projected_to_display_object` 在位）。
5. **处置要求（改 02，不改实现）**：02 §三.2.1 的 `phrases` 行登记为「两形态：`string[]` 或展示对象数组；字符串项零推断投影为 `{text,meaning:null,usage:null,example:null}`」并注明「不改 04/05 设计语义（展示契约 `AnalysisPhrase` 早已存在）」。**不建议**改成「只认字符串」：那会要求 `build-fixtures.mjs` 增加一条**丢弃 meaning/usage/example** 的派生变换，与 §六.1「派生只做字段规范化、不做语义加工」冲突，且让契约产物的短语段永久无释义。

### 偏差 2：long 正例 46 句（源包 47）

**判定**：
1. `MERGED_SENTENCES` **声明式合并可接受**：合并只做字符串拼接（`${first} ${second}`）并复用前一句解析，零语义推断；命中失败即 `throw`（防源包漂移静默通过）。
2. **区分力成立**：若冻结切句器行为改变（`etc.` 不再阻断 → 47 句），合并出的 `quote` 将无法与 App 侧句子逐字符匹配 → 正例 `unmatched>0` + 覆盖率 46/46 vs 实测 47/47 → `MISMATCH` → EXIT≠0。有「改对了会失败」的反证面。
3. **计数不一致（02 §六.3 表 47 / §六.5 表 47/47 vs 实测 46）判「非承重（已如实记录、判据可复算）」**：判据真源是 `long.expect.json`（`sentences:46 / sourceSentences:47 / mergedSentences:1` + `note`），门禁逐格按 expect 比对，任何一格不等即失败 → 判据本身可复算；02 表内 47 是**文档数字错误**，已在执行自测 §十.2 如实上报，未掩盖。
4. **处置要求**：02 §六.3 表、§六.5 表、§三.7 第 2 条三处数字按实测改 **46**，并加一句「源包 47 句，冻结切句器 B-2（`etc.` 在缩写表内）合 1 句 → App 侧 46 句；判据真源见 `long.expect.json`」。

### 偏差 3：⑤ 题型一致性落在 `validate_payload` 而非 `parse_payload`

## 六、代码审查发现（承重项 = 修复边界内必改）

### R1（承重）`write_analysis_rows` 把「批内数组下标」写进 `question.idx`，与既有 19 表约定冲突

**证据**：
- `ai_import.rs:1284` 绑定 `question.idx`（= payload `questions[]` 的**数组下标** 0..N）。
- 既有约定：`import.rs:505` 写 `question.no`（试卷题号）；`types.ts:96` 注释明写「`idx` = 内容包 `questions[].no`（与 `blank_no` 同源）`」；`Reader.tsx:506` 用 `data-question-no={question.idx}` 输出该值。
- **实测**：careful 正例（payload `no` = 46~50）入库后 `question.idx = [0,1,2,3,4]`；cloze 重号复现里 `question.idx = [0..10]` 而 `blank_no = 26..35`。
**影响**：同一库内「内容包导入篇」题号 46~50 与「AI 导入篇」题号 0~4 语义分叉；`blank` 与 `question` 不再同源（A2 裁决落点被破坏）；`data-question-no` 判据锚点对 M5b 篇失真；未来按题号的功能（判分/复习/导出）会错。
**为什么 AC 没抓到**：AC8 只验句/词切片，AC12 只验「写了哪几张表」，AC3 只验「显示答案」——均不判字段语义。
**修复边界**：`ai_import.rs` 的 question 写入改用 `question.no`（`AiQuestionOut.no` 已存在）；前端 `mergeMatched` 的 issues 合并键从 `item.idx` 改为 `item.no`（原因：patch 模式累加按题号对齐才与库一致）；`AiQuestionOut.idx` 若保留须注释「批内槽位，**不是**题号」。新增断言（门禁）：cloze 篇 `question.idx` 集合 == `blank_no` 集合 == payload `no` 集合；careful 篇 `question.idx` == payload `no`（46~50）。

### R2（承重）AC7④「重号」判据未落地

**证据（独立复现，§2.1-6）**：cloze payload 追加一条重复 `no=26`（11 题，去重集合仍 `{26..35}`）→ `--commit` 返回 **`ok:true`，`questionsWritten=11`，`question.idx=[0..10]`**。而 02 AC7④ 明写「多号/少号/**重号**均算」，实现自己的错误文案也声称「重号都会被拒收」。

**修复边界**：在 `match_payload` 的 cloze 分支（④ 归属）先用 `Vec` 计重号，任一 `no` 出现 >1 次即拒收（`AI_TYPE_MISMATCH`，`path="blankAnalyses"`——保持 §五 既有 path 枚举，不新增 path 值）；新增 1 个反例 fixture（`bad-type-cloze-duplicate-no.payload.json`，11 题含重复 26）与门禁 1 行断言。**02 §六.4 计数需同步 17→18 文件**。

### R3（承重）cloze 缺 `questions` 被拒收，与 02 §三.1 明文冲突

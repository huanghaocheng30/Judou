## 二、内容生产工作流（续做必读）

所有脚本在 `.tmp/`（可再生，不入库）；内容资产在 `01-设计/CET4-阅读精读/内容包/`。

**1. 生成/更新结构 JSON（已做，一般不用重跑）**
```
node .tmp/build-structure.mjs "<txt路径>" "E:\Judou\.tmp\art-<文章标识>.json"
```
三种题型自动识别：careful（仔细阅读）/ long（长篇·信息匹配）/ cloze（选词填空）。

**2. 写解析分片**（人工/模型产出，是唯一需要"写"的步骤）
命名必须匹配：`_analysis-<文章ID>-<任意后缀>.json`，放在 `01-设计/CET4-阅读精读/内容包/`。
文件形如：
```json
{
  "sentences": { "<段内键>": { translationLiteral, translationNatural, structMarkup, structureSummary,
                                components[], clauses[], phrases[], pitfalls[], paragraphRole } },
  "blanks": { "26": { answerKey, answerWord, reason, distractors } },
  "tokens": { "<normalized>": { phonetic, pos, senseInContext, collocations[], examples[],
                                isCet4HighFreq, more{roots,synonyms,confusables} } }
}
```
**句子键规则**：第 0 段用 `"0"`、`"1"`…；其余段用 `"<段idx>-<句idx>"`（如 `"1-0"`）。
可用 `.tmp/art-*.json` 查每篇的句子列表与键。

**3. 合并 → 内容包**
```
node .tmp/merge-pack.mjs
```
输出 `cet4-2023-12-<id>.json`，并打印每篇覆盖率与待补句子清单。新增文章要先进 `merge-pack.mjs` 的 `ARTICLES` 数组（已注册 12 篇）。

**4. 生成可交互预览**
```
node .tmp/build-preview.mjs "<内容包路径>" "<输出html路径>"
```
宽屏（≥900px）自动右侧栏，窄屏底部抽屉。

## 三、已固化的内容标准（不可偏离）

1. **六段式**：①中文翻译（直译 + 顺译）②主干/成分划分（structMarkup + structureSummary + components）③从句和语法点 ④重点短语/固定搭配（意思/用法/例句）⑤易错点/难点提醒 ⑥本句在段落中的作用。
2. **成分标注符号**：主语【】／谓语 `_ _`／宾语表语 `~ ~`／从句 `{ }`／介词短语·不定式·分词 `( )`。
3. **选词填空空格**：`blanks` 给「正确答案 + 为什么是它 + 易错与排除」。
4. **词级解析**：`senseInContext` 必须是**本句语境义**，不是词典义；`more` 三档按重要性填（功能词可省）。
5. **全部词可点**：未写解析的词由前端降级提示「暂无预置解析」，不报错、仍可收藏。

## 六、调研结论速览

- **Readlang**：至今不做整句翻译 → 句级解析是真差异；双浮层踩坑；生词带原句片段。
- **扇贝阅读**：无「点句出解析」；长按绕冲突；**短语白名单漏标**投诉 → 任意 token 可点 + 降级提示。
- **LingQ**：词本位、句子入口难找；颜色单通道教训；抽屉 ≤55% + 滚动锚定。
- **星火英语**：解析是判分下游的逐题定位式 → 无直接竞争；包体 114—124MB → 严控体积。

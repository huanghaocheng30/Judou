# 决策记录 · M4-复习

## 一、任务包生成阶段的裁定（调度员，2026-11-06）

| # | 问题 | 裁定 | 依据 |
|---|---|---|---|
| 1 | **D-M0-1**：`reading_record` 列名与 `docs/C2 §4.14` 不一致（`last_position` vs `progress` 等） | **以我方 `001_init.sql` 为准，不改 schema**；M4 只用 `completed` 与 `last_read_at`；若 M6 确需 docs 口径，**在 M6 内做 003 迁移 + 映射表**，不在 M4 预支 | 001 是已验收的冻结基线（M0 AC1「19 表 + version=2」）；M4 用不到差异列；M6 才有统计需求。改 schema 在 M4 会产生「为未开工的包预支迁移」的坏先例 |
| 2 | 「首次完成」事件谁产生（M2 未实现，`reading_record` 现网零写入） | **M4 自建**：精读页底部「完成本篇」按钮 → `mark_article_completed`（幂等） | 若 M4 不自建则无数据、包不可独立交付；04 §6.6 明确「首次标记完成时建 `review_plan`」，这个动作必须有入口 |
| 3 | 写不写 `reading_record.completed` | **写**（`ON CONFLICT DO UPDATE SET completed=1`），且**只写这一列 + `last_read_at`** | `completed` 是「完成过」的唯一真相，M6 复用；若只用 `review_plan` 存在性当真相，M6 会出现两处真相。`last_position`/`duration_sec` 归 M6，M4 不碰 |
| 4 | `interval_index` 语义 | 「**已完成次数**」：0 新建；+1 每次完成；间隔取 `[1,3,7,14][index]`；`index=3` 完成 → `status='done'` | 04 §6.6 逐字 |
| 5 | `result='need_more'` 的行为 | **`interval_index` 不前进**、`next_review_at=明天`、`review_log` 记 `need_more` | 表里已有该枚举（001:202），若它不产生行为则该枚举无意义；「没记住就明天再看」是最小合理语义 |
| 6 | 复习模式如何「复用精读页」 | `#/article/<id>?mode=review` → 加 `data-review-mode="1"`，CSS **只隐藏**角标与笔记圆点（不删 DOM）；底部换「完成复习 / 还需再看」 | 04 §八「复习模式（复用精读页，隐藏已读标记）」；不删 DOM 便于 CDP 断言；与 M3 的 `?sentence=`/`?token=` 可共存 |
| 7 | 到期判定用哪天 | **本地日期 `YYYY-MM-DD` 字符串**，today **由前端传**（不用 SQL 的 UTC `date('now')`） | `next_review_at` 是 TEXT；「今天到期」是用户本地概念；前端传 today 便于测试固定日期、避免跨时区错判 |
| 8 | 侧边栏角标数据来源 | 复用 `get_due_reviews(today).length`（**不新增命令**）；启动 + 路由变化时刷新，**不做轮询** | 少一次 IPC；04 §六 只要「带角标」 |

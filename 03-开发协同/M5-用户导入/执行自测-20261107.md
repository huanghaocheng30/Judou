### 零、断点修复（本批第一优先级）

#### 0.1 `split_sentences()` 恒返回 `[]` —— 根因是**结果从未被收集**

修前（`cargo run --bin import_user_cli -- debug`，原样贴）：

```json
{"cleaned":"Reading is a habit that builds over time. Many people read slowly at first.\n\nPractice …",
 "detail":[{"para":"Reading is a habit …","sents":[],"units":75},
           {"para":"Practice makes …","sents":[],"units":94}],
 "direct":[],
 "paragraphs":["Reading is a habit that builds over time. Many people read slowly at first.",
               "Practice makes the habit stronger every single day. Keep a notebook beside you while you read."]}
```

连 `split_sentences("It is fine. Really.")` 都是 `"direct":[]`。

**根因（不是判句逻辑坏，是收集层丢了）**：函数里 `let mut out: Vec<(usize, usize)> = Vec::new();`
声明后，本该 push 的位置是一行 `let _ = (start, end);` —— 算出来的 `(start, end)` 被丢弃，
函数扫完全段后返回空 Vec。编译器当时已经用 `unused_mut` 警告喊过一次：

```
warning: variable does not need to be mutable
   --> src\import_user.rs:237:9
    |
237 |     let mut out: Vec<(usize, usize)> = Vec::new();
    |         ----^^^ help: remove this `mut`
```

（`mut` 没用上，正是因为从未 push。）

**修后**（同一条命令，原样贴）：

```json
{"cleaned":"…","detail":[{"para":"Reading is a habit …","sents":[[0,41],[42,75]],"units":75},
                          {"para":"Practice makes …","sents":[[0,51],[52,94]],"units":94}],
 "direct":[[0,11],[12,19]], …}
```

`direct` = `["It is fine."(0..11), "Really."(12..19)]` —— 两句都在，句间空格不归属任何句子。

顺带修掉切句器里三处会在长文上出错的判定（都在同一函数内）：

| # | 问题 | 修法 |
|---|---|---|
| 1 | 多点缩写 `e.g.` / `U.S.` / `a.m.` 只按「第一个点前的半截」判（候选是 `e.` / `U.`，表里没有 → 误断） | `abbreviation_end()`：从词首吃掉「ASCII 字母 + 点」得到**整串**候选，命中表才不断，并直接跳到整串末尾 |
| 2 | 小数判定用「点前一字符是字母数字」，会让 `fine. Really` 的 `e.` 也判成小数 → 整段黏成一句 | 改为「点**前后都是数字**」才不断（`3.14` / `v1.1` 不断，`fine.` 照断） |
| 3 | 段末无句末标点的残句（标题行、未写完的段）永远不产句 | 循环后补一次收尾 `trim_span(seg_start..len)` |

### 三、UTF-16 偏移专项证据（AC5 / N-2）

`import_user_cli` 的 `utf16` 段逐 token 打印 `[start,end)` 与**按该区间从 UTF-16 单位数组切回**的字符串：

```

    sentenceSlicesEqual=true tokenSlicesEqual=true coverageEqual=true
```

## concerns

1. **`split_sentences` 的「收集层丢失」是上一轮遗留的静默失败**：函数体完整、判句规则看着也在，
   唯独不产出结果，而编译器 `unused_mut` 警告是唯一线索。本批已用 6 条单测把它钉住
   （`split_sentences_returns_sentences` 等），但**同类风险仍在**：本项目没有
   `#![deny(unused_mut)]` 之类的门禁，其他「算了但没用上」的分支不会被拦。建议后续在
   `lib.rs` 顶层加 `#![warn(unused_mut, unused_variables)]` 之外的 CI 检查（属新改动，本批未做）。
2. **门禁自身曾是「不可信真源」**：首次运行有 5 条失败其实是**断言写死的数字错**（`sentenceCount:2`
   而 SAMPLE 明明 4 句、偏移 `15` 而实际 14 个单位）以及**用例没做库隔离**（剔除段用例污染主库）。
   这些已全部改正为「实测值」或「独立库」，但提醒：门禁数字必须能由样本复算，
   写死绝对值的地方（34 token / 30 词 / 68 总数）已逐个手工复算过（9+7+9+9=34 tokens、8+6+8+8=30 词）。
3. **中文标点不断句（已知精度取舍）**：`。` `？` `！` 不在切句终止符集合里，

## 一、例外类 · 正当扩围（开发阶段 D1，2026-11-13）

**决定**：在 02 §三 D0~D6 字面清单之外，**必须**连带修改 6 个文件（`records.rs` / `Onboarding.tsx` / `types.ts` / `Library.tsx` / `Reader.tsx` / `verify-records.mjs`）。

**依据（可复核）**：
1. **AC5 点名的是 SQL 而非文件**：「`visibility='user'` 代码分支全部移除（`WHERE visibility='user'` / `!= 'user'` / 相关常量与三元判断）」——`records.rs:138` 的 `SELECT COUNT(*) FROM article WHERE visibility = 'user'` 正是被点名形态。
2. **删除即断链**：`user_article_count` 是入门任务 ③ 的唯一判据；导入功能删除后该任务**在 UI 上永远无法完成**（`Onboarding.tsx:78`），必须随之下线。
3. **依赖倒悬**：「补全解析」入口指向 `#/import`（`Library.tsx` / `Reader.tsx`），「编辑」入口依赖 `ArticleEditor.tsx` 与 `update_article_meta` / `get_article_questions` / `replace_article_questions` 三条已删命令——入口不摘则构建即红（tsc 找不到模块）。
4. **AC5 与门禁互斥**：`verify-records.mjs:163-170` 原断言「必须存在 user 计数」，与 AC5 直接矛盾。处置为**反向断言**（`assert(!/user_article_count/.test(records))`），属收紧、非放宽，判定权归审核员。

**影响面**：仅删除与反向断言，无新增功能、无新命令、无迁移、无新增依赖。
**未动（红线）**：`import.rs`、`pack.rs`、`import_content_pack` 及注册、`verify-pack.mjs`、`verify-sql.mjs`、`content-pack/`、`migrations/001~003`、`article.visibility` 字段定义。

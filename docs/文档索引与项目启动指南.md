## 7. 下一步：从文档到代码

**你现在要做的第一件事：按 [F1](F1-里程碑与任务拆解.md) 的 M0 开工。**

M0 的施工步骤在 [D2](D2-开发环境与项目结构.md) 第 5 节，验收标准在 F1 第
3.4 节。M0 的完成标志是：

- 桌面窗口能启动
- `ping` command 链路通
- SQLite 建库成功
- GitHub Actions 三平台绿灯

**给 AI 编码代理的第一条提示词**（按 D1 第 12 节模板）：

> 先读 `AGENTS.md` 和 `docs/D2-开发环境与项目结构.md`。本次任务：初始化
> React + Vite + TypeScript 项目，接入 Tauri v2，配置 rusqlite 单连接 +
> Mutex，实现 `ping` command，写 `001_init.sql` 并执行
> migration。约束：不用 ORM，不用连接池，不用 Taro/uni-app，返回
> `Result<T, CommandError>`。参考 D2 第 4 节的配置文件。

## 8. 文档维护约定

1.  **新增决策**：追加到 F3，编号不复用，状态 `已采纳`。
2.  **推翻决策**：旧 ADR 状态改
    `已替代`，新增替代记录，同步更新受影响的文档。
3.  **功能变更**：先改 A1/A2，再改 C 系列，最后改 F1 任务。
4.  **接口变更**：先改 C3，再改 `api.ts` 和 Rust command。
5.  **风险变化**：更新 F2 状态，等级变化在 F3 留痕。
6.  **文档之间不重复**：每份文档只写自己职责内的内容，引用其他文档时给编号和章节。

## 9. 文档体系设计原则

这套文档不是给甲方交付的，是给**三个月后的自己和 AI
编码代理**看的。所以：

- **重决策和约束，轻形式**：每份文档回答"为什么这么做"和"不能怎么做"，而不是堆砌模板。
- **可执行**：每个验收标准可勾选，每个任务有交付物，每个错误有错误码。
- **不重复**：C4 的测试用例只在 C4 写，D3 引用；A2 的交互规则只在 A2
  写，D1 引用。
- **可演进**：决策记录只追加不修改，文档随里程碑更新，风险清单持续监控。

**文档的目标不是完整，是让项目在半年后还能被自己接手。**

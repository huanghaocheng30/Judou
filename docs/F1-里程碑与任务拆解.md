> 版本：v1.0\
> 状态：定稿\

> 本文档把 MVP

## 1. 文档说明

### 1.1 目的

回答三个问题：

1.  **先做什么、后做什么**：里程碑顺序与依赖关系。
2.  **每步交付什么**：可验证的产物，而不是"写完了某模块"。
3.  **怎么判断做完了**：验收标准与对应文档章节。

### 1.2 范围

覆盖 MVP 从零到首次发布的全过程。不覆盖二期功能（见 A1 第 7.3 节）。

### 1.3 编排原则

1.  **按可验证增量排，不按人天排。**
    单人项目的时间估算失真严重，本文档只规定顺序和验收，不承诺日历天数。
2.  **每个里程碑结束时，应用必须能跑、能演示。**
    不允许"数据层全写完但页面没东西看"。
3.  **不跳步。** 后一个里程碑依赖前一个的产物；跳步会导致返工。
4.  **P1 功能可延后，但入口要留。** 延后项在本文档第 7
    节集中列出，不阻塞发布。
5.  **每个里程碑完成前，对应测试必须绿。** 测试用例来源见 D1 第 9 节和
    C4 第 12 节。

### 1.4 节奏假设

- **单人开发 + AI 辅助编码**，有效工作时间约每天 3---5 小时。
- 总周期参考 **4---6 周**（A1 第 6 节的口径），按里程碑划分，不按天排。
- 每个里程碑之间留 **0.5---1
  天缓冲**，用于修上一阶段的遗留问题和跨平台验证。

## 2. 里程碑总览

  里程碑   名称               核心产出                             依赖      预估占比
  -------- ------------------ ------------------------------------ --------- ----------
  **M0**   项目骨架与环境     可运行的空壳应用 + CI 空跑           无        5%
  **M1**   数据层与文章展示   文章库 + 精读页只读展示              M0        15%
  **M2**   精读闭环           点句点词写笔记、自动保存             M1        20%
  **M3**   生词本             收藏、编辑、标签                     M2        12%
  **M4**   复习               篇级计划、今日待复习、复习模式       M2        10%
  **M5**   导入               粘贴/TXT/MD、预览、入库              M1        15%
  **M6**   导出与记录         生词导出、阅读记录、设置             M3、M4    10%
  **M7**   发布链路           自动更新、GitHub Release、首次发布   M1---M6   13%

**关键依赖**： - M2 依赖 M1 的数据结构和精读页骨架。 - M5 依赖 M1 的
article/paragraph/sentence/token 写入能力。 - M7 依赖 M1
的构建可跑通，不依赖 M2---M6 全部完成------可以先发一个只读版验证链路。

  配置 rusqlite +              C2 第 5.1 节、D1 第 5.1 启动建库、开外键

  验证链路

  ---------------------------------------------------------------------------------------------------

### 3.3 交付物

- 应用能启动，显示一个空首页。
- 点击按钮调用 `ping`，返回成功。
- SQLite 文件在 `app_data_dir` 下生成，所有表存在。
- GitHub Actions 在 push 时跑通测试。

### 3.4 验收标准

- [ ] `npm run tauri dev` 能启动桌面窗口。
- [ ] `ping` command 前端调用成功，返回结构化结果。
- [ ] 数据库文件生成，`schema_meta.version = 1`。
- [ ] `cargo test` 和 `npm test` 本地通过。
- [ ] GitHub Actions 首次运行绿灯。

### 3.5 可简化项

- 前端 UI 可以是空白页 + 一个按钮，不需要样式。
- 不需要真实的业务 command，`ping` 足够验证链路。
- 不需要 Android 构建，M7 再处理。

### 3.6 风险

- Tauri v2 首次配置 Rust 工具链和系统依赖可能耗时，预留缓冲。
- Linux 需要 `libwebkit2gtk-4.1-dev` 等依赖，提前装好。

### 9.5 可简化项

## 10. M7 发布链路与首次发布

### 10.1 目标

打通自动更新、GitHub Release 分发，完成首次可发布版本。

### 10.2 任务清单

  --------------------------------------------------------------------------------------

  --------------------------- ----------------------- ----------------------------------
  生成 updater 密钥对         C5 第 2.2 节            公钥进配置，私钥进 Secrets

  配置 `capabilities`         C5 第 2.4 节            `updater:default`

  配置 `publish.yml`          C5 第 2.5 节            三平台矩阵、`includeUpdaterJson`

  发布 v1.0.0                 C5 第 4 节              本地安装

  README、LICENSE、免责声明                           

  Android 构建与更新引导      C5 第 3 节              可延后到首次发布之后
  --------------------------------------------------------------------------------------

### 10.3 交付物

- GitHub Release 有 Windows/macOS/Linux 安装包和 `latest.json`。
- 已安装的 v1.0.0 能自动更新到 v1.0.1。
- 仓库有 README、LICENSE、免责声明。
- 设置页可手动检查更新。

### 10.4 验收标准

- [ ] C5 第 4.3 节首次验证全部通过。
- [ ] `latest.json` 的 `signature` 和 `url` 正确。
- [ ] 自动更新后版本号变化，数据不丢。
- [ ] README 说明安装、使用、构建、许可。
- [ ] 私钥已离线备份。

### 10.5 可简化项

- macOS 代码签名和公证可跳过，用户手动放行。
- Android 构建和更新引导可延后到 v1.1。
- 自定义域名不需要。

### 10.6 风险

- **首次验证失败是最常见的卡点**：公钥/私钥不匹配、`createUpdaterArtifacts`
  未开、`latest.json` 未上传、endpoint 写错。按 C5 第 7 节逐项排查。
- **不要删除 Release 或手改 `latest.json` 回滚**，发更高版本修复。

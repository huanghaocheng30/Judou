> 版本：v1.0  
> 状态：定稿

## 1. 一句话定义

**面向英语四级备考学生，提供以真实阅读文章为学习单元的本地精读工作台：用户读原文、点句点词写笔记、收藏生词短语语法、按篇提醒复习，移动端与桌面端可用，数据完全存在本地。**

---

## 2. 产品定位

### 2.1 它是什么

- 一个**精读工作台**：平台提供文章结构和精读容器，笔记由用户自己生产。
- 一个**复习提醒工具**：以“整篇阅读”为单位提醒用户回看，而不是只刷单词卡。
- 一个**本地优先工具**：无账号、无云同步、无服务端依赖，数据在用户设备上。

### 2.2 它不是什么

- 不是 AI 解析器：平台不生成句译、语法、词义，笔记由用户写。
- 不是题库/刷题 App：第一版不做作答判分。
- 不是单词卡 App：复习以篇为单位，不是纯单词间隔重复。
- 不是内容平台：不做公开 UGC 社区、不做内容分发。
- 不是在线服务：不提供在线 Web 版，不依赖服务器。

### 2.3 与现有替代方案的差异

| 替代方案 | 不足 | 本产品差异 |
|---|---|---|
| 纸质精读 + 手写笔记 | 笔记分散、无法检索、复习无提醒 | 结构化笔记 + 篇级复习提醒 + 可导出打印 |
| 通用笔记工具（Notion、Obsidian） | 不针对四级精读设计，句子/单词定位弱 | 句级/词级定位、生词本、篇级复习一体化 |
| 背单词 App | 脱离语境，只背词不读文 | 以真实阅读语境驱动词汇和语法学习 |
| AI 阅读解析工具 | 解析质量不稳定、成本高、版权风险 | 用户自己写笔记，平台只做组织与提醒 |

## 3. 目标用户

### 3.1 核心用户

- **备考英语四级的大学生**，尤其是有精读需求、愿意自己动笔整理笔记的学生。
- 特征：有明确的四级考试时间点；阅读是薄弱项；习惯用手机或电脑做学习笔记；对“背单词脱离语境”不满意。

### 3.2 次要用户

- 备考六级或其他英语考试、需要精读训练的用户（后续扩展）。
- 需要导入自己学校考试阅读材料的学生。
- 想用自己材料做精读笔记的英语学习者。

### 3.3 非目标用户

- 只想刷题、不想精读的用户。
- 需要 AI 自动生成解析、不愿自己写笔记的用户。
- 需要社交、排行榜、打卡社区的用户。

## 4. 核心痛点与场景

### 4.1 痛点

1. **精读过程割裂**：原文、笔记、生词、复习分散在不同工具里，难以形成闭环。
2. **笔记不可复用**：纸上笔记无法检索、无法按篇复习、无法导出整理。
3. **背单词脱离语境**：单词卡记住了，回到阅读里仍然不认识。
4. **复习无组织**：不知道哪篇该复习、什么时候复习，容易遗忘。
5. **材料来源杂**：真题、模拟题、学校材料分散，缺少统一精读入口。

### 4.2 典型场景

- **场景 A：精读一篇四级阅读**  
  用户打开一篇文章，先读原文，遇到不认识的句子点开写句译和语法笔记，遇到生词点开写语境释义并加入生词本。

- **场景 B：按篇复习**  
  系统提醒“今天该复习这 3 篇”，用户点进去重新精读，之前写过的笔记和高亮都在，快速过一遍单词、短语、语法。

- **场景 C：导出打印**  
  用户把生词本或精读笔记导出为 PDF，打印出来手动背。

- **场景 D：导入自己的材料**  
  用户粘贴学校考试阅读或自己找到的文章，系统切句分词后，用户开始精读。

## 5. 核心闭环

```
选/导文章 → 读原文 → 点句点词写笔记 → 收藏生词 → 按篇复习 → 看记录
```

| 环节 | 用户动作 | 产品支撑 |
|---|---|---|
| **选/导** | 从内置文章库选一篇，或粘贴/上传自己的文章 | 内置文章库 + 导入预览 + 切句分词 |
| **读** | 看原文和题目，题目答案可折叠，不做判分 | 原文分段展示、题目折叠、答案折叠 |
| **点** | 点句子写句译/语法/短语笔记；点单词写释义/搭配，可加生词本 | 句级面板、词级面板、自动保存、笔记高亮 |
| **收** | 管理生词本、打标签、导出 PDF 打印 | 生词本、标签、PDF/HTML 导出 |
| **复** | 收到篇级复习提醒，重新精读，笔记都在 | 复习计划（1/3/7/14 天）、今日待复习、完成标记 |
| **看** | 查看已读篇数、笔记数、生词数、复习历史 | 记录页、统计页 |

**闭环成立的关键**：第 3 步“点”和第 5 步“复”必须顺滑。点一下就有用，复习时笔记原样呈现，用户才愿意持续用。

## 6. 成功指标

### 6.1 核心指标（3—6 个月）

| 指标 | 定义 | 目标方向 |
|---|---|---|
| **精读完成率** | 打开文章后完成精读（有笔记或标记完成）的比例 | 越高越好 |
| **句子点击率** | 精读页中点击过至少一个句子的用户比例 | 越高越好 |
| **单词收藏率** | 精读过程中加入生词本的单词数 / 点击单词数 | 越高越好 |
| **篇目复习完成率** | 到期复习篇目中实际完成复习的比例 | 越高越好 |
| **7 日留存 / 次周留存** | 首次使用后 7 天/次周仍活跃的用户比例 | 越高越好 |
| **PDF 导出使用率** | 使用过导出功能的用户比例 | 观察项 |

### 6.2 不看的指标

- 注册用户数（本地优先，无账号体系）。
- 日活绝对值（个人开源项目，早期样本小，看比率不看绝对值）。
- 分享/传播数据（第一版不做社交分享）。

## 7. 范围边界

### 7.1 MVP 必须做

- 内置文章库（首批 24 篇，按年份/套卷/题型组织）
- 原文 + 题目展示，答案折叠，**不做判分**
- 点句写笔记（句译、语法、短语）
- 点词写笔记（语境释义、搭配、例句），可加入生词本
- 生词本管理、标签、PDF/HTML 导出打印
- 篇级复习计划（默认 1/3/7/14 天）、今日待复习、完成标记
- 用户导入：粘贴 / TXT / MD，预览分段切句，确认后入库
- 阅读记录与基础统计
- 移动端优先（Tauri 桌面端 + Android APK），Web 版以本地桌面形式提供

### 7.2 MVP 明确不做

- 做题作答与判分
- AI 生成解析（句译、语法、词义）
- 账号体系、云同步、多设备同步
- 公开 UGC 社区、分享、排行榜、打卡
- 在线 Web 服务、服务端部署
- OCR、扫描版 PDF 导入
- 复杂复习算法（只做篇级间隔提醒）
- 支付与商业化

### 7.3 二期及以后考虑

- 六级及其他考试阅读扩展
- 词形还原与生词聚合优化
- 更细的复习调度（篇内薄弱项优先）
- 公开文章库与用户分享（需版权与审核方案）
- 移动端原生 App（Flutter/React Native）替代方案评估

## 8. 关键约束

| 类别 | 约束 |
|---|---|
| **形态** | Tauri v2 桌面应用 + Android APK；不提供在线 Web 服务 |
| **数据** | 全部存本地 SQLite；无账号、无云同步 |
| **分发** | GitHub 开源 + GitHub Releases 分发安装包；自动更新走 Tauri updater |
| **成本** | 现金成本接近零；不承担服务器、数据库、CDN 费用 |
| **技术** | React + TypeScript + Rust + rusqlite；不用 ORM、不用服务端框架 |
| **内容** | 内置文章需拥有著作权或已获授权；用户导入内容默认私有 |
| **合规** | 开源许可 + UGC 免责声明；不主动传播用户导入内容 |
| **维护** | 个人维护，尽力响应；README 明确维护预期 |

## 9. 核心风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **内容版权** | 内置文章若无权属，存在法律风险 | 仅内置自有/授权内容；保留授权记录；用户导入默认私有 |
| **冷启动体验空** | 用户自己写笔记，第一篇可能不知道怎么用 | 内置文章 + 引导文案 + 示例笔记 |
| **笔记质量依赖用户** | 用户写得少，复习价值低 | 降低记录门槛，句级/词级面板尽量轻 |
| **跨平台适配** | Windows/macOS/Linux WebView 差异 | 核心交互在三平台手动验证 |
| **自动更新密钥丢失** | 已安装用户永久无法自动更新 | 私钥安全备份，首次发布前实际验证 |
| **个人维护精力** | Issue 堆积、更新停滞 | README 写明维护预期；Issue 模板引导完整信息 |

## 10. 决策记录（与本卡相关的关键取舍）

| 决策 | 结论 | 理由 |
|---|---|---|
| 是否做 AI 解析 | **不做**，笔记由用户写 | 降成本、降版权风险、产品更轻 |
| 是否做题判分 | **不做**，只展示题目和答案 | 降低复杂度，聚焦精读 |
| 复习方式 | **按篇复习**，不做纯单词间隔重复 | 符合“通过阅读背单词”的定位 |
| 小程序 vs 桌面/APK | **放弃小程序**，走 GitHub + APK + 桌面 | 个人主体无法支撑笔记类目，审核风险高 |
| Electron vs Tauri | **Tauri** | 安装包小、内存低、分发成本低 |
| IndexedDB vs SQLite | **SQLite** | IndexedDB 跨应用更新不持久，笔记有丢失风险 |
| 在线 Web vs 本地桌面 | **不做在线 Web**，桌面安装包承载 | 零服务器成本，数据本地 |
| 内置文章数量 | 首批 **24 篇**（2025 年两次考试 6 套卷） | 足够冷启动验证，后续扩展 |

## 11. 验收标准（项目级）

第一版可发布，需同时满足：

1. 内置 24 篇文章可正常展示，题目答案可折叠。
2. 点句、点词可写笔记并自动保存，重启应用后笔记不丢。
3. 生词本可增删改查、打标签，可导出打印友好文件。
4. 复习计划可生成、今日待复习可见、完成后可推进下次复习。
5. 用户可粘贴/TXT/MD 导入文章，预览切句后可入库，导入文章可删除。
6. Windows 和 Android 安装包可从 GitHub Release 下载安装。
7. 已安装旧版本能检测到新版本并完成自动更新。
8. `AGENTS.md` 中的测试清单全部通过。
9. README、LICENSE、免责声明齐全。

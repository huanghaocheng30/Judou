## 1. 文档说明

### 1.1 目的

回答四个问题：

1.  **测什么**：各模块的测试范围与优先级。
2.  **怎么测**：单元测试、集成测试、手动验收的分工。
3.  **什么时候算通过**：准入与准出标准。
4.  **CI 怎么配**：自动化测试的触发条件与必过项。

### 1.2 范围

覆盖 MVP 全部功能。不覆盖二期功能。Android 专项测试在 M7 之后补充，MVP
阶段以桌面端为主。

### 1.3 读者

- 开发者本人：作为写测试和自查的依据。
- AI 编码代理：生成测试代码时的用例来源。
- 发布前自查：第 6 节手动验收清单。

### 1.4 原则

1.  **能自动化的不手动**：数据层、导入解析、提交校验、复习推进全部用单元测试覆盖。
2.  **自动化测不了的才手动**：跨平台 WebView
    差异、点击定位、自动更新链路。
3.  **测试跟着里程碑走**：每个里程碑完成前，对应测试必须绿，不攒到最后。
4.  **不追求覆盖率数字**：追求"关键路径有测试、回归能拦住"，不追求 90%
    覆盖率。

## 2. 测试分层

  -----------------------------------------------------------------------------------------------------------------
  层                     范围                                                  工具              运行时机
  ---------------------- ----------------------------------------------------- ----------------- ------------------
  **单元测试（Rust）**   数据层、导入解析、提交校验、复习推进、`utf16_slice`   `cargo test`      每次提交、CI

  **单元测试（前端）**   `api.ts` 封装、工具函数、防抖逻辑                     Vitest            每次提交、CI

  **集成测试（Rust）**   command 层与 SQLite 的交互、事务回滚、级联删除        `cargo test` +    每次提交、CI
                                                                               内存 SQLite       

  **手动验收**           页面交互、点击定位、自动更新、跨平台                  人工              每个里程碑结束时

  **发布前回归**         全流程走查、三平台安装、自动更新验证                  人工              M7 发布前
  -----------------------------------------------------------------------------------------------------------------

**MVP 不做 E2E 自动化**（Playwright 等）。桌面 Tauri 的 E2E 工具链在 MVP
阶段投入产出比低，核心逻辑已由 Rust 单元测试覆盖，页面交互用手动验收。

### 3.2 导入解析（M5）

详细用例见 **C4 第 12.1 节**，本文档不重复。覆盖要点：

- 缩写不切、小数不切、引号闭合后切、省略号后小写不切、单字母缩写不切。
- 无空行单段 + warning、全角标点清洗。
- 中文/emoji 偏移正确。
- 空文本、超长文本错误码。

### 3.3 导入提交（M5）

详细用例见 **C4 第 12.2 节**。覆盖要点：

- 正常导入四表数量正确。
- L1---L4 每类错误码至少一个用例。
- 事务回滚：失败后 article 表无残留。
- 重复导入生成不同 `article_id` 和 `source_key`。
- 强制 `visibility='user'`。

### 3.4 `utf16_slice`（M5）

详细用例见 **C4 第 12.3 节**。覆盖
ASCII、中文、emoji、代理对、边界值、非法区间。**这是导入模块的前置依赖，必须最先通过。**

## 5. CI 要求

### 5.1 M0 的 CI

D2 第 6 节的 `ci.yml` 已定义：三平台矩阵跑 `npm test` + `cargo test`。M0
验收即三平台全绿。

### 5.2 后续里程碑的 CI 增量

  里程碑   CI 增量
  -------- --------------------------------------------------
  M1       种子导入幂等测试、级联删除测试加入
  M2       笔记 upsert 测试加入
  M3       生词聚合、标签关联测试加入
  M4       复习推进、日期边界测试加入
  M5       导入解析、提交、`utf16_slice` 全用例加入
  M6       导出、设置测试加入
  M7       发布工作流 `publish.yml` 加入（按 C5 第 2.5 节）

### 5.3 合并门槛

- `cargo test` 全绿。
- `npm test` 全绿。
- `cargo fmt --check` 通过（P1，可先不强制）。
- `cargo clippy` 无 error 级警告（P1，可先不强制）。

**MVP 阶段不设覆盖率门槛。**
覆盖率数字对个人项目意义有限，关键路径有测试即可。

## 7. 测试数据准备

### 7.1 种子数据

- 24 篇内置文章 JSON，放 `src-tauri/resources/seed/`。
- **偏移量必须与文本一致**，M1 入库前用测试校验，避免 M2 点击定位串位。

### 7.2 导入测试数据

放 `src-tauri/tests/fixtures/`，至少包含：

  文件                  覆盖场景
  --------------------- ------------------------
  `normal.txt`          多段、多句、正常标点
  `abbreviations.txt`   `Mr.`、`U.S.`、`e.g.`
  `quotes.txt`          引号内终止、闭合后切
  `ellipsis.txt`        `...` 后小写
  `no_blank_line.txt`   无空行单段
  `fullwidth.txt`       全角标点
  `chinese_emoji.txt`   中文 + emoji，偏移校验
  `empty.txt`           空文本

### 7.3 测试数据库

- 全部用 `Connection::open_in_memory()` + 执行 `001_init.sql`。
- 每次测试独立建库，不共享状态。
- 不 mock 数据库，用真实 SQLite 内存库，保证 SQL 和约束真实生效。

## 8. 缺陷分级与处理

  级别     定义                             处理
  -------- -------------------------------- ----------------------------
  **P0**   核心功能不可用、数据丢失、崩溃   立即修复，阻塞发布
  **P1**   次要功能异常、体验明显受损       发布前修复，或明确记录延后
  **P2**   边缘场景、样式问题               可延后到 v1.1

**数据丢失一律 P0**：笔记保存失败后丢失、更新后 SQLite
数据被重置、导入事务未回滚产生脏数据。

## 1. 文档说明

### 1.1 目的

回答四个问题：

1.  **机器上装什么**：各平台的前置依赖和版本要求。
2.  **项目长什么样**：目录结构和各目录职责。
3.  **配置文件怎么写**：`tauri.conf.json`、`Cargo.toml`、`vite.config.ts`、`capabilities`。
4.  **怎么跑起来**：开发、构建、测试命令，以及 CI 空跑配置。

### 1.2 范围

覆盖桌面端（Windows/macOS/Linux）和 Android 的开发环境。iOS 不在 MVP
范围内，不展开。发布链路的详细配置见 `docs/C5-自动更新与发布方案.md`。

### 1.3 读者

- 首次搭建项目的自己。
- AI 编码代理：生成配置文件和目录时对照本文档。
- 未来的贡献者。

## 2. 前置依赖

### 2.1 通用依赖

  ------------------------------------------------------------------------------------------------------------
  依赖                    版本要求                                                说明
  ----------------------- ------------------------------------------------------- ----------------------------
  Rust                    stable（通过 rustup 安装）                              Tauri 后端编译

  Node.js                 LTS（20 或 22）                                         前端构建

  包管理器                npm / pnpm / bun 任选                                   本文档以 npm
                                                                                  示例，命令可按包管理器替换

  `@tauri-apps/cli`       `^2`（当前 2.9.x）                                      Tauri 命令行工具

  Tauri Rust CLI          `cargo install tauri-cli --version "^2.0.0" --locked`   Android 构建需要
  ------------------------------------------------------------------------------------------------------------

**`@tauri-apps/cli` 与 `tauri-cli` 的关系**：前者通过 npm 安装，用于
`npm run tauri dev/build`；后者通过 cargo 安装，`cargo tauri android`
系列命令依赖它。两者都装，避免 Android 构建时找不到 CLI。

### 2.2 各桌面平台依赖

  ----------------------------------------------------------------------------------------------------------------------------------
  平台                         必须安装                                                                      说明
  ---------------------------- ----------------------------------------------------------------------------- -----------------------
  **Windows**                  Microsoft C++ Build Tools（勾选"使用 C++ 的桌面开发"）、WebView2              WebView2 在 Windows 10
                                                                                                             v1803+ 通常已预装；构建
                                                                                                             MSI 需要 VBSCRIPT
                                                                                                             可选功能启用

  **macOS**                    Xcode 或 Xcode Command Line Tools                                             只开发桌面端时 Command
                                                                                                             Line Tools
                                                                                                             足够；安装后启动一次
                                                                                                             Xcode 完成初始化

  **Linux（Debian/Ubuntu）**   `libwebkit2gtk-4.1-dev`、`libappindicator3-dev`、`librsvg2-dev`、`patchelf`   与 C5 工作流中的 Linux
                                                                                                             依赖一致
  ----------------------------------------------------------------------------------------------------------------------------------

Linux 一次性安装命令：

``` bash
sudo apt-get update
sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf
```

### 2.3 Android 额外依赖

Android 构建是 **M7 的可选任务**，但环境建议在 M0
阶段一次性配好，避免后期返工。

  -------------------------------------------------------------------------------------------
  依赖                    版本要求                说明
  ----------------------- ----------------------- -------------------------------------------
  JDK                     17+                     `tauri android` 要求

  Android Studio          最新稳定版              用于安装 SDK 和 NDK

  Android SDK Platform    API 24+                 Tauri 最低支持

  Android SDK             ---                     `adb` 等工具
  Platform-Tools                                  

  NDK (Side by side)      27.0.0 或 29.x（与      社区实践中 29.0.14206865
                          tauri-cli               可用；若版本不匹配，`cargo tauri android`
                          期望版本一致）          会报 `NDK_HOME` 相关错误

  Android SDK Build-Tools ---                     构建 APK

  Android SDK             ---                     无 Android Studio 时的替代方案
  Command-line Tools                              
  -------------------------------------------------------------------------------------------

**环境变量（必须设置）** ：

``` bash
export ANDROID_HOME="$HOME/Library/Android/sdk"          # macOS 示例
export NDK_HOME="$ANDROID_HOME/ndk/29.0.14206865"        # 替换为实际 NDK 版本
export PATH="$PATH:$NDK_HOME/toolchains/llvm/prebuilt/darwin-x86_64/bin"
```

Windows 将路径改为对应安装目录（如
`%LOCALAPPDATA%\Android\Sdk`）。`NDK_HOME` 必须指向 NDK
的**版本目录**，不是 NDK 根目录。

**Rust Android 目标**：

``` bash
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
```

## 3. 项目结构

### 3.1 目录树

``` text
project-root/
├── docs/                          # A1/A2/C1—C5/D1/F1 等文档
├── src/                           # React + TypeScript 前端
│   ├── pages/                     # 页面组件
│   ├── components/                # 可复用组件
│   ├── stores/                    # Zustand 全局 UI 状态
│   ├── hooks/                     # TanStack Query 封装、自定义 hooks
│   ├── lib/
│   │   ├── api.ts                 # 唯一 invoke 封装
│   │   ├── types.ts               # 与 Rust 返回结构对应的类型
│   │   └── utils/                 # 防抖、格式化、本地草稿
│   ├── styles/
│   ├── main.tsx
│   └── App.tsx
├── src-tauri/                     # Rust 后端（完整 Cargo crate）
│   ├── src/
│   │   ├── main.rs                # 入口
│   │   ├── lib.rs                 # Tauri builder、状态管理、command 注册
│   │   ├── commands/              # 按领域分文件：article.rs / note.rs / vocab.rs / review.rs / import.rs / setting.rs
│   │   ├── import/                # 清洗、切句、分词、commit 校验
│   │   ├── note/                  # 句笔记、词笔记
│   │   ├── vocab/                 # 生词、标签、导出
│   │   ├── review/                # 复习计划、推进
│   │   ├── article/               # 文章查询、进度、删除
│   │   ├── db/                    # 连接管理、migration 执行器、种子导入
│   │   └── error.rs               # CommandError
│   ├── migrations/
│   │   └── 001_init.sql
│   ├── resources/
│   │   └── seed/                  # 内置文章 JSON + manifest.json
│   ├── capabilities/
│   │   └── default.json
│   ├── Cargo.toml
│   └── tauri.conf.json
├── public/                        # 前端静态资源
├── .github/workflows/
│   └── ci.yml                     # M0 先空跑测试，发布工作流 M7 再加
├── AGENTS.md
├── README.md
├── LICENSE
├── package.json
├── vite.config.ts
├── tsconfig.json
└── index.html
```

**与 C1 第 6 节的一致性**：目录结构与 C1 完全对齐，唯一新增的是
`src-tauri/src/db/` 明确承担"连接管理 + migration 执行器 +
种子导入"，这与 D1 第 5 节"单连接 + Mutex"的设计一致。

### 3.2 目录职责约定

  -----------------------------------------------------------------------------------------
  目录                          职责                       不该放什么
  ----------------------------- -------------------------- --------------------------------
  `src/lib/api.ts`              所有 `invoke`              组件逻辑、样式
                                调用的唯一出口             

  `src/lib/types.ts`            与 Rust                    业务逻辑
                                返回结构一一对应的类型     

  `src/stores/`                 Zustand 全局 UI 状态       数据库数据的缓存（数据库数据走
                                                           TanStack Query）

  `src-tauri/src/commands/`     Tauri command              复杂业务逻辑（下沉到领域模块）
                                注册、参数解析、错误转换   

  `src-tauri/src/db/`           `Mutex<Connection>`        业务查询
                                管理、`001_init.sql`       
                                执行、种子导入             

  `src-tauri/migrations/`       只增不改的 SQL 迁移文件    业务数据

  `src-tauri/resources/seed/`   24 篇内置文章 JSON         代码
  -----------------------------------------------------------------------------------------

## 4. 核心配置文件

### 4.1 `tauri.conf.json`

``` json
{
  "$schema": "https://schema.tauri.app/config/2",
  "productName": "cet4-reader",
  "version": "0.1.0",
  "identifier": "com.yourname.cet4reader",
  "build": {
    "beforeDevCommand": "npm run dev",
    "devUrl": "http://localhost:1420",
    "beforeBuildCommand": "npm run build",
    "frontendDist": "../dist"
  },
  "app": {
    "windows": [
      {
        "title": "四级阅读精读",
        "width": 1200,
        "height": 800,
        "minWidth": 800,
        "minHeight": 600
      }
    ],
    "security": {
      "csp": null
    }
  },
  "bundle": {
    "active": true,
    "targets": "all",
    "createUpdaterArtifacts": true,
    "icon": [
      "icons/32x32.png",
      "icons/128x128.png",
      "icons/128x128@2x.png",
      "icons/icon.icns",
      "icons/icon.ico"
    ]
  },
  "plugins": {
    "updater": {
      "active": true,
      "endpoints": [
        "https://github.com/{owner}/{repo}/releases/latest/download/latest.json"
      ],
      "pubkey": "MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQC...",
      "windows": {
        "installMode": "passive"
      }
    }
  }
}
```

**必填字段说明**：

  ----------------------------------------------------------------------------------------------------------------------------------------------------------
  字段                              要求                                     说明
  --------------------------------- ---------------------------------------- -------------------------------------------------------------------------------
  `identifier`                      **必填，反向域名格式**                   如
                                                                             `com.yourname.cet4reader`，用于应用数据目录、代码签名、商店识别，必须全局唯一

  `bundle.createUpdaterArtifacts`   设为 `true`                              否则不生成 `.sig` 签名文件，自动更新链路断裂

  `plugins.updater.pubkey`          填第一步生成的公钥                       与 GitHub Secrets 中的私钥配对

  `plugins.updater.endpoints`       指向                                     不要硬编码版本号
                                    `releases/latest/download/latest.json`   
  ----------------------------------------------------------------------------------------------------------------------------------------------------------

**M0 阶段可以先不填 `plugins.updater`**，M7 发布前再补。但 `identifier`
和 `bundle.createUpdaterArtifacts`
建议一开始就写对，避免后期迁移数据目录。

### 4.2 `src-tauri/Cargo.toml`

``` toml
[package]
name = "cet4-reader"
version = "0.1.0"
edition = "2021"

[lib]
name = "cet4_reader_lib"
crate-type = ["staticlib", "cdylib", "rlib"]

[build-dependencies]
tauri-build = { version = "2", features = [] }

[dependencies]
tauri = { version = "2", features = [] }
tauri-plugin-updater = "2"
tauri-plugin-opener = "2"
serde = { version = "1", features = ["derive"] }
serde_json = "1"
rusqlite = { version = "0.32", features = ["bundled"] }
uuid = { version = "1", features = ["v4"] }
sha2 = "0.10"
```

**`rusqlite` 的 `bundled` feature 是必须的**：它把 SQLite
源码一起编译进二进制，用户机器不需要预装
SQLite，跨平台行为一致。版本锁定在 `0.32` 一带，升级前跑全量测试。

**不引入 `tauri-plugin-sql`**。D1 第 5 节明确使用
`State<Mutex<Connection>>` + rusqlite 手写 SQL；`tauri-plugin-sql`
的连接池和迁移机制与我们的单连接事务设计冲突，不使用。

### 4.3 `src-tauri/capabilities/default.json`

``` json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Capability for the main window",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "updater:default",
    "opener:default"
  ]
}
```

Android 构建时，额外加 `"android-update:default"`（C5 第 3
节）。`updater:default` 不加会导致 `check_update` 被 ACL 拒绝。

### 4.4 `vite.config.ts`

``` ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

const host = process.env.TAURI_DEV_HOST;

export default defineConfig({
  plugins: [react()],
  clearScreen: false,
  server: {
    port: 1420,
    strictPort: true,
    host: host || false,
    hmr: host
      ? { protocol: "ws", host, port: 1421 }
      : undefined,
    watch: {
      ignored: ["**/src-tauri/**"],
    },
  },
});
```

**端口 1420 和 `strictPort: true`** 与 Tauri
默认模板一致，`tauri.conf.json` 的 `devUrl` 也指向 1420。`watch.ignored`
避免前端热更新扫描 Rust 目录。

### 4.5 `package.json` 脚本

``` json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "preview": "vite preview",
    "tauri": "tauri",
    "tauri:dev": "tauri dev",
    "tauri:build": "tauri build",
    "test": "vitest run",
    "test:watch": "vitest"

```

## 5. 启动命令

### 5.1 首次初始化

``` bash
# 1. 创建前端项目（如果从零开始）
npm create vite@latest . -- --template react-ts

# 2. 安装前端依赖
npm install

# 3. 添加 Tauri CLI 和 API
npm install --save-dev @tauri-apps/cli@^2
npm install @tauri-apps/api@^2

# 4. 初始化 Tauri（会生成 src-tauri/）
npx tauri init
# 交互式填写：应用名、窗口标题、前端开发地址 http://localhost:1420、前端构建目录 ../dist

# 5. 安装 Rust CLI（Android 构建需要）
cargo install tauri-cli --version "^2.0.0" --locked
```

`npx tauri init` 会生成 `src-tauri/`
骨架、`tauri.conf.json`、`Cargo.toml` 和图标。之后按第 4
节替换配置内容，按第 3 节调整目录结构。

### 5.2 日常开发

  ---------------------------------------------------------------------------------
  命令                                          作用
  --------------------------------------------- -----------------------------------
  `npm run tauri:dev` 或 `npx tauri dev`        启动 Tauri
                                                桌面开发模式，前端热更新，Rust
                                                改动自动重编译

  `npm run dev`                                 只启动 Vite 前端，不启动 Tauri
                                                窗口（用于纯 UI 调试）

  `cd src-tauri && cargo test`                  运行 Rust 单元测试

  `npm test`                                    运行前端测试（Vitest）

  `cd src-tauri && cargo fmt && cargo clippy`   格式化和 lint
  ---------------------------------------------------------------------------------

### 5.3 构建

  ------------------------------------------------------------------------------------
  命令                                产物
  ----------------------------------- ------------------------------------------------
  `npm run tauri:build`               当前平台的安装包，位于
                                      `src-tauri/target/release/bundle/`

  `cargo tauri android build`         Android APK，位于
                                      `src-tauri/gen/android/app/build/outputs/apk/`
  ------------------------------------------------------------------------------------

Android 首次构建前需要：

``` bash
cargo tauri android init
```

在 CI 中使用非交互模式 `cargo tauri android init --ci`，避免等待输入。

## 6. CI 空跑（M0）

M0 阶段只需要一条"能跑测试"的工作流，发布工作流在 M7 再加。

`.github/workflows/ci.yml`：

``` yaml
name: ci

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    strategy:
      matrix:
        include:
          - platform: ubuntu-22.04
          - platform: windows-latest
          - platform: macos-latest
    runs-on: ${{ matrix.platform }}

    steps:
      - uses: actions/checkout@v4

      - name: Install Linux dependencies
        if: matrix.platform == 'ubuntu-22.04'
        run: |
          sudo apt-get update
          sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev \
            librsvg2-dev patchelf

      - uses: actions/setup-node@v4
        with:
          node-version: lts/*

      - uses: dtolnay/rust-toolchain@stable

      - uses: swatinem/rust-cache@v2
        with:
          workspaces: './src-tauri -> target'

      - run: npm ci

      - run: npm test

      - name: Rust tests
        working-directory: src-tauri
        run: cargo test
```

**M0 的验收就是这条流水线在三平台全绿**。Android 构建 job 在 M7
加入发布工作流，不在 M0 的 CI 中。

## 7. M0 自检清单

M0 结束时逐项确认：

- [ ] `npm run tauri:dev` 能启动桌面窗口。
- [ ] 前端页面能通过 `invoke` 调用一个 `ping` command 并拿到返回。
- [ ] `src-tauri/src/db/` 中 `Mutex<Connection>` 已注册为 Tauri state。
- [ ] 启动时执行 `001_init.sql`，`app_data_dir/app.db`
  生成，`schema_meta.version = 1`。
- [ ] `PRAGMA foreign_keys = ON` 生效（可查 `PRAGMA foreign_keys;` 返回
  1）。
- [ ] `cargo test` 和 `npm test` 本地通过。
- [ ] GitHub Actions `ci.yml` 三平台绿灯。
- [ ] `AGENTS.md`、`README.md`、`LICENSE` 已在仓库根目录。
- [ ] Android 环境变量和 Rust targets 已配置（不要求 M0 构建
  APK，但环境就绪）。

  问题                    原因                       处理

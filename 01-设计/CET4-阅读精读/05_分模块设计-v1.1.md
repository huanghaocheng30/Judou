## 一、模块总览

```
[内容生产链路]（.tmp 脚本，离线）
      ↓ 产出
[内容包 JSON] ──→ [M1 内容导入] ──→ [本地库]
                                    ↓
                          [M2 阅读渲染] ──┬──→ [M3 句子解析卡]
                                          ├──→ [M4 词卡]
                                          ├──→ [M5 题目]
                                          └──→ [M6 空格解析]
                                    ↓
                    [M7 生词本] [M8 笔记] [M9 位置恢复]
```

| 模块 | 职责一句话 | 数据来源 |
|---|---|---|
| M1 内容导入 | 启动时把内容包 upsert 进本地库，不覆盖用户数据 | `content-pack/manifest.json` |
| M2 阅读渲染 | 把一篇渲染成可点句、可点词、可点空格的正文 | `paragraphs[]` |
| M3 句子解析卡 | 点「析」展示六段式解析 | `sentence.analysis` |
| M4 词卡 | 点词展示语境义或通用义，支持收藏与笔记 | `token.analysis` / `pack.lexicon` |
| M5 题目 | 原文在上、题目在下默认折叠，选项不可点 | `questions[]` |
| M6 空格解析 | 选词填空点号显示答案与排除 | `blanks[no]` |
| M7 生词本 | 收藏词条与来源句，支持三态 | `vocab` 表 |
| M8 笔记 | 句级/词级笔记，停止输入自动保存 | `note` 表 |
| M9 位置恢复 | 回到上次阅读位置 | `progress` 表 |

## 二、M1 内容导入

**输入**：安装包内 `content-pack/manifest.json`（`packVersion` + 文章清单 + 每篇 `sourceKey`/`contentHash`）+ 各篇内容包 JSON。

**输出**：本地 `article` / `sentence` / `token` / `question` / `blank` / `lexicon` 表数据；`app_meta.packVersion`。

**关键规则**（承接 04 §5.1）：
1. 版本一致则跳过；不一致逐篇 upsert。
2. `sourceKey` 存在 → **只更新内容字段**；`note`/`vocab`/`progress` 表**绝不覆盖**。
3. 全流程一个事务；失败回滚，旧版本仍可用。

**验收点**：删库重装后 12 篇全在；仅更新内容时不丢笔记与生词。

---

## 三、M2 阅读渲染

**输入**：一篇的 `paragraphs[]`，每个 token 含 `start`（字符偏移）、`surface`、`normalized`、`isWord`、`isBlank`。

**输出**：可交互 DOM —— 单词节点（可点）、空格节点（可点）、句末「析」触点。

**关键规则**：
1. 按 `start` 顺序把句子切成「文本片段 / 单词 / 空格」三类节点，**顺序与偏移必须严格对齐**（内容包已保证）。
2. 句末「析」触点与句子绑定，不干扰点词。
3. 长篇阅读按段落分块渲染，段落之间留视觉间隔。
4. 句卡默认展开前两块（翻译、成分划分），其余折叠（裁决 #9）。

**验收点**：点任意词不误触句子；点「析」不误触词；中文标点与英文标点都不断行错位。

---

## 四、M3 句子解析卡

**输入**：`sentence.analysis`（九字段：`translationLiteral`/`translationNatural`/`structMarkup`/`structureSummary`/`components[]`/`clauses[]`/`phrases[]`/`pitfalls[]`/`paragraphRole`）。

**输出**：六段式卡片。

**关键规则**：
1. 段序固定：①翻译（直译 + 顺译）②主干/成分划分 ③从句和语法点 ④重点短语 ⑤易错点 ⑥段落作用。
2. `structMarkup` 中的符号 **必须渲染成视觉样式而非丢弃**：
   - `【】` → 主语样式（如蓝色 + 轻微底色）
   - `_ _` → 谓语下划线
   - `~ ~` → 宾语/表语波浪线
   - `{ }` → 从句（保留花括号）
   - `( )` → 短语/分词（保留圆括号）
3. 缺失任一字段时降级显示「本段暂无解析」，不报错。

**验收点**：12 篇 274 句全部能打开六段式；符号样式在深色模式下仍可分辨。

---

## 五、M4 词卡

**输入**：`token.normalized`；查 `token.analysis`（语境义）→ 查 `pack.lexicon[normalized]`（通用义）。

**输出**：词卡（音标 + 词性 + 释义 + 搭配 + 例句 + 可选「更多」）；收藏按钮；笔记框。

**关键规则**：
1. **降级链路顺序固定**：本句语境义 → 词库通用义 → 「暂无预置解析」（仍可收藏）。
2. 标题区分来源：语境义显示「本句中的意思」，词库义显示「词义（通用）」。
3. `more` 下三档（词根 / 近义 / 易混）默认折叠，点「更多」展开。
4. `more.*` 与 `blanks[].distractors` 在数据里**可能是数组也可能是字符串**，渲染层必须两种都能处理（逐项换行或顿号连接）。
5. 词条不存在时不得留空白卡片或报错。

**验收点**：`provoke`（语境义）、`teenagers`（词库义）、`the`（降级）三种情况各显示正确。

---

## 六、M5 题目

**输入**：`questions[]`（`no`/`stem`/`options[]`/`answer`）。

**输出**：题目标题可选中的折叠区（裁决 #13）。

**关键规则**：
1. 原文在上、题目在下，默认折叠；题目入口在页头（显示题号范围）。
2. **选项不可点**（不做作答与判分）。
3. 答案默认隐藏，提供「显示答案」。
4. 题目标题高亮（可用性修复项）。

**验收点**：点选项无任何反应；点「显示答案」只显示答案字母与题干对应关系。

---

## 七、M6 空格解析

**输入**：`blankNos[]`、`blanks[no]`（`answerKey`/`answerWord`/`reason`/`distractors`）。

**输出**：正文中编号空格 + 点开后的解析卡。

**关键规则**：
1. 空格渲染为带编号的可点节点（如 `26`），视觉上与普通词区分。
2. 解析卡三段：正确答案（词 + 词库字母）/ 为什么是它 / 易错与排除（**逐条换行**）。
3. 未作答也可查看（本产品不做作答）。

**验收点**：30 个空全部可点且内容正确；排除项每条独立一行。

---

## 八、M7 生词本 / M8 笔记 / M9 位置恢复

### M7 生词本
- 词条 + 来源句片段 + 时间；三态（在学/已掌握/忽略）**数据层定好、UI 二期暴露**。
- 同一词重复收藏不产生重复条目。

### M8 笔记
- 两类：句级（`s:篇:句`）、词级（`w:篇:句:偏移`）。
- 停止输入 600ms 写库；写前存 `localStorage` 草稿；失败保留草稿并提示重试。

### M9 位置恢复
- 每篇记录「上次所在句 id + 句内偏移」；进入时恢复；手动回顶则清空。
- 长篇阅读按段落锚定，避免因字体变化错位。

**验收点**：关掉重开回到原位置；断网/写库失败时草稿不丢。

---

## 九、跨模块约束

1. **目标代码区**：`02-代码/`。内容包与词库属设计产物（`01-设计/`），开发阶段只读引用。
2. **不改变内容契约**：开发阶段不得修改内容包结构；发现内容问题走修复包流程。
3. **无网络依赖**：除收尾部署外，运行期不联网。
4. **体积约束**：12 篇内容包合计约 3 MB（含词库切片），加壳后应远低于 30 MB 卡口（04 §9.2）。
5. **可访问性**：键盘可达所有交互点；颜色不作为唯一信息通道（呼应 LingQ 教训）。

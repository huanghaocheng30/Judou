## 一、目标与非目标

**产品一句话**：**句读 Judou** —— 一个离线优先的英语精读工作台。打开就有真题原文与人工校订的六级/四级解析，点句看结构、点词看语境义、点空看排除项，自己的笔记叠在上面；也可以导入自己的材料来精读；按篇复习，全部数据留在本机。

**本期目标（按用户裁决，全部纳入）**

| # | 目标 | 可验收形态 |
|---|---|---|
| G1 | 打开即精读 | 首页 → 继续精读 ≤2 次点击进入上次位置 |
| G2 | 解析现成 | 274/274 句六段式、213 张词卡、30 空解析，全程离线 <300ms |
| G3 | 笔记可叠 | 句笔记/词笔记自动保存，重启不丢 |
| G4 | 生词可沉淀 | 收藏、标签、掌握状态、按文章分组、点回原句 |
| G5 | 有回头路 | 篇级复习 1/3/7/14 天 + 今日待复习 + 复习日志 |
| G6 | 自有材料能进来 | 粘贴/TXT/MD → 预览切句 → 入库 → 降级精读 |
| G7 | 科目与年份可扩 | 多考试类型（四级/六级/其他）+ 多年份筛选 |
| G8 | 可交付 | Windows 安装包 + Android APK + 自动更新 + 记录统计 |

**非目标**：做题判分、云同步与账号、社交/社区/排行榜、运行时 AI 生成解析、公开 UGC 分发。

## 二、用户角色与核心旅程

**角色**：单一本地用户（无账号、无角色权限）。

**旅程 1 · 首次使用（新用户）**
安装 → 首次启动（引导页：三句话说明「点句看解析 / 点词看语境义 / 可以导入自己的材料」）→ 首页空态（无复习、无继续）→ 文章库（内置 12 篇，按考试类型/年份筛选）→ 进第一篇 → 读完 → 首次完成生成复习计划（`next_review_at = 今天+1`）。

**旅程 2 · 日常精读（核心）**
首页「继续精读」→ 上次落点（篇 + 段落锚点 + 滚动位置）→ 点句子 → 解析卡（六段式）→ 点词 → 词卡（语境义优先）→ 收藏/写笔记 → 完成。

**旅程 3 · 今日复习**
首页「今日待复习（N）」→ 复习页列表（按到期时间）→ 进入复习模式（复用精读页，隐藏已读标记）→ 完成 → `interval_index+1`，写 `review_log`。

**旅程 4 · 导入自有材料**
导入页 → 粘贴文本或选 TXT/MD → 预览（识别标题、自动分段切句、显示句/词数、可改标题、可剔除空段）→ 提交 → 四层校验 → 入「我导入的」→ 降级精读（无解析，可写笔记、可收生词）。

**旅程 5 · 生词回看与导出**
生词本（按文章分组 / 按标签 / 按掌握状态）→ 点词回原句语境 → 导出 HTML（可打印）。

## 三、信息架构与页面地图

采 docs A2 §4.1 的八页骨架 + 导航壳（这是 v1.1「两页跳转」的替代）。

```
导航壳（桌面：左侧边栏 220px 常驻；移动：底部 Tab 5 项）
├── /            首页·今日        今日待复习 / 继续精读 / 最近阅读
├── /articles    文章库           内置（考试类型分组）· 我导入的；筛选+搜索
│   └── /articles/:id  精读页     原文 + 题目 + 解析栏（核心页）
├── /review      复习             今日待复习列表 → 复习模式（复用精读页）
├── /vocab       生词本           列表 / 标签 / 掌握状态 / 导出
└── /me          我的（移动端聚合） 记录 / 统计 / 导入 / 设置 / 关于
    ├── /import  导入（桌面端可提到侧边栏一级）
    ├── /records 记录与统计
    └── /settings 设置
```

**桌面侧边栏**：今日 / 文章库 / 复习 / 生词本 / 导入 / 记录 / 设置（7 项，带图标与角标「今日待复习数」）。
**移动底部 Tab（5 项）**：今日 / 文章 / 复习 / 生词 / 我的 —— 导入、记录、设置收进「我的」。

**为什么这样分组（裁决依据）**
- **来源是一级分组，考试类型是筛选主维度**：文章库一级只分「内置 / 我导入的」（对应数据层 `visibility`），考试类型（四级/六级/其他）与年份、题型做成筛选器。理由：考试类型未来会增加（考研/雅思），硬分组会让侧边栏与列表无限膨胀；而 `visibility` 只有两值，天然适合做一级。
- 与 docs A2 §4.1 的差异：docs 把「内置文章 / 我的导入」放在文章库二级；我们提为一级（用户明确说要「用户导入」是重点场景，需要显眼入口）。此差异已在 `07` 文档 §八 登记。

## 五、本期范围与版本规划

本期＝用户裁决的「全要」。按 docs F1 的 M0~M7 骨架重排，每 M 都能构成一次有意义的人工测试。

| 里程碑 | 内容 | 依赖 | 人工测试点 |
|---|---|---|---|
| **M0** 骨架与环境 | Tauri v2 + React + Vite + TS 骨架；rusqlite 连接；`001_init.sql`；`ping` 链路；主题壳；CI 空跑 | 无 | 窗口能开、主题能切、ping 通、库建好 |
| **M1** 数据层与文章库 | 内容包落位 + manifest + 幂等导入（10+ 表）；文章库两分组 + 筛选；精读页**只读**渲染 | M0 | 12 篇在不在、筛选对不对、正文逐字一致 |
| **M2** 精读闭环（解析三件套） | 句子解析卡（六段式 + 符号样式）、词卡（三态降级）、题目与空格；笔记（句/词）自动保存 | M1 | 点句出解析、点词出语境义、点空出排除项、笔记重开还在 |
| **M3** 生词本 | 收藏/编辑/标签/掌握状态/点回原句 | M2 | 收藏能存、标签能筛、点回能定位 |
| **M4** 复习 | 篇级计划 1/3/7/14、今日待复习、复习模式、日志 | M2 | 今天读完明天到期、完成一次顺延一档 |
| **M5** 用户导入 | 粘贴/TXT/MD → 预览切句 → 四层校验 → 入库 → 降级精读 | M1 | 粘 500 词 → 预览句数对 → 入库能在「我导入的」读到 |
| **M6** 记录/统计/导出/设置 | 阅读记录、统计、生词导出、备份恢复、设置项 | M3/M4 | 统计数字对、导出文件能打开 |
| **M7** 发布链路 | updater + Actions + Releases + Android APK | M1~M6 | 安装包能装、更新检查生效 |

**与 docs M0~M7 的对应**：M0/M1 同 docs；docs M2（精读闭环）在我们这里拆成 M2（解析三件套 + 笔记）与 M3（生词）/M4（复习）；docs M5（导入）→ 我们 M5；docs M3（生词）/M4（复习）→ 我们 M3/M4（顺序前移，因为复习依赖精读闭环更紧）；docs M6（导出记录）→ 我们 M6；docs M7（发布）→ 我们 M7。

**为什么把复习排在导入之前**：复习依赖「精读闭环完成」这一事件（`review_plan` 由首次完成触发），与 M2 紧耦合；导入是独立入口，依赖只有 M1。但**若你希望先验证「用户导入」这条痛点**，M4 与 M5 可对调（两者无依赖关系，成本相同）。

## 六、业务流程与业务规则

### 6.1 内置内容导入（启动时，M1）
1. 读 `content-pack/manifest.json`（不存在/损坏 → 错误页，不进入空壳，见 6.8）。
2. 比对 `app_meta.packVersion`：**相等 → 不写库，返回 skipped**。
3. 不等 → 单事务 upsert：`article`/`paragraph`/`sentence`/`token`/`question`/`blank`/`sentence_analysis`/`token_analysis`/`lexicon`；写 `packVersion`。
4. **不触碰** `sentence_note`/`word_note`/`vocab_entry`/`tag`/`review_plan`/`review_log`/`reading_record`/`app_setting`。

### 6.2 用户导入（M5，两阶段）
1. **preview**：输入文本 → 清洗（去 BOM/统一换行/去多余空行）→ 分段 → 切句（句末终止符 + 缩写排除表）→ 分词（`is_word` + `normalized`）→ 返回 `ImportPreview{title 候选, paragraphs[], sentences[], tokens[], 统计}`，**不写库**。
2. 用户在预览页可：改标题、剔除空段/广告段、选考试类型与年份（默认「其他 / 未知」）。
3. **commit**：四层校验（L1 结构 / L2 偏移 / L3 覆盖 / L4 业务）全过 → 单事务入库，`visibility='user'`、`source_key='user-{uuid}'`。
4. 失败按 docs C4 §11 错误码返回，前端给出可操作的提示（例：偏移不符 → 提示「文本含不可见字符，请重新粘贴」）。

### 6.3 精读页交互
- 默认：原文正文 + 题目折叠区（答案折叠）。点句子 → 解析卡；点词 → 词卡；点空格 → 空格卡。
- **宽屏（≥1100px）**：正文居中 + 右侧解析栏（320~380px，跟随滚动定位）。
- **窄屏（<1100px）**：解析在底部抽屉，**高度 ≤55% 视口**，可拖动扩展，关闭回到原文（06 §五#5 沿用）。
- 点词不误触句子：词节点 `stopPropagation`；句子命中区为词之间的空白与句尾。
- 返回：页头 `‹` 接路由历史（`history.back()`，无历史则回 `/articles`），**不允许点了没反应**。

### 6.4 解析三态的降级链路（M4/M5）
- 句解析：`sentence_analysis` 有行 → 六段式；缺字段 → 该段显示「本段暂无解析」；整句无行（用户导入的文章）→ 「该篇无预置解析，可写笔记」。
- 词卡：`token_analysis`（语境义）→ `lexicon`（通用义，标题标「词义（通用）」）→ 「暂无预置解析」（**仍可收藏**）。
- 空格：`blank` 有行 → 三段式解析；无行 → 只显示编号与词库选项。

### 6.5 笔记规则（M7）
- 句笔记挂 `sentence_id`（1:1），词笔记挂 `token_id`（1:1）。
- 停止输入 **800ms** 自动保存；保存中显示轻提示；失败保留草稿并在下次输入重试；**不得静默丢内容**。
- 笔记为空字符串视为删除（行删除而非留空行）。

### 6.6 生词与复习规则（M8/M9）
- 收藏按 `normalized` 聚合（同词不同句只一条），带首次来源句/文章；来源文章删除时 `SET NULL`（生词保留）。
- 掌握状态：`new` / `fuzzy` / `known`（手动切换，不做自动判定）。
- 复习：文章**首次标记完成**时建 `review_plan`，`next_review_at = 今天 + 1 天`，`interval_index=0`。
- 完成一次复习：`interval_index+1`（0→1→2→3），下次间隔取 `[1,3,7,14][index]`；`index=3` 完成后 `status='done'`（不再提醒，可在文章库手动重启）。
- 「今日待复习」＝ `review_plan.status='active' AND next_review_at <= 今天`。

### 6.7 判分与题目的视觉约束（沿用 ADR-012 + 04 v1.1 §5.6）
选项**不可点选**、不显示对错、不做计分；「显示答案」只显示答案字母与对应选项；不得使用「正确/错误」语义色（避免暗示已判分）。

### 6.8 启动与数据异常（M0/M1）
| 场景 | 行为 |
|---|---|
| 内容包缺失/损坏 | 错误页：显示缺失/损坏文件名 + 「请重新安装」；**不进入空壳目录** |
| 数据库损坏 | 备份 `judou.db.bak-YYYYMMDD-HHmm` → 重建空库 → 重新导入内置内容 → 首页提示「数据库已重建，原库已备份」 |
| 导入用户文章失败 | 保留预览状态与用户编辑（标题/剔除段），显示错误码含义与修法 |
| 无网络（更新检查失败） | 静默降级，不阻塞任何功能 |

### 6.9 权限与合规
- 无账号体系；不做任何上传。
- 用户导入内容属用户自有，导出/备份仅在本机；不提供分享到社区/网络的入口。
- 内置真题的版权风险沿用 docs R01（演示性质、不声称授权），随安装包提供免责声明。

### 7.2 相对 docs C2 的三处修订
1. **`article` 增 `exam_type TEXT NOT NULL DEFAULT 'other' CHECK IN ('cet4','cet6','other')`** + 索引 `(exam_type, exam_year, section_type)`。理由：docs 只有 `exam_year`/`exam_set`/`section_type`，无法区分四级/六级——而用户明确要覆盖六级。
2. **`schema_meta` 合并 `app_meta`**：`pack_version` 作为 `schema_meta` 的一个 `key` 行，避免两张元信息表并存。
3. **`question` 与 `blank` 的职责划分**：`question` 承载题干/选项/答案（所有题型）；`blank` 只承载选词填空的**逐空解析**（reason + distractors）。不用 `question.explanation` 兼做空解析（30 空需要结构化排除项）。

### 7.3 相对 docs C2 的三处新增（我方资产落点）
- `sentence_analysis`：`translation_literal` / `translation_natural` / `struct_markup` / `structure_summary` / `paragraph_role` + `components_json` / `clauses_json` / `phrases_json` / `pitfalls_json`。
- `token_analysis`：`phonetic` / `pos` / `sense_in_context` / `collocations_json` / `examples_json` / `is_cet4_high_freq` / `more_json`。
- `lexicon`：`normalized` PK / `word` / `phonetic` / `pos` / `sense` / `lemma` / `collocations_json` / `examples_json` / `is_cet_high_freq` / `more_json`。

### 7.4 关系与级联（沿用 docs C2 §3.3）
`article → paragraph → sentence → token`（CASCADE）；`article → question`（CASCADE）；`sentence → sentence_analysis`（CASCADE）；`token → token_analysis`（CASCADE）；`sentence → sentence_note` / `token → word_note`（CASCADE）；`article → review_plan/review_log/reading_record`（CASCADE）；`vocab_entry.source_*` → **SET NULL**（生词保留）；`lexicon` 独立（不挂外键）。

### 7.5 偏移口径
统一 **UTF-16 code unit**（ADR-008）；`sentence.start_offset/end_offset` 相对段落，`token.start_offset/end_offset` 相对句子。现内容包已按此口径且 6699/6699 校验通过。

## 十、接口、集成、性能、安全与部署约束

### 10.1 后端命令（宿主 docs C3，此处只列**增量**）
docs C3 已定义 20+ 命令（`list_articles`/`get_article`/`get_article_content`/`commit_import`/`get_sentence_note`/`add_vocab_from_token`/`list_vocab`/`list_tags`/`get_due_reviews`/`complete_review`/`get_reading_records`/`get_stats`/`get_settings`/`export_vocab_html`/`check_update`/`delete_user_article` 等）。本方案新增：

| 命令 | 入参 | 返回 | 用途 |
|---|---|---|---|
| `get_sentence_analysis` | `sentenceId` | `SentenceAnalysis?` | 六段式解析 |
| `get_token_analysis` | `tokenId` | `TokenAnalysis?` | 词级语境解析 |
| `lookup_lexicon` | `normalized` | `LexiconEntry?` | 词库通用义（降级链路第二档） |
| `get_blank_analysis` | `articleId, blankNo` | `BlankAnalysis?` | 空格解析 |
| `list_article_filter_options` | — | `{examTypes[], years[], sectionTypes[]}` | 文章库筛选器选项 |

错误结构沿用 docs C3：`{ code, message }`；新增错误码 `ANALYSIS_NOT_FOUND`（可选，或按「返回 null」处理，取后者更简）。

### 10.2 前端约束（D1 §7-8 沿用）
- 唯一后端入口 `src/lib/api.ts`；React 组件不得直接 `invoke`。
- 状态分层：服务端数据（Tauri 查询结果）/ 页面状态 / 组件局部状态；不做全局 store 泛滥。
- 笔记自动保存防抖 800ms；卸载页面时 flush。

### 10.3 性能
- 冷启动到文章库可用 < 3s；首屏内容导入 < 2s（12 篇 3.36MB，单事务）。
- 点句 → 解析卡可见 < 300ms；点词 → 词卡 < 200ms（索引：`sentence_analysis(sentence_id)`、`token_analysis(token_id)`、`lexicon(normalized)` 主键）。
- 精读页渲染：一次只渲染当前文章（274 句上限），长文（58 句）不得卡顿。

### 10.4 安全与合规
- 无网络、无上传；`content-pack` 路径经 Tauri resource resolver 解析（不拼绝对路径）。
- 用户导入的 `manifest.file`（若来自文件）需做路径限域（评审 M1 债务，本期处理）。
- 错误信息不回显绝对路径（评审 M2 债务，改 basename）。

### 10.5 部署
- Windows：NSIS 安装包（msi 需 WiX，可选）；签名待定。
- Android：APK，需补 Android SDK/NDK 与签名密钥。
- 更新：docs C5 updater + GitHub Releases；不静默更新（Android，ADR-016）。

## 十三、内容与词库规格（沿用 v1.1 §13，此处为索引）

细则见 `04_产品设计方案-v1.1.md` §13，v2.0 不变：

- **13.5 可复算内容校验**：merge/check/audit/lexicon/smoke 五道守卫，全部 exit 0 才算内容合格。

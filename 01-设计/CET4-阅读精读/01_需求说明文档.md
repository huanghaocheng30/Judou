# 01 · 需求说明文档（CET4-阅读精读）

> 编制日期：2026-11-05　阶段：需求沟通中　负责方：调度员 ⇄ 用户

## 一、需求原文

> 我想要做一个面向考英语4级的产品，具体是这样，我打算用这个产品通过阅读背单词，用户能够在程序中看见一篇有一篇的英语4级阅读原文，要求有原文加题目，为的就是让学4级的同学们能够在练习完一篇阅读之后可以进行复盘、精读。默认情况就是原文，但是点击每一个句子就会按照句子进行解析，单词不会就单点单词给出讲解，句子中涉及哪些语法也会详细给出，涉及哪些短语、固定搭配啥的也都会给出，要求适配手机端和电脑端，我最想做移动端因为方便。我已经和其他AI聊出来了一个大致的版本，你阅读一下E:\Judou\docs这个目录下的md文档，选择你需要的文档进行阅读，因为上下文有限制

后续对话追加的原话（按时间序）：

1. **解析来源**：「预生成解析包这个方案挺好的，但是因为是一次性的，每篇新的文章都要重新跑一边，单词在外面的意思和在具体的句子中的意思也不一样，就先选择预生成解析包这个方案吧」
2. **交付形态**：「电脑版和桌面版都是用安装包的形式进行离线安装，本地存储，你可以查看E:\Judou\docs中的相关文档，里面已经记录过了大致的方案」
3. **素材交付**：「放目录吧，帮我创建目录，我等下放进去」
4. **首版范围**：「解析为主 + 轻量笔记 + 生词本」

## 二、业务背景与目标

**要解决的问题**：四级备考者做完一篇阅读后，想真正把文章吃透（生词、长难句、固定搭配），但工具是散的——查词要跳词典、拆句子要另外问 AI、读完就过、复盘没有结构。

**产品目标**：把「做完一篇 → 逐句精读复盘」做成一个开箱即用的本地工具：打开就有真题原文和题目，点句子出整句解析，点单词出**该词在本句中的意思**，离线可用，数据留在本机。

**与既有替代方案的差异**：

| 替代方案 | 不足 | 本产品差异 |
|---|---|---|
| 手机词典 / 翻译 App | 给的是词典义，不是本句语境义；来回切 App 打断阅读 | 语境义预置在句子/token 上，点一下即在原文上下文出现 |
| 通用 AI 对话（问长难句） | 每句都要贴文本、等生成、质量波动，离线不可用 | 解析预生成，零等待、零网络 |
| 纸质真题 + 手写笔记 | 笔记分散、生词不可检索、复盘难组织 | 结构化到句/词粒度，生词本按文章聚合 |
| 背单词 App | 脱离语境，背了不会用 | 以阅读语境驱动词汇记忆 |

## 三、目标用户、角色与权限

- **核心用户**：备考英语四级的大学生，阅读是薄弱项，愿意花时间精读复盘，主要在手机上使用。
- **次要用户**：备考六级/考研的同类需求者（数据结构通用，可后续扩内容）。
- **角色与权限**：单一本地用户，无账号体系、无多角色权限。数据仅存本机。
- **非目标用户**：只想刷题看分数的、要社交排行榜的、要多设备同步的。

## 四、核心场景与现状流程

**场景 A · 精读复盘（主场景）**
打开一篇文章 → 先看题目（答案默认折叠）→ 通读原文 → 点某个看不懂的句子 → 看该句的句译、语法结构拆解、所含短语与固定搭配 → 点句中不认识的单词 → 看该词在本句中的释义、音标、词性、搭配、例句 → 收藏进生词本 → 可选写一句自己的笔记。

**场景 B · 生词回顾**
打开生词本 → 按文章分组查看收藏过的词 → 点回该词出现的原句，在语境里再确认一次。

**场景 C · 无网环境使用**
通勤/宿舍断网时打开应用，全部解析与笔记照常可用（离线内容包 + 本地库）。

**现状流程与卡点**：现在用户通常在手机浏览器或 PDF 上看真题，遇词切词典、遇难句另开 AI，读完不做结构化复盘；卡点在工具切换成本高、语境义缺失、复盘无结构。

## 五、痛点与期望结果

| # | 痛点（用户视角） | 期望结果 |
|---|---|---|
| 1 | 读一篇文章要切三四次 App（词典/翻译/AI） | 点一下就在原文里出解析，不离开当前页 |
| 2 | 词典给的是通用义，放在这句里意思不对 | 单词讲解绑定「本句语境义」，同词不同句可不同解 |
| 3 | 长难句看不懂结构，不知道哪是主句哪是从句 | 句子级语法拆解：主干、从句、修饰关系 |
| 4 | 固定搭配/短语看不出来，逐词翻译读不通 | 句中短语与固定搭配单独列出并给中文 |
| 5 | 读完就忘，没有复盘抓手 | 生词本按文章聚合，可点回原句语境 |
| 6 | 没网/流量紧张时用不了在线工具 | 全离线：内容包 + 本地数据库 |

## 七、约束

| 类别 | 约束 |
|---|---|
| 形态 | Tauri v2：Windows 桌面安装包（首版）+ Android APK（待桌面跑通后补）；不提供在线 Web 服务 |
| 数据 | 全部本地：SQLite 单文件；无账号、无云同步、不上传任何用户数据 |
| 解析数据 | **预生成内容包**，随安装包分发；运行时零联网、零模型调用 |
| 解析粒度 | 句译/语法挂句子层；词义挂 token 层且**绑定所在句子**（同一词在不同句可有不同释义） |
| 内容 | 素材由用户提供四级真题原文；AI 离线生成解析后抽检；版权风险由用户承担（docs 已记 R01） |
| 技术栈 | React + TypeScript + Vite + Tauri v2 + Rust + rusqlite（手写 SQL，不用 ORM） |
| 偏移口径 | 文本偏移统一 UTF-16 code unit（前端字符串索引天然一致） |
| 执行环境 | Windows 11 build 22621；Node 24.21.0；Rust 1.99.1 已装；MSVC C++ Build Tools（安装中）；无 Android SDK/NDK |
| 合规 | 不做公开 UGC、不做分享；内容与免责声明随安装包提供 |

## 八、成功指标

1. 用户从打开一篇文章到看见第一句解析，**点击次数 ≤ 2**。
2. 解析面板打开到内容可见 **< 300ms**（本地数据，无网络等待）。
3. 每篇内置文章的**句子级解析覆盖率 100%**（每句都有句译 + 语法说明），重点词有语境释义。
4. Windows 安装包体积 **< 30MB**。
5. 冷启动到文章库可用 **< 3s**（参考 docs C1 非功能指标）。
6. 笔记与生词在重启应用后**不丢失**。

## 九、明确不做范围

- 做题作答与判分（只展示题目与答案，选项不可点选）——沿用 docs ADR-012
- 运行时调用大模型生成解析（本轮裁决：预生成）
- 篇级复习提醒、导出打印、用户自助导入（首版不做，二期）
- 账号体系、云同步、多设备、社交分享、排行榜、支付
- 微信小程序路线（ADR-001）、Electron（ADR-004）、ORM/连接池（ADR-007）
- 在线 Web 服务与任何服务端依赖（ADR-002）

## 十、已确认事实 / 暂定假设 / 待确认问题

**已确认事实（用户明确裁决）**

1. 解析生产方式＝**预生成解析包**，按「句子内语境义」落库，不查全局词典。
2. 交付形态＝**安装包离线 + 本地存储**（Tauri v2 路线，沿用 docs）。
3. 素材＝**用户提供真题原文**，投放至 `01-设计/CET4-阅读精读/素材原文/`。
4. 首版范围＝**解析为主 + 轻量笔记 + 生词本**（不含复习提醒与导出）。

**暂定假设（不改变方向，可继续推进）**

1. 首版只交付 Windows 桌面安装包；Android 在桌面跑通后补。
2. 内容结构＝文章（标题/年份/题型）+ 段落 + 题目（选项/答案）+ 句子（句译/语法/短语）+ token（语境义/音标/词性/搭配）。
3. 解析生成由调度员在本机用脚本批量生成，抽检后入库。

**待确认问题（设计决策清点输入）**

- Q1 解析的展示形态：底部抽屉 / 内联展开 / 桌面侧栏？（三端差异如何统一）
- Q2 点词时是否高亮所在句、点句时是否灰显其他句？
- Q3 解析内容的具体生成与抽检流程（谁跑、抽检比例、错了怎么改）。
- Q4 生词本要不要最小「回看」形态（无复习提醒时如何促使用户再看）。
- Q5 产品名称（Judou / 追豆 / 其他）。
- Q6 题目是否允许用户点选（可点不判分 vs 完全不可点）。
- Q7 首批文章数量：先 2—3 篇样板验证 vs 直接铺 24 篇。

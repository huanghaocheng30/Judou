# 01 · 需求分析（TP1-应用骨架与内容导入）

> 上游：04 v1.1 §四（MVP 范围）、§7.1（目录卡片字段）、§8（启动异常）、§9.1（命令最小集）、§13.1（内容包结构）、05 v1.1 §二/§三（M1、M2）、06 v1.1 §五（七条开发必须实现的规则）
> 定位：首包。往后四个包都建立在本包产出的工程骨架与本地库之上。
> 修订：v1.1（计划审核第 1 轮驳回 B1~B6 + 建议 S1~S10 后修订；用户裁决 AC1 字段与占位标题处置）

## 一、为什么先做这一包

内容侧已 100% 完成（12 篇 / 90 段 / 274 句 / 6699 token / 213 张词级解析卡 / 30 个空 / 1561 词库），缺的是**能把它跑起来的壳**。首包要回答一个最小问题：**这款应用能不能启动、能不能把 12 篇内容装进本地库、能不能把正文正确显示出来**。

只有这一层通了，后面的句卡、词卡、题目、笔记才有落点。因此本包的范围刻意压到「骨架 + 导入 + 列表 + 正文」，交互一律留占位。

## 二、用户可感知的交付

打开应用 → 看到三套 12 篇的目录（**每篇显示：篇名 / 年份 / 题型 / 词数 / 句数**）→ 点进去能读到该篇全文，段落与句子顺序正确 → **页头 `‹` 能退回目录**。

此时点词、点「析」、点空格**还没有反应**——这是预期，后续三包分别接管。

## 三、范围边界

**做**：
- Tauri v2 工程骨架（可 `dev` 可 `build`）
- 12 篇内容包落位与 manifest 生成
- 导入命令（事务、幂等、不覆盖用户数据）
- 总目录页（三套分组，五项字段）
- 阅读页正文渲染（含可点节点属性，但不接交互）
- **返回导航**：阅读页页头 `‹` 接路由历史（06 §五#4）
- **键盘可达最小实现**：篇目卡与「析」占位按钮可 Tab 聚焦、焦点可见、不靠颜色单独传意（06 §五#6）
- **启动异常最小处理**：内容包缺失/损坏时给出可见提示，不进入空壳应用（04 §八①）；数据库损坏时备份为 `app.db.bak-日期` 并重建空库（04 §八②）

**不做**（明示延后，防「沉默遗漏」）：
- 句卡（TP2）、词卡与词库（TP3）、题目与空格解析（TP4）、笔记/生词本/位置恢复（TP5）
- 目录卡片的「已收藏生词数」字段——TP3 起才有数据
- 视觉打磨（沿用原型色调即可，不做像素级复刻）
- 内容包异常的全量修复流程（本包只做「提示 + 不崩」；内容包本身开发期只读）

## 四、关键约束

1. 导入**不得覆盖**用户数据（本包还没有用户数据，但表结构与 upsert 规则要一次做对）。**物理分表铁律**（04 §三）：本包只建内容表，`note` / `vocab` / `progress` 三表本包**不建**（表不存在即证）。
2. 渲染层节点属性（`data-n` / `data-start` / `data-blank-no`）**必须**输出，否则后续包要返工。
3. 中文内容与中文路径：`content-pack/` 用 ASCII 文件名，内容 JSON 内部是 UTF-8 中文。
4. **运行期不联网**；构建期需联网拉 npm / crate 依赖（两者必须区分，不混淆）。
5. 键盘可达 + 颜色不是唯一信息通道（06 §五#6）。
6. 渲染出的数组/字符串两种形态都要能处理（06 §五#2 的适用范围在本包体现为 `blanks.distractors`：set1/set2 为字符串、set3 为字符串数组）。

## 五、验收摘要

**8 条**验收标准见 `02_开发方案与任务包.md` 第一节；其中 AC1（目录 12 篇 + 五项字段）、AC4（正文逐字一致）、AC7（可打包）是本包能否叫「完成」的硬门槛，AC8（进入/返回）是本包可用性的底线。

## 六、内容债与已知限制（用户已裁决）

- **篇名**：set2/set3 共 8 篇原为占位标题（「第2套 · 仔细阅读 A」），已按正文主旨补为英文篇名，并重建 12 页原型（见 `03-开发协同` 决策记录 2026-11-05）。内容包 `meta.title` 为唯一标题来源。
- **篇内 `packVersion`**：12 篇 JSON 内 `packVersion = "2023-12-set1-v0.9"` 为生产批次残留，**不是版本权威**；版本权威唯一为 manifest 的 `packVersion`。此项不入库，属已知内容痕迹，不改内容包。

## 一、需求摘要与验收标准

**目标**：交付一个可启动的 Tauri v2 桌面应用：能把 12 篇内容包导入本地库，展示三套 12 篇的篇目列表，点进任意一篇能看到**渲染正确的正文**（可点词、可点空的节点存在，但交互留待 TP2/TP3）。

**本包不做**：句卡（TP2）、词卡与词库查询（TP3）、题目与空格解析（TP4）、笔记/生词本/位置恢复（TP5）。

| 编号 | 验收标准（可测） |
|---|---|
| AC1 | 应用可启动，首屏显示总目录：三套分组、12 个篇目入口，每条显示篇名/题型/句数（数字与 `内容包/*.json` 一致：20/15/42/9/15/17/39/10/19/21/58/9） |
| AC2 | 首次启动完成内容导入：本地库出现 12 篇 article 记录，`app_meta.packVersion` 等于 manifest 中的值 |
| AC3 | 再次启动（版本未变）不重复导入；导入耗时 < 2s（12 篇合计约 3.4 MB） |
| AC4 | 点任意篇目进入阅读页，正文段落与句子顺序与内容包一致（抽查第 3 套长篇第 6 段 3 句，文本逐字相符） |
| AC5 | 正文中单词节点带 `data-n`（normalized）与 `data-start`，空格节点带编号——供后续包接管交互 |
| AC6 | 删除本地库后重启可完整重建（导入幂等） |
| AC7 | 构建产物可生成安装包（`pnpm tauri build` 成功，产出 `.msi` 或 `.exe`），体积 < 30 MB |

## 三、具体改动点（逐条可执行）

### D1 · 工程骨架（对应 AC1 / AC7）
- 用 `pnpm create tauri-app` 或手写最小 Tauri v2 工程；`tauri.conf.json` 设 `productName: "CET4 精读"`、窗口 1200×800、`identifier: com.judou.cet4`。
- 前端栈：Vite + TypeScript + 原生 DOM（**不引入 React/Vue**，与原型实现一致，见 04 §9）。
- **消费接口**：无（自包含）。

### D2 · 内容包落位与 manifest（对应 AC2 / D3 输入）
- 把 12 个 `cet4-2023-12-*.json` 拷入 `content-pack/`；用脚本生成 `manifest.json`：`{ packVersion: "2023-12-v1", articles: [{ sourceKey, file, contentHash(sha256), sentenceCount }] }`。
- **产出接口**：`manifest.json` 供 D3 消费。

### D3 · 导入命令（Rust 侧）（对应 AC2 / AC3 / AC6）
- 命令 `import_content(packDir) -> ImportReport`：读 manifest → 逐篇 upsert 进 SQLite（`article`/`sentence`/`token`/`question`/`blank` 表）→ 写 `app_meta.packVersion`。
- **规则**：整批一个事务；`sourceKey` 已存在则只更新内容字段；失败回滚。
- **消费接口**：D2 的 manifest；**产出接口**：本地库表结构供 D4/TP2 读取。

### D4 · 总目录页（对应 AC1）
- 三套分组卡片列表；数据来自 `list_articles()` 命令（读本地库）。
- **消费接口**：D3 建立的 article 表。

### D5 · 阅读页骨架与正文渲染（对应 AC4 / AC5）
- 按 `paragraphs[]` 渲染段落与句子；token 按 `start` 偏移切成「文本/单词/空格」节点。
- 单词节点输出 `data-n`、`data-start`；空格节点输出 `data-blank-no`；句末输出「析」占位按钮（本包不接交互）。
- **消费接口**：D3 的 token 表；**产出接口**：节点属性给 TP2/TP3/TP4 接管。

## 四、自测要求

开发员必须附**真实命令 + 输出片段**：
1. `pnpm tauri dev` 启动成功截图/日志（窗口标题、首屏 12 条）
2. 导入报告：`import_content` 返回的 `{ imported: 12, updated: 0, packVersion }` 实际输出
3. 幂等验证：第二次导入返回 `{ imported: 0, updated: 12 }`（或 `skipped: 12`，按实现）
4. 数据库核对：`SELECT COUNT(*) FROM article` → 12；`SELECT COUNT(*) FROM sentence` → 274
5. 正文抽查：第 3 套长篇第 6 段 3 句与内容包逐字比对（贴 diff 或断言输出）
6. `pnpm tauri build` 成功日志尾部 + 产物体积
7. `git status --porcelain` 范围核查（只应有 `02-代码/` 内改动）

## 五、风险点与影响范围预估

| 风险 | 影响 | 缓解 |
|---|---|---|
| Tauri v2 首次构建拉依赖慢 | 构建 10+ 分钟 | 预算已计入；构建失败先看 `cl.exe` 是否在 vcvars 环境（本机已实测可编译） |
| SQLite 驱动选择（rusqlite vs tauri-plugin-sql） | 影响 D3 实现 | 优先 `rusqlite`（同步、事务直观）；如遇跨平台问题改 plugin |
| 12 篇 JSON 约 3.4 MB 一次性入库 | 导入慢 | 单事务批量 insert；必要时用 prepared statement |
| 中文路径 | 构建/读取失败 | `content-pack/` 用 ASCII 名；文件读取走 Tauri 资源 API |

## 三、关键契约（补充设计件未写死的实现口径）

1. **`UserInputSplit`**：`{ bodyText: String, questionText: String, questionStartLine: Option<usize>, detected: bool, reason: String }`。`detected=false` 时 `questionText` 为空串（**不猜**）。
2. **切分规则**（04 §6.2.1 的可执行版）：逐行扫描；命中 `^\s*\d{1,3}\s*[.、．)]\s*\S` 或题型标题行 → 候选；取最靠前候选 `L`；若 `L` 之后 **5 个有效题行**内同类题号行 ≥2 → `detected=true`、`questionStartLine=L`；否则继续找下一候选；全不中 → `detected=false`。
   **v1.3 修订（已被 v1.4 取代）**：原口径是「其后 5 **行**」，对「题干 1 行 + 4 个分行选项」的真实卷面必然判失败（4 个选项行就把窗口占满，看不到下一个题号行）→ 改为按**非空行**计数，窗口仍为 5。这是识别率修复，不改「不猜」原则。
3. **`mode=plain`**（档 A）：`build_ai_prompt` 返回的提示词**不含** `sentences[]`/`analysis` 字段要求，只含「App 会自己切句分词、你不需要输出任何东西」的说明；`commit_ai_import` 允许 `matched` 为空。
4. **档 C 逐字比对**：把用户题目区按行解析成 `(no, stemLines, options, answerLine)`（宽松：行首题号 → 题干至首个选项行；选项行 `^[A-D][.、)]`；答案行匹配 `answer`/`答案`/单字母行）；`payload.questions[i]` 的 `stem` 与 `options[].text` 必须与解析结果**去空白后逐字相同**，否则 `AI_QUESTION_MISMATCH`。
5. **`answer_source` 判定**：用户题目区该题有答案 → 若 `payload.answer` 与之相同 → `user`；不同 → 拒收（`AI_QUESTION_MISMATCH`，`path="questions[i].answer"`）；用户没给答案而 `payload.answer` 有 → `ai`；都没有 → `none`。
6. **零 schema 铁则修订**：本轮**允许 1 列**（`question.answer_source`），通过 002 迁移；**表数仍 19**，不得新增表。

## 七、M5c 优化轮（v1.1，2026-11-07 晚）

> 用户实测反馈：「点击解析并匹配完全没效果」。**根因**（截图 + 日志已确认）：他选「仔细阅读」，但粘的是**长篇阅读卷面**（43~45 题、答案为段落字母 L/B/G）→ 形态校验按设计拒收 `AI_TYPE_MISMATCH path=questions[0].options`。**不是没跑，是拒收了，但界面把拒绝表现为「没反应」，且不告诉用户怎么改。**
> 本轮不做题型自动猜（设计不允许），只做**「拒收后给可执行的下一步」**。

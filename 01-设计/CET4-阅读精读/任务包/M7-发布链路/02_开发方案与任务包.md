## 一、验收标准（AC1~AC8）

| 编号 | 判据 | 证据 |
|---|---|---|
| **AC1** | **版本三处一致**：`src-tauri/tauri.conf.json` 的 `version` = `package.json` 的 `version` = `src-tauri/Cargo.toml` 的 `[package].version`；新增门禁 `verify:release` 断言并 EXIT=0 | 门禁 |
| **AC2** | `check_update` 命令：读远端 `latest.json`（URL 从配置读，默认 GitHub Releases），有新版返回 `{available:true, version, notes, url}`，无新版 `available:false`；**网络失败/超时（≤5s）静默降级**为 `available:false` 且不报错、不阻塞启动 | 门禁（本地 http 桩）+ 单测 |
| **AC3** | `latest.json` 生成脚本 `scripts/make-update-manifest.mjs`：从 `tauri.conf.json` 取版本、从打包产物目录取签名/文件名，产出符合 updater 格式的 `latest.json`（含 `version` / `pub_date` / `platforms` / `signature` / `url`）；无签名时给出明确提示而非静默产出空签名 | 门禁 |
| **AC4** | CI 工作流 `.github/workflows/ci.yml`：`cargo check` + `cargo test` + `npm run build` + 全部 `verify:*` 门禁；矩阵含 `windows-latest` / `ubuntu-latest`；**不含密钥**（无 `secrets` 明文，签名密钥只引用 `secrets.*` 名） | 门禁（YAML 解析断言） |
| **AC5** | 发布工作流 `.github/workflows/release.yml`：`workflow_dispatch` + tag 触发；`tauri-action` 产出 Windows NSIS + 上传 Release；**私钥不入库**（`.gitignore` 含 `*.key`、`*.pem`、`tauri-signing*`） | 门禁（YAML 解析 + .gitignore 断言） |
| **AC6** | 本地打包脚本 `scripts/build-installer.ps1`：一条命令跑 `tauri build --bundles nsis`，成功后打印产物路径与大小；**脚本本身不被 CI 自动执行**（人工运行） | 门禁（脚本存在 + 语法检查） |
| **AC7** | 设置页「关于」增加「检查更新」按钮（`data-check-update`）：点击调 `check_update`；有新版显示版本号 + 链接；无新版显示「已是最新」；失败显示「检查失败，稍后再试」（不弹技术错误） | CDP |
| **AC8** | 回归：`cargo test --lib --bins`、`npm run build`、`verify:release`（新）、`verify:invoke`、`verify:records` 全 EXIT=0 | 门禁 |

## 三、关键契约

1. **HTTP 实现**：先查 `src-tauri/Cargo.toml` 是否已有网络依赖（`reqwest`/`ureq`/`tauri-plugin-http`）。
   - **有** → 直接用，加 5s 超时。
   - **无** → **不新增网络依赖**，改为：`check_update` 只做「**本地清单检查**」——读环境变量/配置里的 manifest 本地路径或跳过网络（返回 `available:false, reason:"offline"`），并在 README 写明「联网检查归 M7 后续」。**理由：为一个可选功能引入 HTTP 栈（含 TLS/证书）会显著增大二进制与供应链面，本包不值当**。
2. **`latest.json` 格式**（对齐 Tauri updater v2）：`{"version":"0.2.0","pub_date":"2026-11-08T00:00:00Z","platforms":{"windows-x86_64":{"signature":"...","url":"..."}}}`。
3. **私钥与密钥不入库**：`.gitignore` 加 `*.key` / `*.pem` / `tauri-signing*` / `latest.json` 的签名私钥路径；CI 只引用 `secrets.TAURI_SIGNING_PRIVATE_KEY` 等名称。
4. **降级优先**：任何更新检查失败都不得阻塞启动、不得弹技术错误；只影响设置页该按钮文案。

## 四、自测要求

1. 红→绿 ≥2：AC1（改前无 `verify:release`）、AC2（改前无 `check_update`）。
2. CDP：AC7 三态（有新版模拟 / 无新版 / 失败）——若无法造新版，至少验「无新版」与「失败」两态。
3. 门禁：`cargo test`、`npm run build`、`verify:release`、`verify:invoke`、`verify:records` 全 EXIT=0。
4. **禁止**：`tauri build` 真打包、真发布 Release、APK 构建、装 SDK/NDK。

**三问裁定**
1. 改动形态：Rust 1 模块（1 纯函数 + 1 检查 + 4 单测）+ 1 薄命令 + 前端 2 文件 + 门禁 1 脚本 + 4 个配置文件；约 9 文件。
2. 最便宜验证：YAML/JSON 静态断言 + 单测（秒级）；CDP 一次。
3. 禁止项：见上 §四.4 + 新增网络依赖（见 §三.1）。

> 交接块：**任务编号 M9｜档位 小包｜预算 C≤4 / B≤6 / 工作轮≤24｜设计基线 `DB-20261107-6`**
> 设计引用：`04 §二`（响应式断点：`≥1100px` 侧边栏+右解析栏 / `640~1100px` 侧边栏+底部抽屉 / `<640px` 底部 Tab+底部抽屉）、`04 §8` 响应式断点段
> 目标代码区：`02-代码/`（逻辑路径；物理在 `code/`）

---

## 一、验收标准（AC1~AC5）

| 编号 | 判据 |
|---|---|
| **AC1** | `<640px` 时侧边栏变为**底部固定 Tab 栏**：`.sidebar` 固定 `bottom:0`、横向排列、7 个导航项均分宽度（图标在上、文字 10~11px 在下）；**品牌区与版本号隐藏**；主内容区加 `padding-bottom` 避免被遮挡 |
| **AC2** | 五个宽度无横向溢出（`document.documentElement.scrollWidth <= innerWidth + 1`）：**320 / 375 / 640 / 1100 / 1920**（375 为主目标） |
| **AC3** | `640~1099px`：侧边栏保留但**收窄为图标栏**（宽度 ≤72px，隐藏文字标签、hover/聚焦显示 title）；主内容正常 |
| **AC4** | 精读页在 375px 下：右侧解析栏退化为**底部抽屉**（复用既有 `AnalysisPanel`，不改其逻辑），点句能弹出、Esc 能关 |
| **AC5** | 回归：`npm run build` / `verify:records` / `verify:invoke` 全 EXIT=0；桌面 1920 布局**与改动前一致**（截图对比无位移） |

## 二、改动点（D0~D2）

| # | 文件 | 说明 |
|---|---|---|
| **D0** | `src/styles/app.css` | 追加 `@media (max-width: 639px)` 底部 Tab 段 + `@media (min-width: 640px) and (max-width: 1099px)` 图标栏段。**只加不改既有规则**（既有 720/1100/1440 断点不动） |
| **D1** | `src/shell/Sidebar.tsx` | 必要时给导航项加 `data-nav-item` / `aria-label` 与图标容器 class（不改导航逻辑与顺序） |
| **D2** | 各页面的窄屏适配（按需最小改动） | 只修**确实溢出**的地方（如表格/网格 `min-width`），不重排布局 |

**不做**：不新增导航项/路由；不改 `AnalysisPanel` 的断点与抽屉逻辑；不引 UI 框架；不做「更多」二次抽屉（7 项直接均分）。

---

## 三、自测要求

1. **CDP 五宽度截图**（320 / 375 / 640 / 1100 / 1920），每档记录 `scrollWidth` 与 `innerWidth`（AC2 的可复算证据）
2. 375px 下精读页：点句 → 抽屉弹出（截「弹出前/后」两张）；Esc 关闭
3. 回归：`npm run build` / `verify:records` / `verify:invoke`
4. **桌面 1920 截图与改动前对比**（证明没破坏既有布局）

**三问裁定**
1. 改动形态：CSS 为主（1 文件追加约 80~120 行）+ 少量 tsx class 挂载；零 Rust、零新依赖、零 schema
2. 最便宜验证：`npm run build`（秒级）→ CDP 五宽度读数（约 5 分钟）
3. 禁止项：不引 UI/图标库、不改 `AnalysisPanel` 断点、不动既有 media query、不改导航顺序

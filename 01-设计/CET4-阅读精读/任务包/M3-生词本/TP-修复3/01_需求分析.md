> 上游指针：用户 2026-11-06 复测截图反馈（M3 待人工测试阶段）｜父包 `M3-生词本`｜父候选 **`38a55a7`**

> **未决澄清项：无**

## 一、问题与定性

用户原话：

> 「**不要居中排版，改回去**，每篇具体的文章页现在已经差不多了，**这就不用改了**，还有就是原句的折叠也可以了，改完之后 M3 应该就过了吧」

| issueId | 现象 | 定性 |
|---|---|---|
| **M3-U3** | **列表页**（文章库、生词本等）居中后，内容被挤成中间一条窄带、左右都空（截图红框） | **真缺陷**（TP-修复2 引入的回归：`.content { margin-inline:auto }` 是全局规则，列表页本应左对齐铺开） |

**同时用户明确认可两项**（本包不得触碰）：
- **精读页**（`#/article`）居中 + 右栏形态：「现在已经差不多了，这就不用改了」
- **原句折叠**（TP-修复2 的 F2）：「也可以了」

## 二、根因初判（开发员必读）

`.content` 是**全局**容器（`app.css:195-210`）。TP-修复2 给它加了 `margin-inline: auto` 以修复**精读页**右侧留白，副作用是**所有页面**都被居中——而列表页（文章库的筛选区 + 卡片网格、生词本的分组列表）原本靠左铺开，居中后卡片区被压成窄条（截图实测约 600px），左侧和右侧同时出现空白，比修复前更差。

**结论**：居中只应作用于**精读页**，不应作用于列表页。

## 三、修复后应达到的效果

1. **文章库 / 生词本 / 复习 / 记录 / 导入 / 设置**：内容**回到左对齐**（与 TP-修复2 之前一致），卡片按可用宽度铺开，不再两侧同时空。
2. **精读页**：**保持现状**（居中、正文 66ch、右栏 360px）——一个像素都不要变。
3. 其余一切不变。

## 四、不做的事

- **不碰** `SentenceCard.tsx`（原句折叠已获用户认可）
- **不碰** 精读页的任何布局（`.reader-split` / `.reader-body` 66ch / `.analysis-panel-wide`）
- **不改** 设计基线、`001_init.sql`、六个冻结 `data-*`
- **不重排** 列表页的卡片网格与筛选区结构
- **不引入** 新依赖 / UI 框架

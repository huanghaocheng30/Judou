## 一、为什么这一包

M2 之后，用户能在一篇文章里点句看解析、点词看语境义、写笔记。但**学到的东西会随关闭文章消失**：下次遇到 `provoke`，还得重新点一遍。

M3 让「精读」产生**可积累的资产**：

- 碰到值得记的词 → **词卡上「加入生词本」** → 这个词进生词本（同词不同句**只一条**）
- 生词本里按**文章 / 标签 / 掌握状态**三种轴看自己攒了什么
- 每条能**编辑释义、打标签、改掌握状态**
- 点「回原句」→ 跳回那篇文章的**那一句**，滚动到位置并高亮 2 秒
- 原文章被删除时，生词**保留**（来源标「来源已删除」），不连带丢失用户资产

这也是 M4（复习）的直接输入：复习的对象不是文章，而是「我标记为 fuzzy 的词」。

## 二、用户可感知的交付

1. **词卡出现「加入生词本」**（M2 刻意没放，M3 加）：未收藏 → 可点「加入生词本」；已收藏 → 显示「已在生词本」并可点「移出」。**不放灰色禁用按钮**（M2 已立此规矩）。
2. **生词本页**（`#/vocab`）从占位变成真页面：三种分组轴切换、每轴下分组列表、条目显示 `surface` + 音标/词性 + 语境义 + 掌握状态 + 标签 + 来源文章。
3. **筛选与搜索**：按掌握状态筛（new/fuzzy/known）、按标签筛、按关键词搜（normalized/surface 包含）。
4. **编辑**：语境释义、音标、词性、掌握状态、标签增删（**只做表结构里有的字段**，见 §四）。
5. **点回原句**：条目上「回原句」→ 跳精读页定位该句并高亮 2 秒。
6. **删除**：单条移出生词本；删除标签（连带解除关联，不移除词）。

## 三、做 / 不做

**做**：收藏（normalized 聚合）/ 三轴分组 / 筛选与搜索 / 编辑（5 类字段 + 标签）/ 掌握状态三档 / 点回原句定位高亮 / 删除生词 / 标签增删 / 无障碍底线 / 顺带收 M2 的两条债务（D-M2-11、D-M2-12）。

**不做**：**导出**（归 M6，见 §四 冲突 2）/ 复习计划与复习模式（M4）/ 生词本与文章的双向自动联动（如「本文生词」角标，M6 统计）/ 批量导入导出 / 拼写检查 / 词形还原（只按 `normalized` 精确聚合，不做 lemma）。

## 四、两处文档冲突与本包裁定

> 依据链上 04 与 05 有两处不一致，必须在此钉死，否则开发员会撞到「表里没这列」。

### 冲突 1：05 §九 说编辑「搭配、例句」，但 `vocab_entry` 没有这两列

- 事实（`001_init.sql:161-175`）：`vocab_entry` 列为 `normalized / surface / phonetic / pos / context_meaning / source_sentence_id / source_article_id / mastery / review_count / last_reviewed_at / created_at / updated_at`——**无 `collocation`、无 `example`**。
- 带这两列的是 `word_note`（按 `token_id` 的笔记，M2 已做）。
- **裁定**：M3 的编辑**只支持表结构里有的**：`context_meaning`（语境释义）、`phonetic`（音标）、`pos`（词性）、`mastery`（掌握状态）、标签。**不为「搭配/例句」加列、不硬塞进 `context_meaning`**。理由：`001_init.sql` 冻结（改列要动 001 或加 003 迁移，属 schema 变更、超出 M3 授权），而「搭配/例句」在词维度上本来有 `word_note` 承载，生词本条目上重复一份会造成两处数据不一致。

### 冲突 2：05 §九 输出含「导出入口」，但 04 §五 把导出放在 M6

- 事实：04 §五 M3 行 =「收藏/编辑/标签/掌握状态/点回原句」（无导出）；M6 行 =「…**生词导出**…」；05 §九 输出 =「列表 + 编辑 + 点回原句 + **导出入口**」。
- **裁定**：**M3 不做导出、也不做占位按钮**，归 M6。理由：与 M2「不放收藏按钮」同一原则——放了不work的按钮比不放更糟；且导出要设计 HTML 模板与打印样式，是独立工作量。

## 五、关键约束（不可违反）

1. **只写用户表**：`vocab_entry` / `tag` / `vocab_tag` 是 M3 的写入面；**绝不写**解析四表（`sentence_analysis`/`token_analysis`/`lexicon`/`blank`）、内容表（`article`/`paragraph`/`sentence`/`token`）、复习两表（`review_plan`/`review_log`，归 M4）、`reading_record`（归 M6）。
2. **`001_init.sql` 零改动**（三张表 M0 已建好）。
3. **聚合口径**：`vocab_entry.normalized` UNIQUE → 同词不同句只一条。重复添加**不更新来源**（保留首次来源，`ON CONFLICT DO NOTHING` 语义），符合 04 §6.6「带首次来源句/文章」与 05 §九 规则 1「surface 保留首次加入形态」。
4. **级联**：`source_sentence_id` / `source_article_id` 为 `ON DELETE SET NULL` → 文章删除后生词保留、分组归「来源已删除」（05 §九 规则 5）。
5. **点回原句**定位到 `source_sentence_id`，跳转携带 `articleId + sentenceId`（+ 可选 `tokenId` 用于词级高亮）。
6. **无障碍**：掌握状态三档**颜色不作唯一通道**（必须同时有文字/形状）；标签可键盘增删；列表项可 Tab。
7. **不改 M1/M2 已冻结契约**：六个 `data-*` 属性名（`data-token-id`/`data-n`/`data-start`/`data-blank-no`/`data-sentence-idx`/`data-sentence-id`）、`AnalysisPanel` 的三态选中互斥、`useDebouncedSave` 的 `targetKey` flush 语义。

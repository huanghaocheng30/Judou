## 一、审计结论（2026-11-08 实测）

| 项 | 现状 | 判定 |
|---|---|---|
| Rust 路径 API | 全部走 `app.path().app_data_dir()`（Tauri 跨平台） | ✅ 无硬编码 Windows 路径 |
| `pack.rs` 限域 | `std::path::Component` + `canonicalize` | ✅ 跨平台 |
| **`export.rs:781`** | `.unwrap_or_else(\|\| PathBuf::from("exports"))` | ⚠️ 相对路径在 Android 会落到只读/不可预期目录 |
| **前端导出** | 隐藏 iframe + `contentWindow.print()` | ❌ **Android WebView 不支持，会静默失败** |
| 前端平台判断 | 未使用任何平台检测 | ⚠️ 需要 |

## 二、验收标准（AC1~AC5）

| 编号 | 判据 |
|---|---|
| **AC1** | 前端能判断运行平台（**零新依赖**：用 `navigator.userAgent` 匹配 `/Android/i`，封成 `lib/platform.ts` 的 `isAndroid()`），并导出给需要的地方用 |
| **AC2** | **Android 上导出按钮降级**：设置页「导出 PDF 词表」在 Android 显示为**禁用态 + 说明**（`data-export-android-blocked`），文案「Android 版暂不支持导出 PDF，请用桌面版」。**不得**让人点了没反应 |
| **AC3** | `export.rs` 的 `exports` 兜底改为 `app_data_dir/exports`（拿不到 `app_data_dir` 时才回退 `"exports"`）；新增/改单测覆盖 |
| **AC4** | 检查并记录**其它桌面专有调用**（窗口尺寸/托盘/文件选择器）在 Android 的可达性——只需在自测 concerns 里列出清单与风险等级，**不做改造**（归后续包） |
| **AC5** | 回归：`npm run build` / `verify:records` / `verify:invoke` / `verify:release` 全 EXIT=0；`cargo test` 保持全过（当前 124 passed + 本轮新增） |

## 三、改动点（D0~D2）

| # | 文件 | 说明 |
|---|---|---|
| **D0** | `src/lib/platform.ts`（新增） | `isAndroid()` / `platformName()`（零依赖，UA 判断；SSR/无 window 时安全返回 false） |
| **D1** | `src/pages/Settings.tsx` | 导出按钮在 Android 上禁用 + 说明（`data-export-android-blocked`）；桌面路径逻辑不动 |
| **D2** | `src-tauri/src/export.rs` | `exports` 兜底改 `app_data_dir/exports`；单测覆盖 |

**不做**：不做 Android 分享 Intent（归后续包）；不改 iframe 打印实现（桌面继续用）；不改路径 API（已跨平台）。

## 四、自测要求

1. **红→绿 ≥1**：改前 `isAndroid` 不存在 / 改前 Android 上点导出无任何提示
2. 门禁四条 EXIT=0；`cargo test` 全过
3. CDP：**桌面**下导出按钮仍可用（不误伤）；Android 分支用 UA 覆写（`Browser.setUserAgent`）模拟验证禁用态 —— 若 CDP 不便，至少给 UA 匹配的单测/脚本证据
4. 自测 concerns 里列 AC4 的桌面专有调用清单

**三问裁定**：① 3 文件（1 新 + 2 改），零新依赖、零 schema；② 最便宜验证 = `npm run build` + `cargo test`（秒级）+ CDP 一次；③ 禁止项：不引 `@tauri-apps/plugin-os`、不做分享 Intent、不改打印实现。

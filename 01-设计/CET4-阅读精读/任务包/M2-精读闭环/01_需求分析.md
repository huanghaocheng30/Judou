> 前置：**M1-数据层与文章库 已完成**（候选 `17ea905`；12 篇内容 9 表已入库、文章库可用、精读页只读渲染已正确）
> 定位：v2.0 方案的**第三个包**，也是「产品第一次真正能学」的包——从「能读」到「能点开、能查、能记」。

## 一、为什么这一包

M1 交付后，精读页是**一块玻璃**：文字正确、空格标出来了、题目能展开，但**点什么都不动**。它证明「数据对了」，没证明「这产品有用」。

M2 之后，一个真实的精读动作才完整：

- 读到一句看不懂 → **点句子** → 右栏给出六段式解析（翻译 / 成分 / 从句 / 短语 / 易错 / 段落作用）
- 碰到一个词不确定 → **点词** → 词卡给出「在本句里的意思」；查不到就给「词库通用义」；再查不到就说「暂无预置解析」
- 选词填空卡在第 26 空 → **点空格** → 给出「正确答案 / 为什么是它 / 易错与排除」
- 想到点什么 → **在解析旁边写笔记** → 停手 800ms 自动存，下次打开还在

这四件事构成一次完整的精读，也是 M3（生词本）与 M4（复习）的输入源：M3 要靠「词卡上收藏」这一动作，M4 要靠「这篇文章读完了」这个事件。

## 二、用户可感知的交付

打开一篇文章 →

1. **点一个句子** → 右侧（宽屏）/ 底部（窄屏）出现解析卡，卡顶**先把你点的那句话重述一遍**，下面六段：
   ① 翻译（直译 + 顺译）② 主干与成分划分 ③ 从句与语法点 ④ 重点短语 ⑤ 易错点 ⑥ 段落作用
   - 默认展开前两段，其余折叠（点标题展开）
   - 结构划分那一句里，**【主语】是蓝色带底**、`_谓语_` 有下划线、`~表语~` 有波浪线、`{从句}` 留花括号、`(短语)` 留圆括号——**符号变成样式，不是被扔掉**
2. **点一个词** → 词卡：音标 / 词性 / **本句里的意思** / 搭配 / 例句 / 「更多」（词根、近义、易混）
   - 词卡上写「**词义（通用）**」且没有语境义时 → 说明这句没给它专属解释，用的是词库通用义
   - 什么都没有 → 「暂无预置解析」，卡片不空着
3. **点选词填空的编号 26~35** → 空格卡三段：**正确答案**（词 + 词库字母）/ **为什么是它** / **易错与排除**（逐条一行）
4. **题目区**点开后，每题有「显示答案」→ 只显示答案字母和对应选项文字，**不判对错、不计分、不用红绿**
   - 已知例外：第 2 套长篇阅读第 38 题内容包**没有答案**，点开要显示「本题无预置答案」而不是空白或猜一个
5. **在解析卡里写笔记** → 句子笔记三栏（翻译 / 语法 / 短语），词卡笔记三栏（语境义 / 搭配 / 例句），停手 800ms 自动保存；关掉应用再打开还在；**清空内容就删掉这条笔记**
6. **窗口拉窄/拉宽** → 宽屏（≥1100px）是右侧栏、跟随正文；窄屏是底部抽屉（≤55% 视口、可拖动、Esc 关）
7. 点词**不会**同时触发句子解析（词有词卡、句子有句子卡，不打架）

## 三、范围边界

**做**：
- **8 个新命令**：`get_sentence_analysis` / `get_token_analysis` / `lookup_lexicon` / `get_blank_analysis` / `get_sentence_note` / `get_word_note` / `upsert_sentence_note` / `upsert_word_note`
- **`ApiSentence` 增 `id` 字段**（M1 只下发 `idx`，M2 要 `sentence_id` 才能查解析、存笔记）
- **解析卡**：六段式 + 符号→样式 + 默认展开前两段 + 缺字段降级 + 卡顶重述原句
- **词卡**：三态降级（语境义 → 词库通用义 → 暂无预置解析）+ `more` 折叠 + 数组/字符串两形态兼容
- **空格卡**：三段式 + `distractors` 两形态拆条
- **题目**：折叠区 + 「显示答案」（只显字母与选项文本，不判分）+ `answer IS NULL` 降级
- **笔记**：句子 3 栏 / 词 3 栏，800ms 防抖自动保存、卸载 flush、失败保留草稿可重试、空内容删行
- **响应式双形态**：≥1100px 右栏 / <1100px 底部抽屉（≤55% 视口、拖动、Esc 关）
- **纯函数分层**：符号解析（`parseMarkup`）、解析卡字段映射、降级链路判定、两形态归一（数组/字符串）——全部纯函数，可 node 断言
- **门禁脚本**：解析卡/空格/词卡数据完整性、Markup 纯函数、笔记往返

**不做**（明示延后）：
- **收藏到生词本**（`add_vocab_from_token` / `vocab_entry`）→ **M3**，本包词卡**不放收藏按钮**（放了就是 M3 的半成品）
- 生词本、标签、掌握状态 → M3
- 复习计划、今日待复习、复习模式 → M4
- 用户导入文章的「无解析降级」真机路径（本包只有内置 12 篇，`hasAnalysis` 恒 true）→ M5
- 阅读记录、统计、导出、备份 → M6
- 打包、Android → M7

## 四、关键约束

1. **解析四表只读**：`sentence_analysis` / `token_analysis` / `lexicon` / `blank` 由内容包写入，**任何用户操作不得改这四张表**（06 #3）。本包只新增对 `sentence_note` / `word_note` 的写。
2. **`001_init.sql` 一字节不改**：`sentence_note` / `word_note` 两表在 M0 已建好（各 3 个内容字段 + `updated_at`），**M2 不需要任何 schema 变更**。
3. **笔记按表结构做 3 栏，不用单字段 content**：`sentence_note(translation, grammar_note, phrase_note)` / `word_note(context_meaning, collocation, example)`——这三栏恰好对应解析卡的三个维度（翻译/语法/短语）与词卡的三个维度（语境义/搭配/例句）。05 §八 写的 `upsert_note(targetType, targetId, content)` 是单字段形态、与已发布 schema 冲突，**以表结构为准**（决策记录 #13）。
4. **符号渲染不得丢弃**（06 #4）：`【】`主语（蓝色 + 轻底）/ `_ _`谓语（下划线）/ `~ ~`宾语表语（波浪线）/ `{}`从句（保留花括号）/ `()`短语分词（保留圆括号）；深色模式单独一组提亮标注色。**按符号渲染，不校验内容包的语法标注是否正确**（实测有 `~That~` 标成表语而实际是主语——那是内容质量问题，不是渲染问题）。
5. **边注节奏不可改**（06 #6）：宽屏点句 → **右栏原地更换**，不弹窗、不浮层、不遮正文；卡顶**先重述被点的原句**再给解析。
6. **两形态兼容**（06 #5）：`more.synonyms` / `more.confusables` / `collocations` / `examples` / `distractors` 可能是数组也可能是字符串，渲染层两种都吃（数组逐项、字符串按 `、`/换行拆条）。
7. **前端只经 `api.ts`**；React 组件零裸 `invoke(`；解析/降级/拆分判定**全部纯函数**（05 §十七 #5）。
8. **无障碍底线**（06 #8）：全可 Tab 聚焦、`:focus-visible` 可见、颜色非唯一信息通道、抽屉 Esc 可关且 ≤55% 视口。
9. **`answer IS NULL` 必须优雅降级**（D-M1-1）：内容包 `set2Long` 第 38 题无答案，点「显示答案」显示「本题无预置答案」，**不得显示空白、不得猜**。
10. **响应时间**：点句 → 解析卡 < 300ms、点词 → 词卡 < 200ms（本地库查询，毫秒级；按需查询，不预加载 274 份解析）。

## 五、验收摘要

10 条验收标准见 `02_开发方案与任务包.md` 第一节。硬门槛四条：

- **AC3 符号渲染**（五种符号都变成样式、且解析文本逐字不丢）——它是内容包 274 句解析的唯一呈现通道
- **AC5 三态降级**（语境义 / 通用义 / 无语义 三种样本都对）——写错会让「查不到」变成「空白卡片」
- **AC8 笔记往返**（写 → 存 → 重启还在 → 清空即删）——它是用户**唯一会丢数据**的路径
- **AC10 双形态**（≥1100px 右栏 / <1100px 抽屉，且窄屏不遮正文超过一半）——它决定这产品在笔记本上能不能用

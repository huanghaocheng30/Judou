## 二、改动点（逐条可执行）

### F0 · 前置：确认 Esc 真实根因（不许跳过）
- 在动手改之前，用 CDP `Input.dispatchKeyEvent`（`{type:'keyDown', key:'Escape', code:'Escape', windowsVirtualKeyCode:27}`）在**四种组合**下各试一次：宽屏/窄屏 × 焦点在正文/焦点在笔记框。
- 把四种结果写入自测（哪种生效、哪种不生效），**再**决定改哪里。若宽屏本就无意义（宽屏 Esc 不是要求）——本包要求**宽屏 Esc 也生效**（清除选中），所以这是明确要做的，但仍需先测出窄屏失败的真实原因（否则可能修不到点上）。
- **消费接口**：M2 的 `AnalysisPanel` 现状；**产出接口**：根因结论（写进自测，供审查核对）

### F1 · Esc 统一处理（对应 AC-R1）
- `AnalysisPanel.tsx`：把 Esc 监听从 `if (wide || status === "none") return` 改为**只要 `status !== "none"` 就绑**（宽屏也绑）；用 `window.addEventListener("keydown", onKey, true)`（捕获阶段，绕开输入框 stopPropagation 的可能拦截）；`onKey` 内先判 `event.isComposing` → 直接 return。
- 若 F0 测出「焦点在 textarea 时 window 收不到」（少数环境），则在 `NoteEditor` 的 textarea 上加 `onKeyDown` 兜底调同一个 `onClose`（**必须复用同一个 handler**，不写两份逻辑）。
- **消费接口**：F0 结论；**产出接口**：`onClose` 唯一入口（供 D8 的 `targetKey` flush 复用，注意关闭前必须 flush 草稿——M2 的 `useDebouncedSave` 已按 `targetKey` 变化 flush，Esc 关闭属卸载，必须走同一条 flush）

### F2 · 句子角标（对应 AC-R2）
- `Reader.tsx` 的 `Sentence` 组件：在句末加 `<span className="sentence-mark" aria-hidden="true" data-sentence-mark data-has-note={hasNote ? "1" : undefined}>析</span>`（**纯装饰**，不绑事件；点击由父节点 `onClick` 处理）。
- `app.css`：`.sentence` 加 hover / `:focus-visible` 反馈（背景或下划线，**不得**改动正文排版节奏）；`.sentence-mark` 小号、低对比但可见（对比度按 ≥3:1 的标注色阈值，`check-contrast` 增配对项后需绿）。
- **消费接口**：AC-R3 的 `hasNote`（见 F4）；**产出接口**：`data-sentence-mark` / `data-has-note`（供 CDP 断言）

### F3 · 词节点笔记标记（对应 AC-R3）
- `Reader.tsx` 的词节点：`data-has-note={hasNote ? "1" : undefined}` + CSS 视觉区分（如底部小圆点），**不改** token 文本、不改 `renderTokens` 纯函数语义。
- **消费接口**：F4 的命令；**产出接口**：`data-has-note`（供断言）

### F4 · 批次查询「本篇笔记标记」（对应 AC-R3）
- **Rust**：`analysis.rs` 新增 `get_article_note_marks(article_id) -> NoteMarks { sentenceIds: number[], tokenIds: number[] }`：
  ```sql
  -- 句子：本篇文章下的句子
  SELECT sn.sentence_id FROM sentence_note sn
    JOIN sentence s ON s.id = sn.sentence_id
   WHERE s.article_id = ?1;
  -- 单词：本篇文章下的 token
  SELECT wn.token_id FROM word_note wn
    JOIN token t ON t.id = wn.token_id
    JOIN sentence s ON s.id = t.sentence_id
   WHERE s.article_id = ?1;
  ```
  （`token` 表须有 `sentence_id` 列——**开发员先核 `001_init.sql`**；若无，改为经 `sentence` 关联的等价写法并在自测里写清）
- `commands.rs` 薄包装 + `lib.rs` `generate_handler!` 注册（**注册点只在 `lib.rs`**）。
- `types.ts` 加 `NoteMarks`；`api.ts` 加封装；`Reader.tsx` 加载内容后**一次**调用并下发。
- **红线**：只读两张笔记表，不写；解析四表零写；`001_init.sql` 零改动。
- **消费接口**：M1 的 12 篇/274 句 id；**产出接口**：`NoteMarks` 供 F2/F3

### F5 · 门禁与证据（对应 AC-R4）
- `check-contrast.mjs` 增 `.sentence-mark` 与 hover 态配对（判据项 26 → ≥28，**先红后绿**）。
- `verify-analysis.mjs` 不动（纯函数层未变）；**新增** `scripts/verify-note-marks.mjs`：临时库（直跑 `001_init.sql`）→ 插 2 条句笔记 + 1 条词笔记 → 断言 `get_article_note_marks` 返回的 id 集合精确；清空后返回空（**先红后绿**）。
- `package.json` 加 `verify:note-marks`。
- 自测**必须**重跑 M2 的 CDP 断言脚本（原 57 项不许减少；Esc 与笔记标记新增用例追加进去）。

## 三、自测要求（每条 AC 至少一项机器可核证据）

| AC | 手段 | 判据 |
|---|---|---|
| AC-R1 | CDP `Input.dispatchKeyEvent` × 四组合 + isComposing 用例 | 四种组合下 `data-panel-status` 由 `ready` → `none`；`isComposing` 用例**不变** |
| AC-R2 | CDP DOM + computed style | 每句有 `[data-sentence-mark]`；hover/`:focus-visible` 前后 background-color 或 text-decoration 变化（给前后值）；角标内无嵌套 button |
| AC-R3 | `verify-note-marks.mjs` + CDP | 写前 `data-has-note` 不存在 → 写后 `="1"` → 清空后消失（句与词各一组）；一次 IPC（网络/DOM 层无法直接数 IPC，用 Rust 侧单测或日志断言调用次数为 1，或至少断言「页面加载后才写笔记也不需刷新」） |
| AC-R4 | 7 道门禁 + CDP 回归 | 全 exit 0；CDP 断言总数 ≥ 57 且 0 失败；六属性名不变；`git diff` 001 为空 |

**证据纪律**：UTF-8 无 BOM、`&` + `*>` 全流重放、非空壳自检、统计行与逐项算术一致（M2 已收口 D-M1-8，沿用）。

## 四、风险与影响面

| 风险 | 影响 | 缓解 |
|---|---|---|
| 角标破坏正文排版节奏（06 #6 边注节奏） | 阅读体验变差 | 角标 inline、小字号、`aria-hidden`，不改行高与字距；hover 态只做背景不动布局 |
| 宽屏 Esc 关右栏后用户找不到解析 | 体验回退 | 宽屏 Esc 只清选中（面板收起），点句即恢复；关后焦点回到该句（`focus()`） |
| 笔记标记查询拖慢进入文章 | 首屏变慢 | 一次两条 SQL（走 `sentence_note.sentence_id` UNIQUE 与 `word_note.token_id` UNIQUE 索引），实测 <10ms；不预加载解析 |
| Esc 在 IME 组合中误关 | 中文输入被打断 | `event.isComposing` 直接 return；CDP 用 `compositionstart` 模拟用例 |
| 新增命令漏注册 | 前端 invoke 报 command not found | AC-R4 用 `verify:invoke` + `lib.rs` grep 逐条核 |

**环境事实（承 M2，不变）**：Node v24.21.0 / npm 11.19.0 / Rust 1.99.1(msvc) / `vcvars64.bat` 路径已知 / WebView2 v156；CDP 启动 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`，用完杀进程 + 端口无残留；**在 `02-代码/` 写文件会让 vite watcher 崩 → 先改完再起 dev**。

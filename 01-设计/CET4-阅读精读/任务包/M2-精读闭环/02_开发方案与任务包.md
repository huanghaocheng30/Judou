## 一、需求摘要与验收标准

**目标**：把精读页从「一块玻璃」变成能学的页面——点句出六段式解析卡、点词出三态词卡、点空格出三段式解析、题目能显示答案（不判分）、句子与词都能写笔记并自动保存。**不做收藏/生词本/复习/用户导入。**

| 编号 | 验收标准（可测） |
|---|---|
| AC1 | **命令层**：Rust 新增 **8** 个命令（`get_sentence_analysis` / `get_token_analysis` / `lookup_lexicon` / `get_blank_analysis` / `get_sentence_note` / `get_word_note` / `upsert_sentence_note` / `upsert_word_note`）并注册；`api.ts` 各有一层封装且类型来自 `types.ts`；**`get_article_content` 的 sentence 增下发 `id`**（M2 查解析/存笔记的唯一句标识）；裸 `invoke(` 除 `api.ts` 外**为 0** |
| AC2 | **六段式解析卡**：274/274 句都能出卡（`git grep` 证明无「只有部分句可查」的硬编码）；段序固定 ①翻译（直译+顺译）②主干与成分划分 ③从句与语法点 ④重点短语 ⑤易错点 ⑥段落作用；**默认展开前两段、其余折叠**；**卡顶先重述被点的原句**；缺字段 → 该段显示「本段暂无解析」（不空白、不报错）；整篇无解析 → 卡头「该篇无预置解析」（本包只有内置篇，此分支由组件级断言覆盖） |

| AC6 | **题目与答案**：题目区默认折叠；每题有「显示答案」→ **只显示答案字母 + 对应选项文字**，**不判对错、不计分、不使用「正确/错误」语义色**；**`answer IS NULL` 时显示「本题无预置答案」**（样本：`set2Long` 第 38 题，D-M1-1）；选项**不可点选**（点击后 DOM 无变化） |
| AC7 | **交互不误触 + 响应**：点词**不触发**句子解析卡（`stopPropagation`；断言「点词后句子卡不出现、词卡出现」）、点句子命中区为词之间的空白与句尾；点句 → 解析卡 **< 300ms**、点词 → 词卡 **< 200ms**（本地库查询，实测记录） |
| AC8 | **笔记**：句子笔记 **3 栏**（翻译 / 语法 / 短语）、词卡笔记 **3 栏**（语境义 / 搭配 / 例句），完全对应已发布的 `sentence_note` / `word_note` 表结构；停止输入 **800ms** 自动落库；**卸载/切页前 flush**（不丢最后一段输入）；**清空全部栏 = 删除该行**（不留空行）；保存失败 → 保留草稿 + 显示可重试提示 + 下次输入重试，**不静默丢**；**重启应用后内容仍在** |
| AC9 | **响应式双形态**：`≥1100px` → 右侧解析栏（320~380px，点句**原地更换**，不弹窗/不浮层/不遮正文）；`<1100px` → 底部抽屉（**高度 ≤55% 视口**、可拖动调整、**Esc 可关**、关闭回原文）；两形态下解析内容与笔记功能一致 |
| AC10 | **范围与红线**：解析四表（`sentence_analysis`/`token_analysis`/`lexicon`/`blank`）**运行期只读**（`git grep` 证明无 `UPDATE`/`INSERT`/`DELETE` 命中这四表）；`001_init.sql` **零改动**；**不写 `vocab_entry`**（收藏归 M3）；零裸 `invoke(`；改动全在 `02-代码/`；无障碍底线（可 Tab、`:focus-visible` 可见、颜色非唯一通道） |

## 三、具体改动点（逐条可执行）

### D0 · 前置：`ApiSentence` 增 `id`（对应 AC1）
- `commands.rs` 的 `get_article_content`：sentence 结构体加 `id`（DB `sentence.id`）；`types.ts` 的 `ApiSentence` 加 `id: number`。
- **为什么必须先做**：M1 只下发 `idx`（篇内序号），而 `get_sentence_analysis` / `upsert_sentence_note` 都要 `sentence_id`。不做这一步后面全部悬空。
- **回归风险**：`verify-render.mjs` 的段落级断言用 `paragraph.sentences[].start/end/text`，加字段不影响；但**必须重跑**确认 90/90 仍绿。
- **消费接口**：M1 的 `get_article_content` / `ApiSentence`；**产出接口**：`sentence.id` 供 D1 全部句子级命令、D5 句子卡、D8 笔记。

### D1 · Rust 8 个命令 + 查询层（对应 AC1 / AC10）
- 新增 `src-tauri/src/analysis.rs`，`commands.rs` 只做薄包装并注册：
  - `get_sentence_analysis(sentenceId) -> Option<SentenceAnalysis>`：查 `sentence_analysis`（`sentence_id` UNIQUE，索引已有）；返回体含上表 9 字段
  - `get_token_analysis(tokenId) -> Option<TokenAnalysis>`：查 `token_analysis`（`token_id` UNIQUE）
  - `lookup_lexicon(normalized) -> Option<LexiconEntry>`：按主键查 `lexicon`
  - `get_blank_analysis(articleId, blankNo) -> Option<BlankAnalysis>`：查 `blank`（`UNIQUE(article_id, blank_no)`）
  - `get_sentence_note(sentenceId) -> Option<SentenceNote>` / `get_word_note(tokenId) -> Option<WordNote>`
  - `upsert_sentence_note(sentenceId, translation, grammarNote, phraseNote) -> NoteUpsertResult`
  - `upsert_word_note(tokenId, contextMeaning, collocation, example) -> NoteUpsertResult`
- **笔记写入口径（三重裁决）**：① **三栏全空（`TRIM` 后都为空串或 NULL）→ 删除该行**（`DELETE FROM sentence_note WHERE sentence_id = ?`，用 `DELETE` 是**正确**的——这是用户自己的数据、无子表引用，与 M1 的「内容表禁 DELETE」不是一回事）；② 有任何一栏非空 → `INSERT ... ON CONFLICT(sentence_id) DO UPDATE SET ... , updated_at = datetime('now')`；③ 返回 `{deleted: bool, updatedAt: string | null}`。
- **红线**：只写 `sentence_note` / `word_note`；**绝不写** `vocab_entry` / `tag` / `review_*` / `reading_record`；**绝不改** `sentence_analysis` / `token_analysis` / `lexicon` / `blank`。
- **错误结构**：沿用 M1 的 `{code, message}`；查不到一律返回 `None`（不报错码，04 §10.1 明确「取后者更简」）。
- **消费接口**：D0 的 `sentence.id`、M1 的 4 张解析表 + 2 张笔记表；**产出接口**：8 个命令（供 D2）。

### D2 · 类型与封装（对应 AC1）
- `types.ts` 新增 7 个接口（见 §二）；`api.ts` 加 8 个薄封装（沿用 M1 一行式风格，不造统一包装层）。
- **消费接口**：D1 的 8 个命令；**产出接口**：组件层（D4~D9）只依赖 `api.ts`。

### D3 · 纯函数层 `lib/analysis.ts`（对应 AC2 / AC3 / AC4 / AC5）
五个纯函数，**全部不依赖 DOM、不用 `enum`/`namespace`/参数属性、不 import `.css`/`.tsx`**（沿用 M1 R8 约束，`verify-analysis.mjs` 要 node 直接 import）：

1. **`parseMarkup(markup: string): MarkupPart[]`**（AC3 的核心）
   - 标记 → `kind`：`【…】`→`subject`、`_…_`→`predicate`、`~…~`→`object`、`{…}`→`clause`、`(…)`→`phrase`、其余→`text`
   - **文本守恒判据**：`parts.map(p => p.text).join("")` === `markup.replace(/[_~]/g, "")`（`【】{}()` 原样保留在 `text` 里）
   - **fail-closed**：`_` 或 `~` 计数为奇数（标记未闭合）→ 整串退化为单个 `text` part，**不抛错**
   - 嵌套（如 `{when people ask me how I'm doing}` 内含 `(...)`）按**外层优先**切，内层标记原样留在 `text` 里
2. **`toSentenceCard(row): SentenceCardModel`**：9 字段 → 六段固定序（①`translation` 由 literal+natural 合成 ②`structure` 由 `structureSummary` + `components` 合成 ③`clauses` ④`phrases` ⑤`pitfalls` ⑥`paragraphRole`）；缺字段的段标记 `empty: true`
3. **`pickWordCard(tokenAnalysis, lexicon): WordCardModel`**：`mode = "context" | "generic" | "none"`（三态判定的唯一实现，**不许在组件里再判一次**）
4. **`toBlankCard(row): BlankCardModel`**：`distractors` 两形态 → `string[]`（数组直接用；字符串按 `、`/换行拆并去空）
5. **`normalizeList(value): string[]`**：数组/字符串两形态归一（`collocations`/`examples`/`more.synonyms`/`more.confusables` 共用）
- **消费接口**：D2 的类型；**产出接口**：D5/D6/D7 组件 + `verify-analysis.mjs`。

### D4 · 解析容器 `AnalysisPanel`（对应 AC7 / AC9）
- **选中态**：`{kind: 'none'} | {kind:'sentence', id} | {kind:'word', id} | {kind:'blank', no}`，**三者互斥**（点词切换时句子卡消失）。
- **宽屏（≥1100px）**：正文居中 + 右侧固定栏 320~380px；点句 → **原地更换内容**，不弹窗、不浮层、不遮正文（06 #6）。
- **窄屏（<1100px）**：底部抽屉，`max-height: 55vh`，可拖动调整高度（拖动条 + 键盘可用）、`Esc` 关闭、关闭后回原文。
- 断点判定用 `matchMedia("(min-width: 1100px)")` + `useSyncExternalStore`（或等价的最小实现），**不用 resize 监听手写节流**。
- **消费接口**：D2 的 8 个命令封装；**产出接口**：`SentenceCard`/`WordCard`/`BlankCard` 的挂载位 + 关闭态。

### D5 · 句子卡 `SentenceCard`（对应 AC2 / AC3）
- **卡顶重述被点的原句**（06 #6「旁批先重述该句」）：显示 `sentence.text`（截断到合理长度，超长可展开）。
- 六段渲染，**段序固定**；默认展开①②、其余折叠（`<details>` 或等价，**不要自造折叠组件**）。
- ②段里 `structMarkup` 走 `parseMarkup` → 逐 part 输出带 class 的 `<mark>`：
  `mk-subject`（蓝色 + 轻底）/ `mk-predicate`（下划线）/ `mk-object`（波浪线 `text-decoration: underline wavy`）/ `mk-clause`（留花括号）/ `mk-phrase`（留圆括号）
- `self` 为空 → 「本段暂无解析」（05 §五 规则 3）。
- **消费接口**：D3 的 `toSentenceCard`/`parseMarkup`、D2 的 `get_sentence_analysis`；**产出接口**：DOM 钩子 `data-mark-kind`（供断言）。

### D6 · 词卡 `WordCard`（对应 AC4）
- 三态按 `pickWordCard` 的 `mode` 渲染：`context` 显示语境义；`generic` 标题改「**词义（通用）**」；`none` 显示「暂无预置解析」。
- `more`（roots / synonyms / confusables）默认折叠，点「更多」展开；内部列表走 `normalizeList`。
- 音标 / 词性 / 搭配 / 例句按字段有无渲染，**字段空就不渲染那一行**（不要留空标签）。
- **不放收藏按钮**（收藏归 M3，02 范围已写死）。放一个禁用态按钮更糟——用户会以为坏了。
- **消费接口**：D3 的 `pickWordCard`、D2 的 `get_token_analysis`/`lookup_lexicon`；**产出接口**：`data-word-mode`（`context`/`generic`/`none`，供断言）。

### D7 · 空格卡 `BlankCard`（对应 AC5）
- 三段：**正确答案**（`answerWord` + 字母 `answerKey`）/ **为什么是它**（`reason`）/ **易错与排除**（`distractors` 拆条后**逐条一行**）。
- `blank` 无行 → 只显示「第 N 空」+「暂无预置解析」，不报错。

### D8 · 笔记 `NoteEditor` + `useDebouncedSave`（对应 AC8）

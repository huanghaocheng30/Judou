## 一、需求摘要与验收标准

**目标**：把精读页从「一块玻璃」变成能学的页面——点句出六段式解析卡、点词出三态词卡、点空格出三段式解析、题目能显示答案（不判分）、句子与词都能写笔记并自动保存。**不做收藏/生词本/复习/用户导入。**

## 三、具体改动点（逐条可执行）

### D0 · 前置：`ApiSentence` 增 `id`（对应 AC1）
- `commands.rs` 的 `get_article_content`：sentence 结构体加 `id`（DB `sentence.id`）；`types.ts` 的 `ApiSentence` 加 `id: number`。
- **为什么必须先做**：M1 只下发 `idx`（篇内序号），而 `get_sentence_analysis` / `upsert_sentence_note` 都要 `sentence_id`。不做这一步后面全部悬空。
- **回归风险**：`verify-render.mjs` 的段落级断言用 `paragraph.sentences[].start/end/text`，加字段不影响；但**必须重跑**确认 90/90 仍绿。
- **消费接口**：M1 的 `get_article_content` / `ApiSentence`；**产出接口**：`sentence.id` 供 D1 全部句子级命令、D5 句子卡、D8 笔记。

### D1 · Rust 8 个命令 + 查询层（对应 AC1 / AC10）
- 新增 `src-tauri/src/analysis.rs`，`commands.rs` 只做薄包装，**不在此注册**（注册点见 §二 `lib.rs` 行：`mod analysis;` + `generate_handler!`）：
  - `get_sentence_analysis(sentenceId) -> Option<SentenceAnalysis>`：查 `sentence_analysis`（`sentence_id` UNIQUE，索引已有）；返回体含 §三.0 的 9 字段
  - `get_token_analysis(tokenId) -> Option<TokenAnalysis>`：查 `token_analysis`（`token_id` UNIQUE）
  - `lookup_lexicon(normalized) -> Option<LexiconEntry>`：按主键查 `lexicon`
  - `get_blank_analysis(articleId, blankNo) -> Option<BlankAnalysis>`：查 `blank`（`UNIQUE(article_id, blank_no)`）；**返回字段钉死 `{blankNo, answerKey, answerWord, reason, distractors}`**（契约写在改动点，不只靠 §三.0 表）

  - `upsert_sentence_note(sentenceId, translation, grammarNote, phraseNote) -> NoteUpsertResult`
  - `upsert_word_note(tokenId, contextMeaning, collocation, example) -> NoteUpsertResult`
- **笔记写入口径（三重裁决）**：① **三栏全空（`TRIM` 后都为空串或 NULL）→ 删除该行**（`DELETE FROM sentence_note WHERE sentence_id = ?`，用 `DELETE` 是**正确**的——这是用户自己的数据、无子表引用，与 M1 的「内容表禁 DELETE」不是一回事）；② 有任何一栏非空 → `INSERT INTO sentence_note (sentence_id, translation, grammar_note, phrase_note, updated_at) VALUES (?,?,?,?, datetime('now')) ON CONFLICT(sentence_id) DO UPDATE SET translation = excluded.translation, grammar_note = excluded.grammar_note, phrase_note = excluded.phrase_note, updated_at = datetime('now')`——**`updated_at` 在 001 里是 `NOT NULL` 且无 DEFAULT，INSERT 分支必须显式给值**（评审 N-6，漏了 `verify-note` 首跑必红）；`word_note` 同构（4 列：`context_meaning`/`collocation`/`example` + `updated_at`）；③ 返回 `{deleted: bool, updatedAt: string | null}`。

### D3 · 纯函数层 `lib/analysis.ts`（对应 AC2 / AC3 / AC4 / AC5）

1. **`parseMarkup(markup: string): MarkupPart[]`**（AC3 的核心）
   - 标记 → `kind`：`【…】`→`subject`、`_…_`→`predicate`、`~…~`→`object`、`{…}`→`clause`、`(…)`→`phrase`、其余→`text`
   - **`text` 语义（唯一定义，评审 B-2 收口）**：每个 `part.text` 一律施加 `replace(/[_~]/g, "")`——**含嵌套内层与 fail-closed 退化分支**；`【】`/`{}`/`()` 原样保留。唯一的替换规则施加于全部 part，故「拼回 === `markup.replace(/[_~]/g, "")`」恒等成立（274/274 可达，无需改内容包）
   - **文本守恒判据**：`parts.map(p => p.text).join("")` === `markup.replace(/[_~]/g, "")`
   - **fail-closed**：`_` 或 `~` 计数为奇数（标记未闭合）→ 整串退化为单个 `text` part（其 text = `markup.replace(/[_~]/g, "")`），并置 `failedClosed: true` 供断言，**不抛错**。内容包触发这条的有 **7 句**（`sentence_id` 26/68/69/75/180/211/260，事实、不改内容包）——断言里按白名单核这 7 句，其余句一律不得 `failedClosed`
   - 嵌套（如 `{when people ask me how I'm doing}` 内含 `(...)`）按**外层优先**切；内层标记不在 text 里残留（同上统一替换），但内层**结构不展开**（一个 clause part 里含 `(...)` 的去标记文本）
   - `ponytail:` 该解析器故意只支持五类非嵌套标记（天花板）；升级路径：若内容包出现嵌套语义需求，再引入栈式解析器
2. **`toSentenceCard(row): SentenceCardModel`**：9 字段 → 六段固定序（①`translation` 由 literal+natural 合成 ②`structure` 由 `structureSummary` + `components` 合成 ③`clauses` ④`phrases` ⑤`pitfalls` ⑥`paragraphRole`）；缺字段的段标记 `empty: true`
   - **模型字段清单（评审 N2-5）**：`SentenceCardModel = { translation, structure, structMarkup, clauses, phrases, pitfalls, paragraphRole, emptyFlags }`——**`structMarkup` 单独留在模型里**（②段渲染符号句要用它，不塞进 `structure` 里免得丢掉原始标记串）
   - **模型类型落点**：`SentenceCardModel` / `WordCardModel` / `BlankCardModel` / `MarkupPart` 四个类型**定义并导出在 `lib/analysis.ts`**（评审 N-8）
3. **`pickWordCard(tokenAnalysis, lexicon): WordCardModel`**：`mode = "context" | "generic" | "none"`（三态判定的唯一实现，**不许在组件里再判一次**）
4. **`toBlankCard(row): BlankCardModel`**：`distractors` 两形态 → `string[]`（数组直接用；字符串按 `、`/换行拆并去空）
5. **`normalizeList(value): string[]`**：数组/字符串两形态归一（`collocations`/`examples`/`more.synonyms`/`more.confusables` 共用）
- **消费接口**：D2 的类型；**产出接口**：D5/D6/D7 组件 + `verify-analysis.mjs`。

### D4 · 解析容器 `AnalysisPanel`（对应 AC7 / AC9）
- **选中态**：`{kind: 'none'} | {kind:'sentence', id, text?} | {kind:'word', id} | {kind:'blank', no}`，**三者互斥**（点词切换时句子卡消失）。**`articleId` 由 `Reader` 经 props 传入**（`get_blank_analysis` 需要它，选中态本身不带）——评审 N-8。**卡顶原句的传递路径写死**：句选中态带 `text`（`Reader` 从 `ApiSentence.text` 填入），`AnalysisPanel` 以 `sentenceCard` 的 `text` prop 传给 `SentenceCard`——不新增第二套取数路径（评审 N2-4）。
- **宽屏（≥1100px）**：**CSS `grid` 双列**（左正文列 + 右侧 **320~380px** 栏，`grid-template-columns: minmax(0,1fr) 360px` 一类）；点句 → **原地更换内容**，不弹窗、不浮层、**不用 `position: fixed` 覆盖正文**（06 #6 边注节奏；决策 #17 / 评审 N-9——原文「右侧固定栏」易被读成 fixed，已改）
- **窄屏（<1100px）**：底部抽屉，`max-height: 55vh`，可拖动调整高度（拖动条 + 键盘可用）、`Esc` 关闭、关闭后回原文。
- **面板状态（承接 04 §九 骨架屏，评审 B-5）**：`data-panel-status` 三值——`loading`（**进入查询即置 loading**，显示骨架占位而非空白）、`ready`（有结果、或无结果的降级文案都算 ready）、`none`（未选中）。**阈值口径（评审 N2-6）**：实现为「查询开始即 `loading`」，04 §九 的「>300ms 显示骨架屏」在此口径下自然满足（本地查询通常 <10ms，骨架一闪而过；慢查询时真实可见）；AC7 只在**构造 ≥300ms 延迟**的场景断言 `loading` 可见，不要求生产路径上做 300ms 定时器延迟挂载。
- 断点判定用 `matchMedia("(min-width: 1100px)")` + `useSyncExternalStore`（或等价的最小实现），**不用 resize 监听手写节流**。
- **消费接口**：D2 的 8 个命令封装 + Reader 传入的 `articleId`；**产出接口**：`SentenceCard`/`WordCard`/`BlankCard` 的挂载位 + 关闭态 + `data-panel-status`。

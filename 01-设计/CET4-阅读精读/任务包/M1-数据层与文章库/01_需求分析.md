> 上游：`04_产品设计方案-v2.0.md` §五（M1 行）/§八（页面与路由）/§十（命令与接口）、`05_分模块设计-v2.0.md` §二（M1 内容导入）/§三（M2 文章库）/§四（M3 精读渲染）/§十七（跨模块约束）、`06_设计定稿记录-v2.0.md` §三（9 条开发规则）、`docs/C4`（导入规格）、`docs/D1`（红线）
> 前置：**M0-骨架与环境 已完成**（候选 commit `1051bb9`；19 张表 + 导航壳 + 主题 + 图标 + CI 已就绪）
> 定位：v2.0 方案的**第二个包**，也是「第一次能看到真内容」的包——把 12 篇 CET4 真题灌进本地库，做出文章库与只读精读页。**不写解析卡、不做笔记/生词/复习**（归 M2~M4）。

## 一、为什么这一包

M0 交付的是空壳：8 个页面全是占位，库里有表没数据。用户在这个阶段能测的只有「能开、主题能切」。

M1 之后，产品第一次**能读**：

- **12 篇真题**（3 套 × 4 篇）进本地库 → 文章库有内容可看、可筛、可搜
- **精读页只读渲染** → 能点进一篇文章，看到逐段逐句的原文、题目、空格位置
- **导入是幂等的** → 之后每次升级内容包都不会重复写、不会覆盖用户的笔记

这三个能力是 M2（解析卡）/ M3（生词）/ M4（复习）的地基：M2 要靠 `sentence_id`/`token_id` 挂解析，M3 要靠 `token.normalized` 聚合生词，M4 要靠 `article_id` 排复习计划。**它们的 id 稳定性完全取决于本包的导入是否幂等、是否按内容包权威值落库。**

## 二、用户可感知的交付

打开应用 →

1. **文章库**页第一次有货：默认「内置」分组显示 **12 篇文章卡**，每张卡有 **篇名 / 年份 / 题型 / 词数 / 句数** 五项。
2. 筛选器可用：**考试类型（CET-4）/ 年份（2023）/ 题型（仔细阅读·长篇阅读·选词填空）**，可组合；切换后列表立刻变；**刷新页面筛选条件还在**（写进 URL）。
3. 搜索框输入标题片段（如 `busy`、`Rival`）能筛出对应篇。
4. 点进任意一篇 → **精读页只读正文**：段落排版、句子可分、词与标点按原文顺序无缝拼回（读起来就是正常英文，看不出拼接痕迹）；**选词填空篇的数字标记 26~35 是空格位**，而正文里的 `150`/`1997`/`88,000` 这类固有数字**不是**空格。
5. 题目区默认折叠，展开可看题干与选项（**选项不可点、答案不显示**——这是 M2 的交互）。
6. 右上/左上**返回**有反应，能回到文章库并保留原筛选。
7. 「我导入的」分组为空时显示引导（「还没有导入材料 → 去导入」），M5 才接真导入。

**此时点句子不会出解析卡、点词不会出词卡**——预期，M2 接。

## 三、范围边界

**做**：
- **内容包落位**：`02-代码/content-pack/`（12 篇 JSON + `manifest.json`）+ `tauri.conf.json` 的 `bundle.resources` 映射
- **`002` 迁移**：给 `token` 加 `is_word`、给 `article` 加 `pack_version`/`sentence_count`（**001 一字节不动**）
- **幂等导入引擎**：manifest 版本比对 → 单事务 upsert 9 张内容表 → `ImportReport{imported, skipped, elapsedMs}`；**绝不写用户 8 表**
- **命令层**：`list_articles` / `get_article_content` / `list_article_filter_options` / `import_content_pack`（全部经 `src/lib/api.ts`）
- **文章库页**：两分组 + 四类筛选 + 标题搜索 + 五项字段卡 + 空分组引导 + URL query 保持
- **精读页只读渲染**：`renderTokens()` 纯函数 + 段/句/词/空格节点 + `data-*` 属性契约 + 题目折叠区 + 返回导航
- **D-M0-6 收口**：`.tag` 对比度达标（M0 遗留，M1 开工前必修）
- **门禁脚本扩展**：导入幂等校验、渲染切片逐字校验、空格判定校验

**不做**（明示延后）：
- 句子解析卡（六段式）、词卡、题目交互、笔记 → **M2**
- 生词本、收藏 → **M3**
- 复习计划与复习模式 → **M4**
- 用户导入（粘贴/TXT/MD/切句/四层校验）→ **M5**
- 记录统计、导出备份、首次引导 → M6
- 发布打包、Android → M7

## 四、关键约束

1. **`001_init.sql` 已发布，一字节不改**（docs D1 §11.6）；本包所有 schema 变更走 `002_add_import_columns.sql`，只做 `ALTER TABLE ... ADD COLUMN`（加法，不删不改）。
2. **空格判定必须用内容包权威 `isWord`**，不得用 `normalized 是否含字母数字` 推导——推导会把选词填空的空格 token（`surface="26"`, `normalized="26"`）判成「词」，空格全部丢失。这就是 `token.is_word` 必须落库的原因。
3. **导入幂等**：`manifest.packVersion` 是**唯一版本权威**；篇内残留的 `packVersion`（实测 12 篇全是 `2023-12-set1-v0.9`，含 set2/set3 篇）**不入库、不参与比较**；版本相等直接返回，**零写入**。
4. **导入绝不碰用户 8 表**（`sentence_note`/`word_note`/`vocab_entry`/`tag`/`vocab_tag`/`review_plan`/`review_log`/`reading_record`）。
5. **渲染走纯函数** `renderTokens(text, tokens, blankNos) -> TokenNode[]`（不依赖 DOM），供 node 断言与 React 组件共用；`data-token-id`/`data-n`/`data-start`/`data-blank-no` 四个属性名**不得改**（M2 起依赖）。
6. **前端只经 `api.ts`**（docs D1 §7.4）；`.ts/.tsx` 里除 `api.ts` 外裸 `invoke(` 为零（M0 已有断言脚本，本包继续守住）。
7. **运行期不联网**；本包不引入任何网络请求。
8. **改动只限 `02-代码/`**（含 `content-pack/` 数据文件）；`01-设计/`、`docs/` 只读。

## 五、验收摘要

9 条验收标准见 `02_开发方案与任务包.md` 第一节。硬门槛三条：

- **AC3 幂等**（二启 `skipped=12` 且零写入）——它坏了以后每次升级都会重写用户数据
- **AC4 数据量**（12/90/274/6699 + 274/213/1561/30 逐项对上）——数字不对就说明导入漏表
- **AC6 渲染**（6699 token 切片逐字一致 + 30 个空格全中 + 固有数字零误判）——这是 M2 全部交互的地基

## 三.0 · 字段名口径表（承重，先定死再做）

> M0 既有 IPC 边界是 **camelCase**（`commands.rs` 的 `PingResult { appVersion }`，`api.ts` 直接读 `.appVersion`）。本包沿用，**不得混用 snake_case**——混用会让 D6 的判据恒 false，30 个空格全部丢失。

| DB 列（snake） | Rust 字段 | serde | IPC JSON | TS 类型 | 判据写法 |
|---|---|---|---|---|---|
| `token.is_word` | `is_word` | `#[serde(rename_all = "camelCase")]` | `isWord` | `isWord: boolean` | **`isWord === false`** |
| `article.sentence_count` | `sentence_count` | 同上 | `sentenceCount` | `sentenceCount: number` | 卡片五项字段 |
| `article.pack_version` | `pack_version` | 同上 | `packVersion` | `packVersion: string` | 仅审计，不参与判定 |
| `sentence.start_offset/end_offset` | `start_offset`/`end_offset` | 同上 | `start`/`end` | `start`/`end` | `text.slice(start,end)` |
| `blank.blank_no` 聚合 | — | — | `blankNos` | `blankNos: number[]` | `blankNos.includes(Number(surface))` |
| `hasAnalysis`（派生） | `has_analysis` | 同上 | `hasAnalysis` | `hasAnalysis: boolean` | M1 恒 `true`（见 R10） |
| `question.options_json` | `options_json` | 同上 | `options` | `options: {key,text}[]` | 在 Rust 侧解析成数组后以 `options` 暴露（**不把原始 JSON 串发给前端**） |
| `StartupError`（Rust 枚举） | `kind` / `message` / `file` | 同上 | `kind` / `message` / `file` | `StartupErrorInfo` | 错误页数据通道（`get_startup_error`）；`file` 只带 basename |

**规则**：① DB 用 snake_case、Rust 结构体字段用 snake_case + `rename_all="camelCase"`、TS 与前端判据一律 camelCase；② `render.ts` 的 `TokenNode` 是**前端内部类型**（`{kind,text,tokenId?,normalized?,start?,blankNo?}`），与 IPC 的 `TokenNode` 无关，命名沿用 05 §四 既定；③ `data-*` 属性名不受本表影响（`data-token-id`/`data-n`/`data-start`/`data-blank-no` 保持不变）；④ **本表只列「需要特别说明的」字段**——其余多词字段（`sourceKey`/`examType`/`examYear`/`examSet`/`sectionType`/`wordCount`/`paragraphCount`/`examTypes`/`years`/`sectionTypes`/`sources`）由 `rename_all="camelCase"` **机械推导**，不逐行列表；**未列出 ≠ 未定义**，一律按 camelCase 推导。

### D1 · `002` 迁移（对应 AC2）

ALTER TABLE article  ADD COLUMN pack_version   TEXT;
ALTER TABLE article  ADD COLUMN sentence_count INTEGER NOT NULL DEFAULT 0;

### D2 · 内容包落位与 manifest（对应 AC1）
- 把 `01-设计/CET4-阅读精读/内容包/` 下 **12 篇 JSON + `manifest.json`** 拷入 `02-代码/content-pack/`（**13 个文件、合计 3,529,547 B、逐字节一致**，用 `verify-pack.mjs` 的 SHA-256 自证；目录内不得出现 `_` 前缀中间件）。
- `manifest.json` 结构（已由调度员生成，**不改字段名**）：
  - 顶层：`packVersion`（`2026.11.05-1`）、`contentVersion`、`generatedAt`、`schemaVersion`、`note`、`articles[]`、`totals{}`
  - `articles[i]`：`sourceKey` / `articleId` / `file` / `title` / `examType`（`cet4`）/ `examYear` / `examSet` / `sectionType`（`careful`/`long`/`cloze`）/ `sectionLabel`（中文）/ `passageLabel` / `wordCount` / `paragraphCount` / `sentenceCount` / `tokenCount` / `questionCount` / `blankCount` / `visibility`
  - `totals`：12 / 90 / 274 / 6699 / 274 / 213 / 30 / 90 / 1561
- `tauri.conf.json` 加 `"bundle": { "resources": { "content-pack/": "content-pack/" } }`（v2 资源映射形态按实际 CLI 版本对齐；若形态不同按官方写法并在 `concerns` 说明）。
- 运行期定位：优先 `resource_dir()/content-pack`，开发模式回落 `CARGO_MANIFEST_DIR/../content-pack`；两条都试，失败返回 `StartupError::PackMissing`（不 panic）。
- **错误类型＝`StartupError`**（与 05 §二 规则 6 同名；`PackError` 不用），变体 `PackMissing` / `PackCorrupt{file}`；**必须 `impl std::error::Error`**——`lib.rs` setup 闭包用 `?`，不实现 `Error + Debug + Display` 编译不过。
- **路径限域（收 T1）**：`manifest.articles[].file` 必须先 `canonicalize` 再校验其父目录等于包目录，越界（含 `..`、绝对路径、符号链逃逸）一律 `PackCorrupt{file}`，**不得打开该文件**。
- **错误信息只带 basename（收 T2）**：`PackCorrupt{file}` 的 `file` 存 `Path::file_name()` 结果（如 `cet4-2023-12-set1Long.json`），**不写绝对路径**——错误页会展示给用户，绝对路径会泄漏本地用户名与目录结构。
- **消费接口**：内容源文件（只读）；**产出接口**：包目录解析函数 + manifest 结构体（供 D3）。

### D3 · 幂等导入引擎（对应 AC3 / AC4）

- **第 0 步·完整性核对**（取代「版本相等就直接 skip」）：
  1. 读 `manifest.json` 取 `packVersion`（**唯一权威**，篇内 `packVersion` 忽略）。
  2. 与 `schema_meta.pack_version` 比较：
     - **不相等** → 全量导入 12 篇。
     - **相等** → **不直接返回 `skipped:12`**，先核完整性：① 以 `manifest.articles[].sourceKey` 为全集、`SELECT source_key FROM article` 为现存集，**差集 = 缺失篇**；② `COUNT(*)` 对照 `totals` 九项计数；③ **差集空但计数不符**（篇在、子表缺行）→ 用 `totals` 定位到具体哪张表，再按该表的 `article_id` / 父 id 反查受影响篇，**整篇重导**（仍只 INSERT/UPDATE）；定位不出归属时全量重导 12 篇并记 warning（数据完整性优先于省事）。
       - 完整 → `{imported:0, skipped:12}`，**零写入**（不碰任何行，连 `updated_at` 都不动）。
       - 有缺项 → 只导缺失篇，`{imported:k, skipped:12-k}`。
  3. 完整性核对本身**只读**。判据写进 `verify-import.mjs`。
  4. **为什么不能只比版本**：删掉的篇不会改变 `schema_meta.pack_version`，纯版本短路会让 AC3「删一篇能补回」永久不可达。

- **单事务**：全量导入与补导都在一个事务内；任何错误整体回滚（旧数据仍可用），返回 `StartupError::PackCorrupt{file}` 而非 panic。

- **upsert 冲突键（写死，不许自选）**：`article(source_key)` / `paragraph(article_id, idx)` / `sentence(paragraph_id, idx)` / `token(sentence_id, idx)` / `question(article_id, idx)` / `blank(article_id, blank_no)` / `sentence_analysis(sentence_id)` / `token_analysis(token_id)` / `lexicon(normalized)` —— 全部是 001 既有的 UNIQUE / PK，**零 schema 改动**即可 `ON CONFLICT(...) DO UPDATE`。
  **为什么必须写死**：若实现者图省事走「先删后插」，既违反下面的红线，又会让 `sentence_id` / `token_id` 重新分配——用户挂在 `sentence_id` 上的笔记（M2 起就是真实数据）会**全部错位**。01 §一 已写明「M2 的 id 稳定性完全取决于本包导入是否幂等」，这里就是那句话的落地方式。

- **9 张内容表写入映射**（严格按 `05 §二` 建表落点；字段名口径见 §三.0）：
  - `article`：`source_key`（= manifest `sourceKey`，UNIQUE upsert 键）/ `title` / `exam_type`（manifest `examType`）/ `exam_year` / `exam_set`（**内容包是数字，按 TEXT 写入**，R12）/ `section_type` / `word_count` / `visibility='system'` / `sentence_count`（= manifest `sentenceCount`）/ `source`（见下条）/ `pack_version`（manifest `packVersion`）。
  - **`article.source` 取值规则**（B4，裁决 #11）：`'CET-' + <examType 的数字> + ' ' + examYear + '年' + examMonth + '月真题'`，`examMonth` 取篇内 `meta.examMonth`（实测 12/12 = 12）→ 现行 12 篇实际值全为 **`CET-4 2023年12月真题`**；缺 `examMonth` 时退化为 `'CET-4 2023年真题'` 并在日志记 warning。
  - `paragraph`：`idx` 从 0；`text`。
  - `sentence`：`idx` / `start_offset`/`end_offset` **相对段落**（内容包已按此口径）/ `text` / `text_hash` = `sha256(text)` 前 16 位十六进制。
  - `token`：`idx` / `start_offset`/`end_offset` **相对句子** / `surface` / `normalized` / **`is_word` = 内容包 `isWord`（true→1 / false→0，禁止推导）** / `lemma`、`pos` 留 NULL（内容包 token 顶层无这两字段，ADR-009）。
  - `question`（B2）：**`idx` = 内容包 `questions[].no`**（cloze 26~35 / long 36~45 / careful 46~55，与 `blank.blank_no` 同源，是 explanation 的配对键）/ `stem` / `options_json` = `[{key,text}]`（long 篇为 `[]`）/ **`answer` = 内容包 `answer`（必须写；90/90 非空）** / `explanation` = `blanks[no].reason`，该篇无对应空格（careful/long）时写**空串**——与 05 §二 L76 对齐：解析存 `blank.reason`，`question.explanation` 只是 cloze 篇的投影。
  - `blank`：`blank_no`（内容包 `blanks` 对象的 key，转 INTEGER）/ `answer_key` / `answer_word` / `reason` / `distractors`（**归一为 JSON 字符串**；读取侧兼容字符串/数组两形态）。
  - `sentence_analysis`：9 字段（`translation_literal` / `translation_natural` / `struct_markup` / `structure_summary` / `paragraph_role` + `components_json` / `clauses_json` / `phrases_json` / `pitfalls_json`）。
  - `token_analysis`：7 字段（`phonetic` / `pos` / `sense_in_context` / `collocations_json` / `examples_json` / `is_cet4_high_freq` / `more_json`），来自 `token.analysis`（213 个 token 有）。
  - `lexicon`（B3）：12 篇切片合并去重（`normalized` 为主键，1561 行）；**`word` = 该 `normalized` 首次出现 token 的 `surface`**（按 manifest.articles 顺序 → 段落 → 句子 → token 顺序扫描，先到为准、不覆盖）；`lemma` 留 NULL（条目无该字段）；其余 7 字段照抄条目；跨篇 payload 冲突实测 **0**，仍按「先到优先，不覆盖」处理。
  - `schema_meta.pack_version` 与 `article.pack_version` **在同一事务内写同一个值**（R11），不允许一处成功一处失败。

- **红线口径（裁决 #8）**：内容包导入**只允许 `INSERT` / `UPDATE`，禁止 `DELETE` 任何内容表行**。`article` 被 5 张用户表 `ON DELETE CASCADE` 引用，`DELETE FROM article` 会连带删掉用户的句子笔记/生词/复习记录，并把 `vocab_entry.source_article_id` 置 NULL（`db.rs` 已开 `foreign_keys=ON`）。需要下架某篇时只能 `UPDATE article SET status='draft'`。
- `ImportReport{imported, skipped, elapsedMs}`；启动时自动跑一次，结果写日志供取证。
- **绝不写**用户 8 表（`sentence_note` / `word_note` / `vocab_entry` / `review_*` / `setting` 等）。
- **消费接口**：D1 三列 + D2 manifest；**产出接口**：内容表数据（供 D4/D6）。

### D6 · 精读只读渲染（对应 AC6 / AC7）
- **纯函数先行**：`src/lib/render.ts` 的 `renderTokens(text, tokens: ApiToken[], blankNos: number[]): TokenNode[]`
  - 节点类型：`{kind:'text'|'word'|'blank', text, tokenId?, normalized?, start?, blankNo?}`
  - 空格判定**三条件**：**`isWord === false`**（IPC 字段名，见 §三.0；落库为 `is_word=0`）**∧** `surface` 匹配 `/^\d+$/` **∧** `Number(surface) ∈ blankNos`
  - 顺序与偏移严格对齐；断言三条：`text.slice(prev, t.start)` 全空白、`text.slice(t.start,t.end) === t.surface`、末 token `end === text.length`
  - **`render.ts` 的运行环境约束（R8）**：只用 **erasable 语法**（禁 `enum` / `namespace` / 参数属性）；**不得 `import` `.css` / `.tsx`**。原因：`verify-render.mjs` 与 `node` 要直接 `import "./render.ts"`（Node 24 已实测可直跑 `.ts`），一旦引入上述任一项就 import 失败。
- 渲染：逐段 → 逐句 → `renderTokens` 输出映射到 JSX；词节点 `data-token-id`/`data-n`/`data-start`；空格节点 `data-blank-no`（**属性名不得改**，M2 起依赖）。
- 题目区：默认折叠，展开显示题干 + 选项（**点击选项后 DOM 无变化、答案仍未渲染**——M2 才做交互；该断言只在 careful 篇做，long 篇 `options: []` 无可点项）。
- 版式：纸感正文（`max-width: 66ch` 居中）、段落间距、句中词可 hover 高亮（不做点击态）。
- 返回：页头返回控件接路由历史（修 AC7 的原型缺陷）。
- **消费接口**：D4 的 `get_article_content`；**产出接口**：`renderTokens` 供 M2 复用（M2 只加交互，不改节点契约）。

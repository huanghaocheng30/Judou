## 一、验收标准（AC1~AC18）

| 编号 | 判据 | 证据形态 |
|---|---|---|
| **AC1** | 导入页有双 Tab：`data-import-mode="quick"` / `data-import-mode="ai"`；切到 quick 时**原快速导入 6 步全流程不回归**（粘文本→预览→剔段→改标题→确认导入→跳精读） | CDP 两档各走一遍 |
| **AC2** | AI 模式下**先选题型**（`data-ai-section`，三选一：仔细阅读/长篇阅读/选词填空）→ 粘原文后显示「N 段 / M 句」，且 M = 之后入库的真实句数；`data-ai-sentence-list` 内每条含 `S编号` + 该句原文前 24 字符；句数 > 15 时 `data-ai-batch-hint` 显示「建议分批（当前 N 句）」，但**不报错、不阻断**、`parse_payload` 也**不因句数 > 15 拒收** | CDP 读数 + 门禁断言 |
| **AC3** | 粘回**完整** AI payload（每句都有解析 + 题目 + 词条）→ 覆盖率显示 `解析 M/M · 题目 x/y · 词条 n` → 入库成功 → 精读页点句出**六段式**、点词出词卡、题目区显示答案 | CDP + 入库后抽 3 句核对 |
| **AC4** | 只给**部分**句解析（如 20/M）→ 覆盖率 20/M → **仍可入库**；未覆盖句点开显示「该句暂无解析」（不是空白/报错） | CDP 两态对照 |
| **AC5** | AI 改写了原文导致 `quote` 匹配不上 → 该条进入 `unmatched` 列表并在界面逐条列出（含原因）→ 用户点「跳过」后可继续入库；**不得静默丢弃** | CDP + 计数断言 |

## 二、改动点（D0~D9，含消费/产出契约）

> 契约行格式：`消费 = 依赖哪一方的产出`；`产出 = 提供给哪一方`。审核员据此做跨改动点冲突扫描。

### 2.1 AI 模式入参结构（A4 落地，避免触碰快速导入路径）

```rust
/// AI 模式入参：ImportPreview（既有，不动）+ 用户所选题型
pub struct AiDraft {
    pub preview: ImportPreview,   // 复用 import_user.rs:43 的既有结构
    pub section: AiSection,       // Careful / Long / Cloze
}
```

**为什么不在 `ImportPreview` 上加 `section`**：`ImportPreview` 也被快速导入路径使用（`import_user.rs:43`），加字段等于改快速导入的入参与序列化形状，触碰 M5 已验收路径。用外层包一层 `AiDraft` 即隔离。

`section` 前端来源：导入页 `data-ai-section` 三选一（记住上次选择）；patch 模式初值取 `article.section_type`，若其为 `NULL` 或不在 `{careful,long,cloze}` 内则**不预选、要求用户选**（不猜）。

## 三、AI payload 契约（**本包唯一真源**）

> 用户从自己的 AI 拿到的东西**不是**完整内容包，而是这份**轻量语义包**：只给语义，不给结构。
> **结构（段/句/词/偏移）由 App 自己算**——这是「App 管结构、AI 只出语义」的落地定义，也是 AC8 的根据。
> 提示词模板文本（`build_ai_prompt` 产出，用户看到并复制的东西）**必须与本契约同源**：字段名、必填项、题型片段差异三者一致，不得一处增字段而另一处不认。

### 3.1 顶层结构

```json
{
  "packVersion": "2026.11.08-1",
  "section": "careful",
  "sentences": [],
  "questions": [],
  "blankAnalyses": [],
  "lexicon": []
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `packVersion` | 是 | 契约版本号，本版固定 `2026.11.08-1`。**不参与校验**：不匹配时仅在界面提示「模板版本较旧」（避免历史产物无法导入） |
| `section` | 是 | `careful` / `long` / `cloze`；**必须与本次模板所选题型一致**，否则 `AI_TYPE_MISMATCH`（AC7⑤），`path="section"` |
| `sentences` | 是 | 句级数组，见 3.2 |
| `questions` | 否 | 题目数组，见 3.3；快速导入文章补解析时可缺省。**缺省时的形态判定口径**：无 `questions` 则无题号区间 `R`，「正文空号集合」判定不适用 → AC7④ 跳过（不拒收）；`blankAnalyses` 仍照常入库，逐空覆盖率**只显示已解析数 `k`**（分母未知，不显示 `?` 或 `k/?`，对齐 §六.4 表的 `coverage.blanks="10"`） |
| `blankAnalyses` | 否 | **仅 cloze**：逐空解析，见 3.4 |
| `lexicon` | 否 | 词条**数组**，见 3.5 |

**禁止/忽略的字段**（出现即忽略，不计错）：`paragraphs` / `tokens` / `start` / `end` / `offset` / `sourceKey` / `articleId` / `meta`（后三者为完整内容包残留，见 §六.1）。

### 3.2 `sentences[]`

| 字段 | 必填 | 说明 |
|---|---|---|
| `quote` | 是 | 该句原文，**必须与正文逐字符一致**（含标点、引号、连字符）。匹配方式：按句序取第一条未被占用的相同 `quote`；同文重复句按出现顺序对齐 |
| `analysis` | 是 | 九字段对象，见 3.2.1 |
| `sNo` | 否 | 辅助编号（`S1`、`S2`…）。**仅辅助**：与 `quote` 冲突时以 `quote` 为准（AC18） |

#### 3.2.1 `analysis` 九字段（与既有 `sentence_analysis` 表一一对应）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `translationLiteral` | string | 是 | 直译（逐句对照） |
| `translationNatural` | string | 是 | 意译（通顺中文） |
| `structMarkup` | string | 是 | 结构标记句：`【主语】` 主干、`_谓语_`、`~修饰~`、`{}` 从句、`()` 插入语。**`_` 与 `~` 必须成对（偶数次），`【】{}()` 必须配对**——否则 `AI_MARKUP_UNBALANCED`（AC6） |
| `structureSummary` | string | 是 | 一句话结构总结（如「主谓 + 宾语从句 + 同位语」） |
| `components` | `{part,role,note}[]` | 是 | 成分拆解，按主干→修饰顺序 |
| `clauses` | string[] | 否 | 从句说明，无则 `[]` |
| `phrases` | `string[]` **或** `{text,meaning,usage,example}[]` | 否 | 短语/搭配，无则 `[]`。**两种形态都收**（v1.2b 勘误）：既有展示契约 `SentenceAnalysis.phrases` 与内容包均为对象形态，且 `analysis.rs` 的 `PhraseItem.text` 必填（不投影会让六段式「重点短语」整段消失）；写库时零推断投影：字符串 → `{text, meaning:null, usage:null, example:null}` |
| `pitfalls` | string[] | 否 | 易错点，无则 `[]` |
| `paragraphRole` | string | 否 | 本句所在段在全文中的作用 |

### 3.3 `questions[]`

| 字段 | 必填 | 说明 |
|---|---|---|
| `no` | 是 | 题号（整数，与试卷题号一致：仔细阅读 46~50、长篇 36~45、cloze 26~35） |
| `stem` | 是 | 题干；cloze 可为 `第 26 空` |
| `options` | 是 | `{key,text}[]`；**careful 每题必须 4 项**，**long 每题必须 `[]`**（信息匹配题无选项），**cloze 每题必须 15 项**（全部词库项，不是单空答案） |
| `answer` | 是 | 答案：careful/cloze 为选项 key；long 为段落字母（`A`~`N`）。**不在合法集合内即归一为无答案**（AC16），不编造 |
| `explanation` | 否 | 解析文字，落 `question.explanation` |

### 3.4 `blankAnalyses[]`（仅 cloze，落 `blank` 表）

| 字段 | 必填 | 说明 |
|---|---|---|
| `no` | 是 | 空号（26~35） |
| `answerWord` | 是 | 该空答案词（须在**本题的 `options[].text` 词库**内） |
| `reason` | 是 | 为什么选它（语义/搭配/词性） |
| `distractors` | `{key,word,why}[]` | 否 | 干扰项为什么不行，可只给 2~3 个。**对象数组**；字符串形态按「非必填、忽略」处理，不做结构化解析 |

**部分覆盖允许**：10 个空只给 6 个 → 落 6 行 `blank`，`data-ai-blank-coverage` 显示 `逐空 6/10`，**不拒收**（A1 裁决）。

#### 3.4.1 正文空号集合的提取规则（N2，写死）

> 用于 AC7④ 的形态判定。**必须由 App 自己算，禁止读 payload 或源包里的 `tokens`。**

定义：对 cloze 正文跑既有分词（`import_user.rs:374 tokenize`），得到 token 流 `T`。令 `R` = 本次答卷的题号区间 `[min(questions[].no), max(questions[].no)]`（cloze 实测为 `[26,35]`）。正文空号集合 =

```
{ v | t ∈ T, t.is_word == false,
      let s = t.surface 去掉尾部标点（, . ; : ! ? " ' ) ] ）” ’）, 保留内部字符,
      s 为纯 ASCII 数字串,
      且 v = s.parse::<i32>() ∈ R }
```

**为什么不能直接 `surface.parse::<i32>()`**：既有分词会把数字串与紧跟的逗号吞成一个 token（实测源包 `surface` 为 `"28,"`），直接 parse 会失败 → 正例被误判为 `AI_TYPE_MISMATCH`。按上式去尾后 `"28,"` → `28` ✅；而 `"600,000"` 去尾后仍含内部逗号、非纯数字 → 排除 ✅。

**已知脆弱点（如实记录，不掩盖）**：正文中真实出现的数字若恰好落在题号区间（如正文写「共 30 人」），会被误算为一个空号。本包三份 fixture 实测无此情形（审核员核）。若未来出现，处置方式是把区间判定改为「正文中**被挖空标记**的号」（需设计变更），不在本包范围。

### 3.5 `lexicon[]`

| 字段 | 必填 | 说明 |
|---|---|---|
| `word` | 是 | 词条原型；**必须在正文出现**（按 token `normalized` 比对，大小写不敏感），否则进 `unmatched`（AC15） |
| `phonetic` | 否 | 音标 |
| `pos` | 否 | 词性（`n.` / `v.` / `adj.` …） |
| `sense` | 是 | 中文释义（本句语境下的意思优先） |
| `collocations` | string[] | 否 | 搭配 |
| `examples` | string[] | 否 | 例句（含中文翻译） |
| `isCet4HighFreq` | boolean | 否 | 是否四级高频，缺省 `false` |

**小写归一（N6，二选一写死为「归一」）**：`word` 保留原型用于展示；写入 `lexicon.normalized` 前**按 `normalized` 规则小写归一**（对齐 04 §6.2 步 4「词条 key 小写且出现在正文」），不因大小写拒收。

**写入冲突策略（N9）**：`INSERT OR IGNORE` by `normalized` PK——**已存在的行不覆盖**（尤其不覆盖内置 1561 词库），也不因冲突报错。

### 3.6 三题型片段差异（提示词按所选题型裁剪）

> `section` 来源：用户在导入页选（`data-ai-section`），随 `AiDraft` 传给 `build_ai_prompt`（§二.1）。模板只给对应片段，并显式要求 AI 在产物里回填同一个 `section` 值。

| 题型 | `section` | 必给 | 不给 / 特殊 | 分批建议 |
|---|---|---|---|---|
| 仔细阅读 | `careful` | 全部句解析 + 5 题（每题 **4 个 `options`** + `answer`）+ 词条 | 无 | 20 句左右，**一次可给完** |
| 长篇阅读 | `long` | 全部句解析 + 10 题（`options: []`，`answer` 为段落字母）+ 词条 | **禁 `options` 非空**（形态错误①） | 46 句 → **建议按段落拆 2~4 批**，每批 15 句上下 |
| 选词填空 | `cloze` | 全部句解析 + 10 题（每题 `options` = **全部 15 项词库**）+ `blankAnalyses` + 词条 | 每题 `options` 必须 15 项；`questions[].no` 集合必须等于正文空号集合（§三.4.1）；`blankAnalyses[].no` 必须是它的**子集**（可只给部分空解析） | 13 句，**一次可给完** |

### 3.7 分批与覆盖率（三点写死）

1. **15 是模板建议值，不是硬上限**：`build_prompt` 在句数 > 15 时只把句子清单按 15 一组分段打印并提示「建议分批」，**不报错、不截断**；`parse_payload` **不因句数 > 15 拒收**。
2. **单次 payload 句数不设上限**：给 46 句也接受（门禁 `long` 正例即整篇 46 句）。
3. **覆盖率累加合并**（不是覆盖替换）：同一篇文章多次粘贴，解析/题目/逐空/词条四类覆盖率**按已覆盖集合求并集累计**；重复句子以**后到者覆盖先到者**（同一句再给一次视为修订）。AC9 的 20/M → 30/M 依赖此条。

## 四、页面级状态机（D3 / D4 同文件双写口径）

`src/pages/Import.tsx` 被 D3 与 D4 两次修改，口径如下：

### 4.1 单一写入者与实施顺序

- **D3 先落地** commit 路径全流程（双 Tab + 题型选择 + 四步 UI + 入库），D3 通过 `待审查` 后 **D4 才动同一个文件**。
- D4 只在 D3 的产物上**加分支**，不重写四步组件；patch 分支复用同一组子组件。

### 4.2 模式判定

| 入口 | URL | 模式 | 终点命令 |
|---|---|---|---|
| 导入页 Tab → AI 解析导入 | `#/import` | **commit** | `commit_ai_import` |
| 库卡片 / 精读页页头「补解析」 | `#/import?articleId=<id>` | **patch** | `patch_ai_analysis` |

判定只看 `articleId` **是否存在**：有 → patch；无 → commit。不允许两个都走或都不走。

### 4.3 patch 模式的初值与步骤差异

- 进入即调 `get_article_content(articleId)` → 前端 `toImportPreview()` 映射出 `ImportPreview`（段/句/词 + 标题）→ **填充并锁定**「粘原文」与「标题」两步：`data-ai-text` **隐藏不显**，改为只读展示「已从文章库载入：标题 / N 段 / M 句」。
- `data-ai-section` 初值取 `article.section_type`（列见 `migrations/001_init.sql:32`）；为 `NULL` 或不在 `{careful,long,cloze}` 内时**不预选、要求用户选**（不猜）。
- 已覆盖的句/题/空/词**预标**「已有解析」，覆盖率初值取 `get_ai_import_stats(articleId)` 的真读数（不是 0）。
- 之后步骤与 commit 模式完全一致（生成模板 → 粘回 → 匹配 → 覆盖率 → 提交）。
- 最后一键文案不同：commit 是「导入这篇文章」，patch 是「补充解析」（`data-ai-patch-commit`）。

### 4.4 共用校验与写库路径

两模式共用：`build_ai_prompt` → 用户复制 → 粘回 → `parse_ai_payload`（**只做容错解析与 JSON 结构校验**；容错剥围栏取最外层 `{}`）→ `match_ai_payload`（**先 `validate_payload` 做形态校验与 markup 校验**——⑤ 题型一致性必须在此判，因为 `parse_payload` 是单参签名拿不到 `draft.section`；然后做 quote 匹配 → `matched` / `unmatched`）→ 覆盖率渲染 → 终点命令。**⑤ 优先于 ①②③④ 报错**（同一份 payload 同时违反时，`path` 必须是 `section`）。
**差异只在终点命令与「原文来源」**。**校验逻辑与写库逻辑都只有一份实现**（在 D0 的 `ai_import.rs`）：不得在前端复制校验、不得在命令层或 bin 里复制 SQL（N4）；否则 AC5/AC6 会出现两套行为。

### 4.5 中间态隔离

切 Tab 时清空 AI 中间态（`text` / `payload` / `unmatched` / 覆盖率）；quick Tab 的既有 state 保持 M5 原样不动（AC1 不回归）。

## 五、错误码契约（4 码，与既有 `ImportCode` 形态一致）

> 既有形态参考 `import_user.rs:110-152`：`as_str()` 给码 + `message()` 给用户可读修法；错误体 `CommandError{code, message, path}`。

| 错误码 | 触发条件（可机械判定） | `message()`（用户可读修法） | `path` |
|---|---|---|---|
| `AI_PAYLOAD_INVALID` | 剥围栏、取最外层 `{}` 后仍非法 JSON；或顶层不是对象；或缺 `section`/`sentences` | 「粘贴内容不是合法 JSON。请确认复制了完整的 `{` … `}` 块，且没有漏掉结尾的 `}`」 | `"payload"` |
| `AI_TYPE_MISMATCH` | AC7 六种形态错误之一 | 按形态给具体文案，如「长篇阅读的题目不应带选项（第 36 题有 4 个选项）；长篇信息匹配题的 `options` 必须是空数组」 | ①`"questions[2].options"` ②`"questions[0].options"` ③`"questions[0].options"` ④`"blankAnalyses"` ⑤⑥`"section"` |
| `AI_MARKUP_UNBALANCED` | 某句 `structMarkup` 的 `_` 或 `~` 为奇数次，或 `【】{}()` 不配对 | 「第 S12 句的结构标记不配平：`_` 出现 3 次（必须成对）。可点『跳过该句』继续导入」 | `"sentences[11].analysis.structMarkup"` |
| `AI_NO_MATCH` | **一句都没匹配上**（`matched` 为空且 `unmatched` 非空）——通常是粘错文章 | 「粘贴的解析与当前文章完全不匹配：请确认复制的是这篇文章的模板产物」 | `"sentences"` |

**边界分工**：部分不匹配（≥1 句命中）**不是错误**，进 `unmatched` 由用户处置（AC5/AC14）；只有 0 句命中才是 `AI_NO_MATCH`。这与 05 约束 2 不冲突。

## 八、风险与三问裁定

| 风险 | 缓解 |
|---|---|

# 01 · 需求分析（M5b-AI解析导入）

> 上游指针：用户 2026-11-07 实测 M5 后的重设计请求（原话：「给用户一个模板，用户拿上模板带上他自己找的阅读原文、题目、答案，交给用户自己找到的 AI，AI 生成符合我们模板要求的格式，用户再复制粘贴到我们这里」）｜父任务 M5-用户导入｜设计基线 **DB-20261107-5**（04 v2.1 §6.2 / §8，05 v2.1 §十一之二，06 v2.1）
> **未决澄清项：无**

## 一、为什么要这个包

M5 的「快速导入」只解决「把纯文本变成可点词的精读文章」，导入进来的文章**没有解析、没有题目答案**（设计上的降级）。用户的实际需求是：**他愿意自己找 AI 生成解析**，只要 App 给他一个说得清的模板。这既省掉项目的解析成本，也让导入的文章真正好用。

同时暴露两个现实约束（决定了形态）：

1. **AI 算不准偏移**：一篇长篇阅读 1193 个 token，每个都要 UTF-16 精确位置；AI 数不准 → 用户点词会高亮错位，且用户无法自查。
2. **AI 一次写不完**：一篇 long 完整内容包约 570 KB（解析占 400 KB），超出单次输出上限 → 必须分批。

因此本包的职责划分是：**App 管结构（切句/分词/偏移/校验），AI 只管语义（解析/题目答案/词条）**。

## 二、用户会经历的流程（4 步）

1. 导入页选「**AI 解析导入**」→ **选题型**（仔细阅读 / 长篇阅读 / 选词填空）→ 粘原文（可一次粘一整卷多篇，也可只粘一篇）→ 界面显示「N 段 / M 句」
2. 点「**复制提示词 + 句子清单**」→ 粘贴给他自己找的 AI（模板按篇目题型只给对应片段：仔细阅读 / 长篇阅读 / 选词填空；默认每批 ≤15 句）
3. 把 AI 返回的 JSON 粘回 App（可多次粘贴累积：15/42 → 30/42 → 42/42）
4. 看到覆盖率与未匹配清单 → 点「**确认入库**」；已入库的文章之后还能「**补解析**」

## 三、范围与边界

**做**
- 导入页双 Tab（快速导入保留不动 / AI 解析导入新增）
- **题型选择**（A4 裁决）：AI 模式下由用户在导入页三选一，作为「模板按题型裁剪」与「题型不符拒收」的基准；补解析时若文章已存题型则预选
- 提示词生成（含句子清单锚点、题型片段、分批指令）
- AI 产出的容错解析（剥 ```json 代码块与说明文字）、偏移字段一律忽略
- 按 `quote` 文本匹配定位句子；未匹配句呈现给用户处置（跳过 / 重新生成该句）
- 校验并入库：JSON 合法、题型形态、`structMarkup` 括号与 `_~` 成对、词条 key 在正文、答案不编造
- 覆盖率显示（解析 / 题目 / 词条三档独立）
- **允许不完整入库**（未覆盖句显示「该句暂无解析」）
- **后补解析**：已入库文章（含快速导入的）可增量补，且不重写原文结构、不动笔记/生词/复习/阅读记录

**不做**
- 不调任何外部 AI API（用户自己去聊，我们不联网、不带 key）
- 不改数据库 schema（复用 `sentence_analysis`/`question`/`lexicon`/`token_analysis`）
- 不做 PDF/DOCX/OCR、不做文件选择器、不做自动翻译
- 不改快速导入路径与其 AC
- 不自动修复 markup（只提示 + 允许跳过该句）

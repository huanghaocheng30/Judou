## 二、改动点

### F0 红端取证（必须先做）
在 `02-代码/` 跑 `npm run tauri dev`，捕获「bin 歧义」原始报错 + exitCode，落 `.tmp/TP-修复6/red-dev.log`（`.tmp/` 不入库）。

### F1 修复（一行 + 注释）
`02-代码/src-tauri/Cargo.toml` 的 `[package]` 段加：

```toml
# 本 crate 有两个 bin（隐式 judou + 显式 import_user_cli）：不设 default-run 时
# `cargo run`（tauri dev/build 走它）无法选 bin，报 "could not determine which binary to run"。
default-run = "judou"
```

**不加其它任何字段**；`[[bin]]` 与 `[lib]` 原样保留。

### F2 验证
AC-R2 复跑同一命令 → AC-R3 起窗与端口 → AC-R4 M5 契约 → AC-R5 回归门禁 → AC-R7 清场。

## 三、自测要求

- **红→绿**：AC-R1（改前报错原文）→ AC-R2/AC-R3（改后无报错 + 起窗）
- 证据纪律：UTF-8 无 BOM；含 `Write-Host` 的输出禁 plain `>`，用进程内 `&` + `*>` 全流重放；证据文件非空壳自检（>0 字节且含预期锚点，如 `could not determine which binary`、`Running \`target\debug\judou.exe\``）；统计行与逐项算术一致；心跳真实时间写入 `.tmp/TP-修复6/heartbeat-<runId>.md`
- **收工清场**：杀 dev、确认 1420 / 9222 无监听
- 若 dev 因环境不可起（如无 GUI 会话）：按 `DONE_WITH_CONCERNS` 返回，把 `cargo run` 不歧义 + 端口 200 的读数作为部分证据，明确写阻塞原因，**不要伪造起窗**

## 四、风险

| 风险 | 缓解 |
|---|---|
| 只加 default-run 不够（还有第二处 bin 歧义） | AC-R1 红端原文 + AC-R2 复跑同一命令；仍失败按 `与 01 初判不符 + 新证据` 上报 |
| 修 default-run 弄坏 `import_user_cli` 门禁 | AC-R4 显式核验（这是唯一允许的"另一条 bin 路径"） |
| dev 起窗长驻拖住执行 | 后台起、读日志到 `Running` 即判过、随后 kill 并做 AC-R7 清场 |

**三问裁定**
1. **改动形态**：1 文件 1 行（`Cargo.toml` `[package]` 段）+ 注释；零 Rust/前端源码改动。
2. **最便宜验证**：`cargo run` 秒级不歧义；`npm run tauri dev` 复用已有 debug 缓存（`target/debug/judou.exe` 11-06 23:25 编译过，增量约 1~3 分钟）→ 看日志 + 端口，不必人工点界面。
3. **过度杀伤禁止项**：`tauri build` / 打包；删 `[[bin]]`；改 `src/bin/import_user_cli.rs`；改任何 `src/**`；改门禁脚本；新增依赖；顺手修其它问题。

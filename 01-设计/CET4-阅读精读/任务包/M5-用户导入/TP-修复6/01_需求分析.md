## 一、问题（M5-U1 · 阻断级 · 修复级）

**现象**：在 `02-代码/` 执行 `npm run tauri dev`，前端 vite 正常（`VITE v6.4.5 ready in 1289 ms` → `Local: http://127.0.0.1:1420/`），Rust 侧立刻失败退出（终端会话 **exitCode=101**）：

```
Running DevCommand (`cargo  run --no-default-features --color always --`)
error: `cargo run` could not determine which binary to run. Use the `--bin` option to
specify a binary, or the `default-run` manifest key.
available binaries: import_user_cli, judou
```

**根因初判（开发员必读契约）**：`02-代码/src-tauri/Cargo.toml` 第 28~30 行 M5 D8 新增了

```toml
[[bin]]
name = "import_user_cli"
path = "src/bin/import_user_cli.rs"
```

显式声明后本 crate 有**两个 bin**：隐式的 `judou`（`src/main.rs`）+ 显式的 `import_user_cli`；而 `[package]` 段**没有 `default-run`** → `cargo run`（Tauri CLI 的 dev 命令用它）无法决定跑哪个，直接报错退出。

**影响面**：
1. **阻断本次人工测试**：M4 + TP-修复4/5 + M5 四包都还没真机验过，dev 起不来用户就无法测（这是当前唯一阻塞点）。
2. **历史误判需纠正**：TP-修复5 与 M5 的台账/说明把「dev 不可用」记成「本机无 MSVC」，实测不成立——rustc 1.99.1 与 VS 2022 BuildTools（含 VC.Tools.x86.x64）都在，`src-tauri/target/debug/judou.exe` 也存在（2026-11-06 23:25 编译产物）。真实原因就是上面的 bin 歧义。
3. **M7 发布链路风险**：`tauri build` 同样走 cargo 选 bin 的路径，同一歧义会在打包环节复现（本包不验 build，只登记）。

**修复方向初判**：`[package]` 加 `default-run = "judou"`（一行），不动 `[[bin]]`、不动 `src/bin/import_user_cli.rs`、不动任何 Rust 源码。

**若修复与初判不符**（如加 `default-run` 后仍报错、或发现还有第二处 bin 歧义），修复自测必须显式写「与 01 初判不符 + 新证据」，不得静默改口。

## 二、修复后应达到的效果

1. `npm run tauri dev` 能编译并**真的起窗**（日志出现 `Running `target\debug\judou.exe``，进程存活，窗口加载应用首页），用户可立即按 M4/M5 测试入口说明实测。
2. M5 门禁契约不被破坏：`import_user_cli` 仍能独立构建与运行（`cargo run --bin import_user_cli -- debug` 行为不变）。
3. 除 `Cargo.toml` 外零改动。

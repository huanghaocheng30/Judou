## 一、需求摘要与验收标准

**目标**：交付一个**能启动的句读骨架**：React + Tauri v2 工程、**19 张物理表（18 业务 + `schema_meta`）的本地库**、`ping` 命令链路、三档主题、句读图标上包、CI 空跑。**本包不写任何内容逻辑**。

| 编号 | 验收标准（可测） |
|---|---|
| AC1 | 应用可启动：`npm run build`（tsc + vite）exit 0；`cargo check` exit 0；启动后窗口标题含「句读」，首屏渲染导航壳（侧边栏 7 项）+ 骨架占位文案；无控制台错误 |
| AC2 | 本地库建成 **19 张物理表 = 18 张业务表 + 1 张元表**：业务表＝内容 9（`article`/`paragraph`/`sentence`/`token`/`question`/`blank`/`sentence_analysis`/`token_analysis`/`lexicon`）+ 用户 8（`sentence_note`/`word_note`/`vocab_entry`/`tag`/`vocab_tag`/`review_plan`/`review_log`/`reading_record`）+ 配置 1（`app_setting`）；元表 1＝`schema_meta`。19 张全部存在，`schema_meta` 记录 `version=1`；外键与索引按 §三 D2 清单建立 |

## 三、具体改动点（逐条可执行）

### D1 · 工程骨架（对应 AC1 / AC7）
- React 18 + Vite 6 + TypeScript；`@vitejs/plugin-react`；dev server 固定 **1420**（Tauri 约定）。
- Tauri v2：`tauri.conf.json` 设 `productName:"句读"`、**`app.windows[0].title:"句读"`**（AC1 窗口标题断言的唯一来源——Tauri v2 未配置 title 时默认 `"Tauri App"`，只设 `productName` 不会改窗口标题）、`identifier:"com.judou.app"`、窗口 1200×800、`resizable:true`。
- 路由：hash 路由（与原型一致：`#/today`、`#/library`、`#/article`、`#/review`、`#/vocab`、`#/import`、`#/records`、`#/settings`），**不引入 react-router**（`ponytail:` 注释注明：8 页 hash 路由够用，需要嵌套/守卫再引入）。**与 04 §八 的 `/articles/:id` 差异**：本包用扁平 `#/article`，M1 接入真实详情页时切为 `#/article/:id`（成本 1 处改路由表，已预先登记）。
- **消费接口**：无。**产出接口**：
  - ① `invoke_handler` 骨架：`lib.rs::run()` 内 `.invoke_handler(tauri::generate_handler![commands::ping, commands::get_settings, commands::set_setting])`；`main.rs` 只调 `judou_lib::run()`（不写业务）。供 D3 挂命令；
  - ② `src/shell/routes.tsx` 路由表 + 挂载点（供 M1~M6 注册真实页面）；
  - ③ `styles/tokens.css` 的**变量名清单与文件骨架**（浅/深两块占位，取值由 D4 填；同一文件按 D1→D4 顺序串行写，不并发改）；
  - ④ `tauri.conf.json` 基础配置（名称/identifier/窗口），`bundle.icon` 由 D5 追加。

### D2 · 数据库 schema 与迁移（对应 AC2）
- **19 张物理表 = 18 张业务表 + 1 张元表 `schema_meta`**（清单里 `schema_meta` 与 `app_setting` 都在）。
  **口径说明（避免二义）**：`04 §7.1` 标题写「合并后 18 表」是**业务表口径**，其表格含 `schema_meta` 共 **19 行**；分类口径见 `05 §十七.1`（内容 9 / 用户 8 / 配置 1），列定义见 `04 §7.3`（三张新增表）与 `docs/C2 §4.1~§4.15`（宿主 15 表）。

| 分类 | 表 | 关键列 |
|---|---|---|
| 元 | `schema_meta` | `key` PK, `value`（含 `version`） |
| 内容 | `article` | `id` PK, `source_key` UNIQUE, `title`, `source`, `exam_type` CHECK(`cet4`,`cet6`,`other`), `exam_year`, `exam_set`, `section_type`, `difficulty`, `word_count`, `visibility` CHECK(`system`,`user`), `status`, `created_at`, `updated_at` |
| 内容 | `paragraph` | `id`, `article_id` FK CASCADE, `idx`, `text` |
| 内容 | `sentence` | `id`, `article_id`, `paragraph_id`, `idx`, `text`, `text_hash`, `start_offset`, `end_offset` |
| 内容 | `token` | `id`, `sentence_id`, `idx`, `surface`, `normalized`, `lemma`, `start_offset`, `end_offset`, `pos` |
| 内容 | `question` | `id`, `article_id`, `idx`, `stem`, `options_json`, `answer`, `explanation` |
| 内容 | `blank` | `id`, `article_id` FK CASCADE, `blank_no` INTEGER, `answer_key`, `answer_word`, `reason`, `distractors`；`UNIQUE(article_id, blank_no)` |
| 内容 | `sentence_analysis` | `id`, `sentence_id` UNIQUE, 5 文本列 + 4 JSON 列（列名见 `04 §7.3`） |
| 内容 | `token_analysis` | `id`, `token_id` UNIQUE, 7 列（含 `is_cet4_high_freq` INTEGER，注意是 `cet4` 不是 `cet`；列名见 `04 §7.3`） |
| 内容 | `lexicon` | **`normalized` PK**（无代理 id，按冻结设计 `04 §7.3`）, `word`, `phonetic`, `pos`, `sense`, `lemma`, `collocations_json`, `examples_json`, `is_cet_high_freq`, `more_json` |
| 用户 | `sentence_note` | `id`, `sentence_id` UNIQUE, `translation`, `grammar_note`, `phrase_note`, `updated_at` |
| 用户 | `word_note` | `id`, `token_id` UNIQUE, `context_meaning`, `collocation`, `example`, `updated_at` |
| 用户 | `vocab_entry` | `id`, `normalized` UNIQUE, `surface`, `phonetic`, `pos`, `context_meaning`, `source_sentence_id`, `source_article_id`, `mastery` CHECK(`new`,`fuzzy`,`known`), `review_count`, `last_reviewed_at`, `created_at`, `updated_at` |
| 用户 | `tag` | `id`, `name` UNIQUE, `color` |
| 用户 | `vocab_tag` | `vocab_id`, `tag_id`, PK(vocab_id,tag_id) |
| 用户 | `review_plan` | `article_id` PK, `next_review_at`, `interval_index`, `status` CHECK(`active`,`paused`,`done`) |
| 用户 | `review_log` | `id`, `article_id`, `reviewed_at`, `interval_index`, `result` |
| 用户 | `reading_record` | `article_id` PK, `last_position`, `duration_sec`, `completed`, `last_read_at` |
| 配置 | `app_setting` | `key` PK, `value` |

- **`blank` 级联溯源**：`04 §7.4` 的级联清单未列 `article→blank`（`blank` 是我方新增表，不在 docs C2 的 15 表内），本包按「文章子表统一 CASCADE」补齐 `article_id FK CASCADE`——否则删文章会留孤儿行；M1 迁移若严格对齐冻结设计再登记债务。
- 索引：`article(exam_type, exam_year, section_type)`（04 §7.2 原口径）**与** `article(visibility, exam_type, exam_year, section_type)`（列表默认按「内置/我导入」分组）各建一条、`sentence(paragraph_id, idx)`、`token(sentence_id, idx)`、`vocab_entry(normalized)`、`review_plan(status, next_review_at)`。
- **UNIQUE 隐式索引**：`sentence_analysis(sentence_id)`、`token_analysis(token_id)`、`lexicon(normalized)` 已由 `UNIQUE`/`PK` 约束在 SQLite 自动建索引覆盖（对应 04 §10.3 的性能索引），**无需重复显式建索引**。
- 迁移：`db.rs` 启动时读 `schema_meta.version` → 顺序执行 `migrations/00N_*.sql`（本包只有 001）；执行后写回 version。**已发布的 001 不得修改**。
- 默认数据：只写 `app_setting` 的 `theme='system'` 与 `guide_shown='0'`（幂等：`INSERT OR IGNORE`）。
- **消费接口**：无。**产出接口**：① 连接与迁移 API（供 M1 导入）；② `app_setting` 读写（供 M6 设置）。

### D3 · `ping` / 设置命令与 api.ts（对应 AC3）
- Rust：`#[tauri::command] fn ping() -> PingResult { pong:true, appVersion: env!("CARGO_PKG_VERSION") }`；`get_settings() -> HashMap<String,String>` 与 `set_setting(key, value)`（命令名对齐 `docs/C3 §5.8`：**`get_settings` 是复数**，返回全量，前端自取 `theme`）；三者都注册进 `invoke_handler`。
- 前端：`src/lib/api.ts` 导出 `ping()` / `getSettings()` / `setSetting()`；`App.tsx` 启动时调一次 `ping()` 并在控制台打印结果（用于取证）。
- **禁止裸 `invoke`**：除 `api.ts` 外任何 `.ts/.tsx` 出现 `invoke(` 即返工（脚本断言）。
- **消费接口**：① D1 的 `invoke_handler`（命令注册点）；② **D2 的 `Db` state**（`tauri::State<Db>`，内部 `Mutex<Connection>`）与 `app_setting` 读写函数——`get_settings`/`set_setting` 全靠它落地。**产出接口**：`api.ts` 的封装模式（后续所有命令照此，M1 起不得绕过）。

### D4 · 主题系统（对应 AC4）
- `styles/tokens.css`：D1 已建变量名清单与浅/深骨架，**D4 在 D1 之后串行填取值**（纸底/墨/靛蓝/玫红/陶土橘/线色，取自原型 v2）。
- `ThemeProvider`：读 `app_setting.theme` → 在 `<html data-theme>` 上应用；`system` 模式监听 `matchMedia`。
- 设置页：三段控件（浅/深/跟随）→ 调 `set_setting('theme', v)` → 立即生效。
- **只经 `api.ts`**：`ThemeProvider` 调 `getSettings()`/`setSetting()`，不直连 `db`、不裸 `invoke`。
- **红线注解**：`theme` 属**应用设置状态**（UI 偏好），不是 docs D1 §11.8 禁止的「用 `useState` 缓存数据库业务数据」；M1 引入查询层后统一口径（本条预先写入，避免代码审查误判）。
- **消费接口**：D2 的 `app_setting`（经 D3 的 `api.ts`）；**产出接口**：`useTheme()` hook + CSS 变量取值（供全部页面）。

### D5 · 应用图标流水线（对应 AC5）
- 源图：`01-设计/CET4-阅读精读/原型-v2/icon/句读-选定-1024.png`（**只读引用，拷入 `02-代码/` 后再生成**）。
- 执行 `npx tauri icon <源图> -o src-tauri/icons`，产出全套（32/128/128@2x/256/512、`icon.ico`、`icon.png`）。
- `tauri.conf.json` 的 `bundle.icon` **列全 5 项**：`icons/32x32.png`、`icons/128x128.png`、`icons/128x128@2x.png`、`icons/icon.ico`、`icons/icon.png`（Tauri v2 的 `bundle.icon` 是字符串数组，多值合法）。**文件归属**：`tauri.conf.json` 由 D1 创建基础配置，**D5 在 D1 之后仅追加/修改 `bundle.icon` 一处**（串行，不并发改）。
- **验收注意**：`tauri icon` 会同时生成 Android/iOS 目录，本包保留（M7 用）；但 `bundle.icon` 只列**桌面**图标（上述 5 项），不引用 Android/iOS 目录下的产物。
- **消费接口**：图标源图（只读）+ D1 建的 `tauri.conf.json`；**产出接口**：`icons/` 全套 + 已配置的 `bundle.icon`（供 M7 打包）。

### D6 · CI 骨架（对应 AC6）
- **位置**：工作流必须放在**仓库根** `.github/workflows/ci.yml` 才生效；但仓库根不属于 `02-代码/`（本包目标代码区）。
  **处理（本轮裁定）**：文件写在 `02-代码/.github/workflows/ci.yml` 并在 `README.md` 注明「M7 收尾时移动到仓库根」；**本包不写仓库根**（越界）。AC6 的校验只验该文件存在 + YAML 可解析 + job 名齐全。
- 内容：`build` job 用 matrix 跑**三平台** `windows-latest`/`macos-latest`/`ubuntu-latest` → `npm ci` + `npm run build` + `cargo check`（Ubuntu 的 Linux 系统依赖按 Tauri 官方清单装，macOS 无需额外系统依赖，成本零）；Android job `if: false` 占位。**三平台依据**：01 §三 第 7 条 + `05 §十六.4`。
- **消费接口**：无；**产出接口**：CI 骨架（供 M7 启用）。

## 四、自测要求（每条 AC 至少一项机器可核证据；禁以截图/手工点选冒充）

> 证据三义务：真实命令 + 输出片段；证据文件非空壳（>0 B 且含锚点）；统计与逐项算术一致。人工观感归用户实测。

| AC | 手段 | 判据 |
|---|---|---|
| AC1 | ① `npm run build`（tsc + vite）；② `cargo check`（vcvars64 前置）；③ `npm run tauri dev` 启动日志（Vite 端口 200 / 进程存活 / 无 panic）；④ **窗口标题断言**：`Get-Process | Where-Object { $_.MainWindowTitle -match '句读' }` 返回 1 行（或 `lib.rs::run()` 启动时打印一次标题供日志取证） | ①② exit 0；③ 日志三条满足；④ 命中窗口 1 个；贴各段尾部 |
| AC2 | 启动后 `node -e` 用 `node:sqlite` 只读查 `sqlite_master` | **19 张表全部存在**（贴表名清单，与 AC2 的 18 业务 + `schema_meta` 逐项对上）；`schema_meta.version=1`；索引清单与 §三 D2（含两条 `article` 索引）一致 |
| AC3 | `grep` 断言 + 运行取证 | `.ts/.tsx` 中 `invoke(` 只出现在 `api.ts`（脚本输出 0 例外）；运行日志出现 `ping → {pong:true, appVersion:"0.1.0"}` |

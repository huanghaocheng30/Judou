## 一、模块总览与依赖方向

```
[内置内容包 JSON] ──→ M1 内容导入 ──→ [本地库(内容表)]
                                          │
[用户粘贴/TXT/MD] ──→ M10 用户导入 ──→ [本地库(用户文章)]  
                                          │
                                    ┌─────┴───────────────────────┐
                                    ▼                             ▼
                            M2 文章库与筛选               M3 精读渲染
                                                          ├─→ M4 句子解析卡
                                                          ├─→ M5 词卡 ──→ M8 生词本
                                                          ├─→ M6 题目与空格
                                                          └─→ M7 笔记
                                    ┌───────────────────────────┴───────┐
                                    ▼                                   ▼
                            M9 复习（依赖 M3 完成事件）        M11 记录与统计
                                    │                                   │
                            M12 导出与备份 ←──────── M8/M7/M9 ──────────┘
```

## 二、M1 内容导入（内置）

**输入**：`content-pack/manifest.json` + 12 篇 `cet4-2023-12-*.json`（随安装包分发，`bundle.resources` 映射）。

**输出**：内容表 9 张（`article`/`paragraph`/`sentence`/`token`/`question`/`blank`/`sentence_analysis`/`token_analysis`/`lexicon`）+ `schema_meta.pack_version`。

**关键规则**
1. **单一版本权威**：`manifest.packVersion`；篇内残留 `packVersion` 不入库、不参与比较；`article.pack_version` 写 manifest 值。
2. 版本相等 → 直接返回 `{imported:0, skipped:N, elapsedMs}`，**不做任何写入**。
3. 不等 → **单事务** upsert；`source_key` 已存在只更新内容字段；失败回滚（旧版本仍可用）。
4. **绝不写**用户 8 张表（`sentence_note`/`word_note`/`vocab_entry`/`tag`/`vocab_tag`/`review_plan`/`review_log`/`reading_record`）。
5. `ImportReport` 含 `elapsedMs`（覆盖整段导入）。
6. 内容包缺失/损坏 → 返回 `StartupError::PackMissing/PackCorrupt{file}`，不 panic。

**建表落点（9 张内容表字段来源）**
| 表 | 权威字段来源 | 本模块写入要点 |
|---|---|---|
| `article` | docs C2 §4.2 + `exam_type` | 从 `meta` 映射：`title/source/exam_year/exam_set/section_type/word_count/visibility='system'`；`exam_type` 由 `sourceKey` 前缀或 manifest 声明（`cet4`） |
| `paragraph` | docs C2 §4.3 | `idx` 从 0 |
| `sentence` | docs C2 §4.4 | `start_offset/end_offset` **相对段落**（内容包 `sentence.start/end` 已按此口径）；`text_hash` = sha256(text) 前 16 位 |
| `token` | docs C2 §4.5 | `start_offset/end_offset` **相对句子**；`lemma`/`pos` 留空（ADR-009） |
| `question` | docs C2 §4.6 | `options_json` 存 `[{key,text}]`；`explanation` 存 `blanks` 的 reason（若该题对应空格），否则空 |
| `sentence_analysis` | 我方增量 | 九字段：`translation_literal/translation_natural/struct_markup/structure_summary/paragraph_role` + `components_json/clauses_json/phrases_json/pitfalls_json` |
| `token_analysis` | 我方增量 | 七字段：`phonetic/pos/sense_in_context/collocations_json/examples_json/is_cet_high_freq/more_json`（213 行，`is_cet_high_freq` true 166 / false 47） |
| `lexicon` | 我方增量 | 12 篇切片合并去重（**1561 行**）；`collocations_json`/`examples_json`/`more_json` |
| `blank` | 我方增量 | 30 行；`distractors` 有的篇是字符串、有的篇是数组 → **归一为 JSON 字符串**，读取侧两形态都接受 |

**索引**（本模块建立）：`article(visibility, exam_type, exam_year, section_type)`、`paragraph(article_id, idx)`、`sentence(paragraph_id, idx)`、`token(sentence_id, idx)`、`sentence_analysis(sentence_id)` UNIQUE、`token_analysis(token_id)` UNIQUE、`lexicon(normalized)` PK、`blank(article_id, blank_no)` UNIQUE。

**验收点**：12/90/274/6699 + 274/213/1561/30；二启 skipped 且库未写；删库可重建。

## 三、M2 文章库与筛选

**输入**：`article` 表。
**输出**：两分组列表 + 筛选器选项 + 搜索。

**关键规则**
1. 一级分组按 `visibility`：`system`（内置）/ `user`（我导入的）；**空分组显示引导**（「还没有导入材料 → 去导入」）。
2. 筛选器：考试类型（`exam_type` 去重）/ 年份（`exam_year` 降序）/ 题型（`section_type`）/ 来源；筛选条件为 AND，多选值之间 OR；**筛选状态写 URL query**（刷新/返回保持）。
3. 搜索：标题模糊（`LIKE %kw%`，`escape` 处理 `%_`）；不做全文检索（句级搜索留后续）。
4. 卡片五项字段：篇名 / 年份 / 题型 / 词数 / 句数（`sentence` 聚合或 `article` 冗余列，取冗余列以避免 N+1）。
5. 键盘：卡片可 Tab 聚焦、Enter 进入；筛选器为原生 `select`/`button group`，不自定义下拉陷阱。

**命令**：`list_articles(filter)`（docs C3）+ `list_article_filter_options()`（本方案增量）。

**验收点**：12 篇五项字段与 manifest 一致；筛选组合正确；空分组引导出现；URL 带筛选参数可复现。

## 四、M3 精读渲染

**输入**：`article` + `paragraphs[]` + `sentences[]` + `tokens[]`（`get_article_content`）。
**输出**：可交互正文 DOM + 题目区锚点。

**关键规则**
1. 逐段渲染，段内逐句；句内按 token 的 `start/end` 切「文本片段 / 词 / 空格」三类节点，**顺序与偏移严格对齐**（内容包已保证）。
2. **空格判定三条件**：`token.is_word === false` 且 `surface` 匹配 `/^\d+$/` 且 `Number(surface) ∈ blankNos`。**正文固有数字（150/1997/88,000）不得判为空格**（已实测等价校验：漏判 0 / 多判 0）。
3. 节点属性：词节点 `data-token-id`/`data-n`（normalized）/`data-start`；空格节点 `data-blank-no`；**不得改名**（TP2/TP3/TP4 后续接管与测试依赖）。
4. 点词不触发点句（`stopPropagation`）；句子命中区为词间空白与句末。
5. 宽屏右侧解析栏、窄屏底部抽屉（≤55% 视口，Esc 关闭，可拖动）。
6. 用户导入文章（无解析）：正文仍可点句点词，解析区显示「该篇无预置解析，可写笔记」。
7. 渲染必须走**纯函数** `renderTokens(text, tokens, blankNos) -> TokenNode[]`（不依赖 DOM），供 node 断言与 React 组件共用。

**验收点**：6699 token 切片逐字一致；空格/数字不误判；长文（58 句）滚动不卡；返回有反应。

## 五、M4 句子解析卡（六段式）

**输入**：`sentence_analysis` 一行。
**输出**：六段式卡片。

**关键规则**
1. 段序固定：①翻译（直译 + 顺译）②主干/成分划分 ③从句与语法点 ④重点短语 ⑤易错点 ⑥段落作用。
2. `struct_markup` 里的符号**渲染为视觉样式而非丢弃**：`【】`主语（蓝色 + 轻底色）、`_ _`谓语（下划线）、`~ ~`宾语/表语（波浪线）、`{}`从句（保留花括号）、`()`短语/分词（保留圆括号）。深色模式下对比度可辨。
3. 缺字段 → 该段显示「本段暂无解析」，不报错、不空白。
4. 整句无行（用户导入）→ 卡片头显示「该篇无预置解析」，仅保留笔记入口。
5. 默认展开前两段（翻译、成分划分），其余折叠（裁决 #9 沿用）。

**命令**：`get_sentence_analysis(sentenceId)`。
**验收点**：274/274 句都能出卡；符号样式在深浅两主题下可辨；缺字段降级正确。

## 六、M5 词卡

**输入**：`token.normalized` → `token_analysis`（语境义）→ `lexicon`（通用义）。
**输出**：词卡（音标/词性/释义/搭配/例句/更多/收藏/笔记）。

**关键规则**
1. **降级链路固定**：本句语境义 → 词库通用义（标题「词义（通用）」）→ 「暂无预置解析」（**仍可收藏**）。
2. `more`（词根/近义/易混）默认折叠，点「更多」展开。
3. **数组与字符串两形态兼容**：`more.synonyms`/`more.confusables`/`collocations`/`examples`/`blanks.distractors` 可能是数组或字符串，渲染层两种都接受（逐项换行或顿号连接）。
4. 收藏：同 `normalized` 已存在则提示「已在生词本」，不重复插入；收藏即写 `vocab_entry`（带 `source_token_id`/`source_sentence_id`/`source_article_id`）。
5. 词条不存在 → 不留空白卡片、不报错。

**命令**：`get_token_analysis(tokenId)` / `lookup_lexicon(normalized)` / `add_vocab_from_token(tokenId)`。

**验收点**：`provoke`（语境义）、`teenagers`（通用义）、`the`（降级）三样本正确；数组/字符串两形态都渲染成功。

## 七、M6 题目与空格

**输入**：`question` + `blank` + `blankNos`。
**输出**：题目折叠区 + 空格解析卡。

**关键规则**
1. 原文在上、题目在下，默认折叠；页头显示题号范围作为入口。
2. **选项不可点选**、不显示对错、不做计分（ADR-012）；「显示答案」只显示答案字母。
3. 选词填空：正文空格编号（26~35）可点 → 三段式：正确答案（词 + 词库字母）/ 为什么是它 / 易错与排除（**逐条换行**）。
4. `distractors` 字符串形态按 `、` 或换行拆条；数组形态逐项。
5. 长篇阅读的信息匹配题（10 题）与仔细阅读（5 题）共用同一渲染，仅题干差异。

**命令**：`get_blank_analysis(articleId, blankNo)`。

**验收点**：30 空全部可点且内容正确；排除项逐条一行；选项点击无反应。

## 八、M7 笔记

**输入**：用户输入（句笔记 / 词笔记）。
**输出**：`sentence_note` / `word_note` 行。

**关键规则**
1. 防抖 **800ms** 自动保存；页面卸载/切换前 flush。
2. 保存失败：保留草稿、显示重试提示、下次输入重试；**不得静默丢**。
3. 空内容 = 删除该行（不留空行）。
4. 笔记与解析**分层显示**：解析区只读（来自内容包），笔记区可编辑（用户数据），视觉上区分来源。
5. 用户导入文章同样可写笔记（无解析但有笔记）。

**命令**：`get_sentence_note/get_word_note` + `upsert_note(targetType,targetId,content)`（docs C3）。

**验收点**：输入停止 800ms 后落库；重启后仍在；空内容删除行；失败重试不丢字。

## 九、M8 生词本

**输入**：`vocab_entry` / `tag` / `vocab_tag`。
**输出**：列表（三种分组轴）+ 编辑 + 点回原句 + 导出入口。

**关键规则**
1. 按 `normalized` 聚合，一词语一条；`surface` 保留首次加入形态。
2. 三种分组轴：按文章（`source_article_id`，NULL 归「来源已删除」）/ 按标签 / 按掌握状态（new/fuzzy/known）。
3. 编辑：语境释义、搭配、例句、音标、词性、掌握状态、标签增删。
4. 点回原句：跳精读页并定位到 `source_sentence_id`（滚动 + 高亮 2s）。
5. 来源文章删除 → `SET NULL`，生词保留（docs 级联规则）。

**命令**：`list_vocab(groupBy)` / `add_vocab_from_token` / `delete_vocab` / `list_tags` / `delete_tag`。

**验收点**：同词两句只一条；标签筛选正确；点回定位准确；删除文章后生词仍在。

## 十、M9 复习

**输入**：`review_plan` / `review_log`。
**输出**：今日待复习列表 + 复习模式。

**关键规则**
1. 建计划时机：文章**首次标记完成**（`reading_record.completed=1`）时建 `review_plan`，`next_review_at = 今天 +1d`，`interval_index=0`，`status='active'`。
2. 完成一次复习：`interval_index+1`（0→1→2→3），`next_review_at += [1,3,7,14][index]`；`index=3` 完成后 `status='done'`。
3. 今日待复习：`status='active' AND next_review_at <= today`；角标数同步到侧边栏/Tab。
4. 复习模式**复用精读页**（同一组件，`?mode=review`），隐藏「已读」标记，底部固定「完成本次复习」。
5. `review_log` 记 `article_id`/`reviewed_at`/`interval_index`/`result`。
6. 间隔档位来自 `app_setting`（默认 `[1,3,7,14]`，本期只读展示，不允许用户改——改档位引发数据不一致，留后续）。

**命令**：`get_due_reviews` / `complete_review` / `get_review_logs`。

**验收点**：首次完成生成计划；到期出现在今日；完成一次顺延一档；第 4 次后不再提醒。

## 十一、M10 用户导入

**输入**：粘贴文本 / TXT / MD 文件。
**输出**：`ImportPreview` → 用户确认 → 入库（`visibility='user'`）。

**关键规则**
1. **两阶段**：`parse` 只算不写；`commit` 校验通过才写（docs C4 §2）。
2. 清洗：去 BOM、统一 `\n`、去行尾空白、合并 3+ 空行为 1（保留段落语义）。
3. 分段：按空行；连续非空行视为同段。
4. 切句：终止符 `.`/`!`/`?`/`;`（`;` 可选）+ 缩写排除表（Mr./Dr./e.g./i.e./U.S. 等，docs C4 §6.3）+ 数字小数点不切 + 引号内不切。
5. 分词：字母序列为词，其余为标点；`normalized` = 小写 + 去首尾非字母数字 + 保留词内撇号与连字符；数字序列为独立 token（`is_word=false`）。
6. **四层校验**（docs C4 §8）：L1 结构（字段齐全/非空）/ L2 偏移（UTF-16 切片等于 `surface`）/ L3 覆盖（token 覆盖句子全字符，间隙仅空白）/ L4 业务（标题非空、句数 ≥1、字数上限 20000）。
7. 预览页可改标题、剔除段落、选考试类型（默认 `other`）与年份（默认空）。
8. 导入文章的**降级形态**：无解析、无题目；精读页保留点句/点词定位与笔记。

**命令**：`parse_import_text(text) -> ImportPreview` / `commit_import(payload) -> {articleId}`（docs C3）。

**验收点**：500 词材料 <10s 入库；四层校验能拦截脏文本；预览可剔段；入库后出现在「我导入的」。

## 十一之二、M10b AI 解析导入（v2.1 增量，M5b）

**职责**：复用 M10 的原文解析产物（段落/句子/词/偏移），把外部 AI 的语义产出（逐句解析 / 题目答案 / 词条）对齐合并入库。**不负责切句与偏移**——那是 M10 的职责，且偏移只由 Rust 侧算一次，AI 产出的任何数字都不采信。

**数据流（5 个命令 + 1 个后补命令）**

| 命令 | 职责 | 是否写库 |
|---|---|---|
| `build_ai_prompt(draft, batchSize)` | 生成提示词模板 + 本批句子清单（`S编号` + 原文前 24 字符）+ 题型片段 | 否（纯字符串） |
| `parse_ai_payload(text)` | 容错解析：剥 ```` ```json ```` 包裹与前后说明，只取最外层 `{}`，丢弃任何 `start`/`end`/`offset` 字段 | 否 |
| `match_ai_payload(draft, payload)` | 按 `quote` 规范化匹配句子 → `matched[]` / `unmatched[]` / 覆盖率（解析·题目·词条三档独立） | 否（纯函数） |
| `commit_ai_import(draft, matched, meta)` | 单事务写入 article/paragraph/sentence/token + **可选** sentence_analysis/question/lexicon；`visibility='user'`、`source_key='user-{uuid}'` | 是 |
| `patch_ai_analysis(articleId, matched)` | 给已入库文章**增量补**解析/题目/词条；只写这三类表 | 是 |
| `get_ai_import_stats(articleId)` | 覆盖率回读（解析 x/y 句、题目 x/y、词条 n） | 否 |

**关键约束（违反即返工）**

1. **偏移与分词只在 Rust 侧算一次**（复用 `import_user.rs` 既有实现），AI 产出中的偏移字段一律忽略。
2. **quote 匹配规范化**：小写 + 折叠空白 + 去首尾标点；同一 draft 内按句子顺序取第一条未占用的句子；匹配失败进 `unmatched[]` 由用户处置（跳过 或 重新生成该句），不得静默丢弃。
3. **允许不完整**：解析 / 题目 / 词条任一缺失都能入库；覆盖率独立显示。
4. **拒收条件**：JSON 不可解析 / 题型与题目形态不符（careful 4 选项、long `options:[]`+字母、cloze 15 库项+空号）/ `structMarkup` 括号或 `_`、`~` 不成对且用户未选「跳过该句」/ 编造答案（`answer` 非 null 但不在词库或段落字母范围内）。
5. **用户数据零触碰**：并入只写内容表；`sentence_note`/`word_note`/`vocab_entry`/`review_plan`/`reading_record` 一律不动。
6. **原文稳定**：`patch_ai_analysis` 不改 `paragraph`/`sentence`/`token`（笔记与生词引用不失效）。

**验收点**

- 粘原文 → 提示词可复制且含全部句子锚点；分批上限 15 句生效
- 粘回 42 句解析 → 覆盖率 42/42 → 入库成功
- 只给 20 句 → 覆盖率 20/42 → 仍可入库，其余句显示「该句暂无解析」
- 后补：已入库文章再补 10 句 → 30/42，原文结构与已有笔记不变
- 三种题型样例各一份都能通过（careful / long / cloze）

## 十二、M11 记录与统计

**输入**：`reading_record` + 聚合查询。
**输出**：记录时间线 + 统计卡。

**关键规则**
1. 阅读进度：进入精读页记 `started_at`，离开更新 `last_position`（段落 idx + 句 idx）、`duration_sec` 累加。
2. 完成判定：用户点「完成精读」→ `completed=1`，触发 M9 建计划。
3. 统计项：篇数（总/已完成）、总时长、笔记数、生词数、复习次数、**连续天数**（按 `reading_record.last_read_at` 的日期序列算，允许今天未读则算到昨天）。
4. 统计不做缓存表（数据量小，现算）；单次查询 <50ms。

**命令**：`get_reading_records` / `get_stats`。

**验收点**：数字与库内真实计数一致（可复算）；连续天数算法有单测（含跨月/断档）。

## 十六、M15 发布链路

**输入**：构建产物。
**输出**：Windows NSIS 安装包 + Android APK + 更新清单。

**关键规则**

**验收点**：安装包 <30MB 且安装态内容包可读；更新检查在无网时不报错；CI 绿灯。

## 十七、跨模块约束（违反即返工）

1. **物理分表**：内容表 9 张 / 用户表 8 张 / 配置 1 张；导入只写内容表，笔记生词复习只写用户表。
2. **偏移口径 UTF-16**：所有 `start/end` 一律 UTF-16 code unit（ADR-008）；跨语言（Rust/JS）转换必须显式。
3. **前端只经 `api.ts`**：React 组件禁止裸 `invoke`；每个命令在 `api.ts` 有一层薄封装（TypeScript 类型来自 `types.ts`）。
4. **解析只读**：`sentence_analysis`/`token_analysis`/`lexicon`/`blank` 由内容包写入，运行期**只读**，任何用户操作不得改这四张表。
5. **纯函数分层**：`renderTokens` / 解析卡字段映射 / 降级链路判定 / 复习间隔计算 —— 全部做成纯函数（可 node 断言），React 组件只负责渲染与事件。
6. **错误结构统一**：`{code, message}`；前端按 `code` 决定提示文案与修法，不靠 `message` 字符串匹配。
7. **无障碍底线**：可 Tab 聚焦、焦点可见、颜色非唯一通道、抽屉 Esc 可关。
8. **无网可用**：除 `check_update` 外不得发起任何网络请求；`check_update` 失败必须静默。

## 0. 一页结论（供调度员快读）

1. **星火英语的商业重心是「教辅出版 + 课程」，App 是纸质书的数字配套入口**，不是独立阅读产品：官方图书资源站把「本书配套电子试卷，在星火英语 App 图书配套板块免费获取」写成卖点，App 简介第一条功能就是「图书配套（扫码获取配套音频/视频、支持离线下载）」。[事实]
2. **它的解析形态是「应试导向」而非「语言点导向」**：纸书侧写明「总结考点，揭示命题规律」「阅读答案划线点评，从定位到解析」——即**逐题定位式解析 + 整篇全文翻译**，目标是「培养答题技巧」。[事实，来源为官方图书详情页]
3. **App 侧的解析入口挂在「提交试卷 → 成绩报告 → 查看解析」之后**，即**先作答、后看解析**；答题是「左滑翻题、点选项自动跳下一题」的全屏模考形态。[部分，来源为第三方操作教程，非官方一手]
4. **没有取得任何「点句→句级解析」或「逐句可点」的证据**；语法拆解、短语/固定搭配单独列出这两项**证据不足**，但书侧文案的关键词（考点/命题规律/答题技巧）强烈提示其解析不以此为主。[推断]
5. **对本项目最关键的三条**：①「不做判分」恰是它与本产品的分水岭，不要照抄模考流程；②「全文翻译 + 划线点评」的信息顺序（翻译→点评→定位）与我们「句译→语法→短语」的排布同源，可借其阅读习惯；③体积是反面教材（App 114.8–124.8MB，图书资源包另有 157–540MB），本项目 <30MB 指标要求解析 JSON 必须按句/词增量估算。[推断/建议]

## 2. 产品定位、目标用户、核心流程

### 2.1 定位

- **公司业务结构**：星火英语是「教辅出版（图书）+ 培训课程 + 数字服务」三位一体的教育出版机构，App 属于第三条腿「数字服务」的承载物。[事实，S1 导航 + S2 版权方]
- **App 的第一身份是「纸质书的配套工具」**：官方图书详情页把「配套电子试卷在 App 免费获取」写入内容简介作为购买理由；App 简介功能列表第 1 条即「图书配套：获取黑旋风试卷配套音频，免费观看配套名师讲解视频，支持离线下载」。[事实，S2 + S5]
- **绑定链路是「扫码 + 图书代码」双层**：纸书印二维码（FAQ 提到「扫码的二维码与 App 学段匹配」），资源站另以「图书代码」（DSQDG253 / DSTS263 / DSQM253）标识每册书。[事实，S2/S3/S4 + S7]
- **不是纯粹的阅读器**：没有「阅读器」定位的迹象，阅读只是五大专项（单词/听力/阅读/翻译/写作）之一。[事实，S7 提分练习]

### 2.2 目标用户

- 名称口径：**每年 500 万四六级考生**（应用宝简介与下载站文案一致）。[事实/营销口径]
- 用户画像推断：以「要考试、要提分、要刷题」的在校生为主，使用动机是**应试**而非**语言习得**。[推断，据全站文案关键词「提分」「考点」「命题规律」「答题技巧」]
- 与本产品目标用户的差异：本产品用户是「做完一篇想真正吃透」的复盘型用户；星火用户是「要练、要测、要看分数」的应试型用户。**两者在「做完之后」这一刻重叠，但星火在那一刻提供的是「对答案+看技巧」，本产品提供的是「逐句读透」**。[推断]

### 2.3 核心流程（可考证的部分）

**流程 A · 图书配套（星火的主入口）** [事实，S2/S5/S7]
1. 购书 → 2. 扫书上的二维码（或输入图书代码登录下载）→ 3. App「图书配套」板块获取音频/讲解视频/电子试卷 → 4. 支持离线下载，离线收听/观看。

**流程 B · 智能模考（与「真题 + 题目 + 答案 + 解析」直接相关）** [部分，S6 第三方教程]
1. 首页「智能模考」→ 2. 选四级或六级真题 → 3. **左滑开始答题，点选项自动进入下一题**（全屏、一次一题、无原文常驻视野）→ 4. 全部答完「提交试卷」→ 5. **成绩报告** → 6. 点「查看解析」看错题 → 7. 不满意可「再做一遍」。

**流程 C · 专项练习** [事实，S5/S7]
五大专项（单词/听力/阅读/翻译/写作）分项练 → 生成「能力报告」（五大专项能力评估）。

> **流程 B 的关键结构含义**：解析是**判分的下游**，不是阅读的同层。用户必须先答完、交卷、看报告，才能触达解析。这与本项目「打开即读、点句即解析、不做判分」在信息架构上是**相反方向**。[推断，据 S6 步骤 + S5 无「阅读器」定位]

## 4. 交互模式

逐条回答清单的四个关注点；证据不足处直说。

### 4.1 题目与答案的折叠方式

- **App 侧**：[证据不足]。未取得 App 内题目/答案/解析页的排版描述或可读截图文本。可证的只有流程：答题时**答案不显示**（点选项即进下一题，不存在对答案环节），交卷后才在成绩报告与解析里出现答案与错题解析。[部分，S6]
- **纸质书侧**：[事实] 解析以独立册/独立板块承载（「《5套标准模拟》和《集训刷题卷》胶订成册」S2），答案与解析在书末或别册，正文页**不即时给答案**。
- **对本项目的含义**：星火把「答案不可见」做成**流程约束**（必须交卷），本产品要做成**UI 约束**（选项不可点 + 答案默认折叠）。这是同一目的的两种实现：前者靠流程，后者靠排版。本产品更轻，但风险是用户会误以为「选项可以点」——需要在视觉上明确「这是已作答的题，不是待做题」。[推断/建议]

### 4.2 解析入口位置

- **入口在「成绩报告」里，面向错题**（S6 第 5 步）。[部分]
- 也就是说解析入口**出现时机晚、出现位置深**：一次使用要经过「选卷 → 答完 N 题 → 交卷 → 看报告 → 点解析」。
- 与本产品对照：本产品解析入口是**原文每个句子**（点句即出），入口数量从「1 个/套卷」变成「N 个/篇」。这是最本质的交互差异。

### 4.3 逐题解析还是逐句解析

- **可证的是逐题（定位式）**：「阅读答案划线点评，从定位到解析」——按题号回原文划线定位，再讲为什么。[事实，S2]
- **同层还有「整篇全文翻译」**：不是逐句可点，是整篇给译文。[事实，S2]
- **逐句解析：[证据不足]，且无正向线索**。若星火 App 有逐句功能，其官方文案（图书详情、App 简介、FAQ）几乎不可能一次都不提；三处文案都只提「全文翻译/考点/技巧」。因此**「星火没有逐句解析」是较强推断**。[推断]

### 4.4 原文与题目：分屏还是分页

- **App 侧**：[证据不足]。
- 唯一可用的结构线索：答题是「左滑翻题、一次一题」——手机上一屏一题，**题干与原文必然分页**（否则无法在一屏内同时容纳四级长篇阅读原文与 4 个选项）。四级阅读一篇原文约 300–400 词，手机竖屏不可能与题目并置。[推断，据 S6 交互 + 常识]
- 桌面/平板侧：无证据。
- **对本项目的含义**：本产品「手机点句→底部抽屉、桌面→右侧固定栏」在移动端等价于「原文常驻 + 解析覆盖半屏」，比星火的「原文/题目全屏切换」少了来回跳转次数——这正是需求文档成功指标 1（点开一篇文章到看见第一句解析 ≤2 次点击）能成立的结构前提。[推断]

1. **「内容—纸书—App」三方闭环扎实**：扫码 + 图书代码 + 离线下载，把已经付过钱的纸书用户零成本导进 App，获客成本极低。[事实，S2/S5/S7]

## 9. 对本项目启示（逐条标注：事实 / 推断 / 建议）

1. **[事实]** 星火英语 App 的解析入口挂在「提交试卷 → 成绩报告 → 查看解析（错题）」，其产品结构把解析定义为判分的下游。
   → 本产品不可沿用该结构；解析必须挂在句子层（同层可点）。

2. **[事实]** 其纸质解析的内容骨架是「阅读文章附全文翻译 + 阅读答案划线点评 + 从定位到解析」，方法论语汇是「总结考点、揭示命题规律、答题技巧」。
   → 主流产品的解析粒度停在「逐题 + 整篇译文」，**没有**「逐句拆解 + 句内语法 + 句内搭配」的成熟形态。

3. **[推断]** 因此本项目要做的「点句出句译/语法/短语 + 点词出语境义」在四六级真题类产品里**没有可直接抄的交互范式**——这既是差异化空间，也意味着交互要自研、没有现成参照，评审时不能用「别家也这么做」背书。

4. **[推断]** 星火的词汇路径（1450 高频词自测、按词频排列）与本产品的「语境义」是**两种教学假设**的竞争：前者赌「高频重复」，后者赌「语境绑定」。产品文案与引导语应明确站后者，否则用户会用「这不就是背单词 App」来理解它。

5. **[事实]** 体积对比：星火 App 114.8–124.8MB，单册图书资源包 157.65–539.89MB；本产品指标 <30MB。
   → **[建议]** 在 04 方案里补一条体积估算：每篇 ≈ N 句 ×（句译 ~60 字 + 语法 ~150 字 + 短语 ~4 条）+ 每句重点词 M 个 ×（语境义 ~40 字 + 例句 ~80 字）；按 24 篇估算总量，若超 30MB 需裁剪字段或分层加载（首屏只要句译+句法摘要，展开再取全量）。

6. **[建议]** 抽屉内信息顺序固定为「句译 → 语法结构 → 短语/固定搭配」，词页为「语境义 → 音标/词性 → 搭配/例句」——与纸书「翻译 → 点评 → 定位」的既有认知顺序同源（B2），降低用户学习成本。

7. **[建议]** 「不做判分」必须落到视觉：选项**不可点**且有明确标识（如置灰 + 「答案/解析见下」），否则用户会点、会期待反馈，形成「这 App 是不是坏了」的误解。这条应在任务包的 AC 里写成可测项（点选项无任何状态变化）。

8. **[建议]** 首启路径压到最短：无登录、无扫码、无引导页；直接进文章库（B6）。星火的扫码绑定是**为纸书存量用户服务**，本产品无此约束，抄它只会增加摩擦。

9. **[建议]** 内容包版本化（内容包独立版本号 + 启动幂等导入 + 版本不匹配可视化提示），借鉴其「资源与客户端解耦」思路（B5）；但**不做**在线增量更新（首版离线约束）。

10. **[证据不足 · 需补证]** 「解析够不够细」的真实用户反馈本轮未取得（应用宝评论正文被截断、知乎 403、小红书 404）。补证路径见 §5.3。**在补证前，不要在设计文档里写「用户普遍反馈解析不够细」这类论断**——目前它只是合理猜测。

11. **[证据不足 · 需补证]** App 内阅读解析页的实际排版（原文与题目是否分屏、解析是否可折叠、是否有整篇翻译入口）无一手证据；若要为 04 方案找参照，唯二路径是真机截图或应用商店截图的可读化。**不要据本文推断当事实使用。**

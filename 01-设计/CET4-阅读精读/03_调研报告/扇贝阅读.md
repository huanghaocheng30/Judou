## 二、产品定位、目标用户、核心流程

### 2.1 定位（来源 S1 官方文案，事实）

> 「扇贝阅读是一款专为备考人群、职场人士及终身学习者设计的英语阅读能力进阶 App，每日推送原汁原味的英语短文，还有 1000+ 英语原著……」

一句话定位：**内容驱动的英语阅读平台**——以「每日热文 + 英文原著 + 备考真题」为供给，把泛读和精读都承载在一个 App 里，用生词本/手帐/打卡把阅读沉淀成学习记录。

与本项目的关键结构差异（事实）：扇贝阅读是**在线 SaaS**（内容每日更新、账号体系、会员订阅），本项目是**离线单机工具**（预生成内容包 + 本地 SQLite，无账号无同步）。

### 2.2 目标用户（来源 S1）

| 用户群 | 原文依据 | 对应产品入口 |
|---|---|---|
| 四六级/考研/雅思备考生 | 「为大学四级、大学六级、考研、雅思……提供英语阅读一站式提升方案」 | 历年真题、考试同源文章、阅读专题、考纲词汇标注 |
| 职场人士 | 「更适合工作党、职场人利用碎片时间」 | FutureU 认知升级专栏、BookSpark 推书频道 |
| 长期英语学习者/原著爱好者 | 「1000+ 英语原著」 | 哈利·波特双语全套、牛津通识双语、有声书虫、经典名著 |

### 2.3 内容供给结构（事实，来源 S1）

1. **精选短文**：每日更新的全球热文，按话题分类（热点/科技/商业/科普/文化/生活/职场/教育/医疗），**难度标注清晰**。
2. **英文原著**：套装化（哈利·波特双语、迪士尼电影原著、大英百科、牛津通识双语、有声书虫、福尔摩斯…）+ 人文社科 + 经典名著。
3. **备考资源**：历年真题、考试同源文章、阅读专题；配套能力＝长难句讲解、词汇精讲、考纲词汇标注。
4. **专栏**：FutureU（500+ 双语深度长文）、BookSpark（500+ 图书精要，可听）。
5. **学习计划**：100+ 计划，可按难度/目标选，也可基于「阅读档案」定制。

## 四、交互模式（本节为重点）

### 4.1 逐句翻译的呈现位置

**事实**（S1 文案原文）：官方能力表述是「**全文**支持官方翻译，**中英对照**」——即翻译以**整篇/段落级对照**形式提供，配合一个整篇级别的开合；同一文案中，**句子级**的能力落在别处：「**长按句子**唤起 AI 讲解，复杂句式快速拆解」。

**事实**（S2 反证）：多条 1–2 星评论把「看译文」当作付费门槛（「没会员只能看纯英文版本」「看个文章翻译都要会员？」），说明译文是**一个整篇开关**（有译文 / 无译文），而不是按句触发的点查。

**推断（中可信）**：扇贝阅读**没有**「点一句 → 出这句的译文」的按句点查模式。它用两个不同的东西替代：
1. 整篇「中英对照」解决「整段看不懂」；
2. 长按单句 → AI 讲解解决「这句结构看不懂」（讲解里同时给词汇/短语精析，通常包含句意解释）。

**对本项目骨架的直接含义**：本项目的「点句 → 半屏抽屉出句译 + 语法 + 短语」在交互上是**扇贝没有做的形态**，不存在直接可抄的实现；可借鉴的是它用「不同手势承担不同粒度」来避免点击歧义（见 4.3）。同时要注意：扇贝用户对「译文收费」的强反感（§五）反过来证明——**按句点出译文必须是免费的一级能力、且一次点击就到位**，本项目「点击次数 ≤2、面板 <300ms」的指标方向正确。

### 4.2 生词点击与收藏路径

**事实路径（重构自 S1 文案 + S2 评论）**：

```
阅读页（纯英文/对照）
  → 单击单词  →  释义浮层或面板（含柯林斯词典词条）
  → 「加入生词本」（按钮位置未取证）
  → 生词本（跨产品词库，可与扇贝单词联动复习）
  → 另有「单词图示」类会员增值能力，点击时反复弹提示（用户强反感）
```

**事实**：单次点击即可查词（多条评论以「每点一个单词就弹提示」描述这一动作，反证 tap→释义是一步到位）；词典内容为「权威柯林斯词典」；生词本可「随时复习」。

**事实（摩擦点）**：评论「每次点一个单词，都要提示我单词图示功能结束了…每个单词单击后都要反复提示充会员，我不如看纯外刊」——**收藏路径被会员诱导打断**。这是可直接规避的反面样本。

**推断（中可信）**：生词本是与扇贝单词共用的**全局词库**（按词而非按句/按文章组织），因此**丢失「该词在这一句里的意思」这一上下文**——用户收藏后复习时看到的是词典义。这恰好是本项目 F3/F5 的差异化基础（语境义 + 生词按文章分组 + 点回原句）。

**对本项目骨架的含义（建议，非事实）**：点词不要跳页、不要新开浮层，应作为**句抽屉内的二级视图**（抽屉头部保持句子原文与句译，下方换成词卡），使「词义—句义」同屏；返回只回退一级；收藏动作放在词卡首屏可点处，且**不弹任何升级提示**（本产品无付费墙）。

### 4.3 移动端手势与点击命中（最值得借鉴的一条）

**事实（S1 文案原文）**：

- 「**生词即点即查**，加入生词本便可随时复习」→ **单击 = 词级**
- 「**长按句子**唤起 AI 讲解」→ **长按 = 句级**

**推断（高可信）**：这是**手势分层**设计——同一块文本上，轻点命中「词」，长按命中「句」。理由是英文正文里词与句的点击区域天然重叠（词是句的子区域），若都用「点」，则「点句子空白处」的目标太小、且难以让用户发现「点句」这一能力；用长按把句级能力分离出去，可以保证「点词」永远优先、零歧义。

**对本项目骨架的直接冲突（必须处理）**：

| | 扇贝阅读（事实） | 本项目已定骨架（裁定） | 冲突与解法（建议） |
|---|---|---|---|
| 点词 | 单击 | 点词 → 抽屉内切换到词卡 | 一致，无冲突 |
| 点句 | **长按**（不经点击） | **点击句子**（点句→抽屉出句译） | **冲突**：词在句内，点词必然先命中词。解法见下 |

**建议（供设计决策，非事实）**：

1. **命中优先级**：词级命中 > 句级命中。点击落在 token 上 → 词卡；点击落在**句内非词区域**（词间空格、标点、行尾空白、段尾）→ 句卡。
2. **补充触点（不依赖精确空白）**：句尾给一个**低视觉权重但可点**的句级入口（如句末标记点/行首序号）。理由是空格区在窄屏、中文标点混排、行折行处都极难命中——只靠「点空白出句译」在真机上会大量误触为词。
3. **长按保留给「句级快速预览」可选**（长按任一词或空白 → 直接出该词所在句的句卡），作为 2 的加速器，不作为主路径。
4. **明确禁用**：不要用「双击」做任何解析动作（与系统选词、浏览器缩放冲突）；不要在词卡上叠加任何推广/提示弹层。

### 4.4 笔记、划线与其他阅读器交互

**事实**：支持划线；短文末尾可写读书笔记（可被打赏/点赞）；文章底部读后感为公开 UGC 并被 AI 审核；段落之后有「小旗子」控件（评论原文「点那个段落后的小旗子，大概率卡死重启」——**推断**其语义为「标记/收藏本段」）。

**事实（缺失能力，来自评论诉求）**：

- 字号不可调/偏小（「希望设置更大的字体，老同志眼睛不好」「macOS 上使用字体太小」）→ 阅读器必须有字号档位。
- 无「冷启动恢复上次阅读位置」（用户明确建议「增加状态恢复功能」）→ 阅读器必须有位置记忆。
- 卡顿/卡死/闪退投诉密集（阅读中卡死、点笔记卡死、更新后卡死重启）→ 笔记写入与段落交互是性能/稳定性高危区。

### 4.5 桌面/多端

**事实**：官方标注「iPhone、iPad」「专为 iPad 设计。未针对 macOS 验证」；订阅说明走 iTunes 账户 → 苹果生态内购。评论中出现 macOS 使用反馈与字体过小问题 → 存在 Mac 端形态（可能是 iPad App 运行在 Apple Silicon 上，**推断**，未取证）。

**事实（站点结构）**：shanbay.com 页脚导航存在 Web 阅读入口 `/read/home/`，说明有 Web 形态；`web.shanbay.com/reading` 抓取失败，**Web 版布局与交互未取到实证**（缺口）。

**对本项目含义（建议）**：桌面「右侧固定栏」与移动「半屏抽屉」可以共用同一份内容组件，仅容器不同——扇贝没有可参考的桌面精读栏证据，此项按本项目自有判断落地。

## 五、优点 / 限制 / 用户反馈线索

### 5.1 优点（事实层）

1. **内容供给厚度**：每日热文 + 1000+ 原著 + 四六级/考研/雅思真题与同源文章，覆盖「泛读—精读—备考」三种诉求，一个 App 承载。
2. **点词体验基础打得对**：单击即查、内置柯林斯词典、一键入生词本，路径极短（一步出释义）。
3. **系统级难点词高亮**：文章重点词 + 各类考试难点词由系统标注，用户不必自己判断「该不该查」。

## 九、对本项目启示（逐条标注：事实 / 推断 / 建议）

1. **（事实）扇贝阅读没有「点句 → 出该句译文+语法+短语」这一形态**：它的句级能力走「长按 → AI 讲解」，整篇理解走「中英对照开关」。→ 本项目首版骨架是差异化形态，无直接竞品实现可抄，需自行验证可用性。
2. **（事实）点词即查已在成熟产品中被验证为一步式交互**（单击 → 释义），且用户能自然掌握。→ 本项目「点词 → 词卡」的交互成本假设成立，可放心推进。
3. **（事实）译文与句子解析收费会引发强烈负反馈**（样本中 11 条投诉指向收费墙）。→ 本产品「全离线、全功能可用」应作为显性卖点写进关于页/首启页。
4. **（推断，高）同一文本上「点词」与「点句」必须做命中分层**：扇贝用长按规避冲突，本项目已定「点句出抽屉」，若不处理命中优先级，真机上「想点句子却总点到词」「想点词却点到空白出句卡」会同时发生。→ 建议按 §4.3 采用「词优先 + 句级补充触点（句末标记/行首序号）」。
5. **（推断，高）本项目的最大隐性风险是「漏标」**：预生成内容包只覆盖已标注 token，扇贝「短语只能选预置项」的抱怨是同一机制的早期症状。→ 建议：①任意 token 可点；②未标注 token 明确提示「本句无该词解析」而非静默；③在内容包生成阶段做覆盖统计（每篇 token 覆盖率、每句必含句译与语法）并作为验收指标（呼应需求 §八 指标 3）。
6. **（建议）点词不离开句上下文**：词卡作为句抽屉的二级视图，抽屉头部常驻句原文 + 句译；返回一级回句卡。理由是用户点词的动机是「这句读不通」，脱离句义的词卡会退化成普通词典（正是本项目要否定的替代方案）。
7. **（建议）点词时高亮所在句（回应需求文档 Q2）**：理由有二——①用户在词卡里需要知道「这个词属于哪一句」；②高亮可承担「句卡→词卡→句卡」的返回锚点。扇贝无同类证据，按本项目自有判断做，成本低。
8. **（建议）桌面右侧固定栏与移动半屏抽屉共用一套内容组件**，只换容器与滚动策略；扇贝桌面侧无可用证据，不构成约束。
9. **（建议）首版就补两项「阅读器基本素养」**：字号档位 + 冷启动恢复上次阅读位置（扇贝缺失项，用户明确点名）。成本小、体验收益明确，与需求 §八 指标 6（笔记不丢）同属「不打扰阅读」范畴。
10. **（建议）生词本必须保留「句语境」**：扇贝生词本是全局词库、复习时丢上下文；本项目 F5 已定「按文章分组 + 点回原句」，应在 UI 上把这个差异显性化（生词条目显示「原句片段 + 本句释义」而非仅词典义）。
11. **（建议）不做任何运行时会员/推广/评分弹窗**，并写进验收标准（对应 N2）。本产品无商业模式，任何打断都是纯损失。
12. **（建议）内容质量要把关「翻译错误」这一具体投诉类型**（用户举出 state→stay 拼写错误、多处翻译错误）：抽检清单应包含**拼写与专有名词一致性**、**句译与原文语义等价性**两类检查项，而非只看「有没有解析」。

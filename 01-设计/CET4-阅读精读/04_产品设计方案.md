# 04 · 产品设计方案（CET4-阅读精读）

> 版本：v1.0　编制日期：2026-11-05　阶段：方案设计中　负责方：调度员

> 输入：`01_需求说明文档.md`（4 项裁决 + 6 项追加裁决）、`03_调研报告/`（LingQ / Readlang / 扇贝阅读 / 星火英语，四份齐备）

## 一、目标与非目标

**目标**：让四级考生做完一篇阅读后，在**同一个阅读界面内**完成精读复盘——点句子看句译+语法拆解+短语搭配，点单词看它**在这一句里的意思**，可收藏生词、可写一句笔记，全程离线。

**非目标（本版明确不做）**：做题作答与判分、运行时调用大模型、篇级复习提醒、PDF/HTML 导出、用户自助导入文章、账号与云同步、社交分享、支付。

**一句话取舍**：把「解析质量 × 打开速度」做到极致，功能面刻意收窄。宁可少一个功能，不让点一下等 3 秒。

---

## 二、用户角色与核心旅程

**角色**：单一本地用户，无登录、无权限分级，数据仅存本机。

**旅程 A · 精读一篇（主旅程）**

1. 打开应用 → 文章库（已内置文章卡片：标题 / 年份 / 题型 / 词数）
2. 点一篇 → 阅读页：顶部标题栏，正文分段，题目区默认折叠
3. 读到一个卡住的句子 → 点句末「析」→ 底部抽屉出句卡（句译 / 语法 / 短语）
4. 句里有个词不认识 → 直接点词 → 同一抽屉切换为词卡（本句释义 / 音标 / 搭配 / 例句）
5. 点「加入生词本」→ 按钮变为已收藏态
6. 需要记一笔 → 词卡/句卡底部的笔记框打字，停止输入 600ms 自动保存
7. 下滑关闭抽屉 → 回到原文同一位置继续读

**旅程 B · 回看生词**

生词本 → 按文章分组 → 每条显示「词 + 本句片段 + 本句释义」→ 点一条跳回原文该句并高亮

**旅程 C · 无网使用**

断网打开应用 → 内容包与解析全部来自本地库 → 全部功能可用（本产品没有任何网络请求）

| 编号 | 功能 | 模块 | 边界 |
|---|---|---|---|
| F1 | 文章库 | 内容只读 | 只读内置内容包；无搜索/筛选（首版文章少，不做） |

## 四、MVP、后续版本与明确排除项

**MVP（本版）**：F1—F7，其中 F1 内容为 2—3 篇样板文章。

**二期**：篇级复习提醒（1/3/7/14 天）、PDF/HTML 导出、用户自助导入、生词三态（在学/已掌握/忽略）UI 暴露、批量内容铺到 24 篇。

**明确排除**：作答判分、实时 AI 生成、账号云同步、社交分享、支付、微信小程序、Electron、ORM、在线 Web 服务。

## 五、业务流程、业务规则与权限规则

### 5.1 内容包导入（启动时）

1. 读安装包内 `content-pack/manifest.json`（`packVersion` + 文章清单 + 每篇 `sourceKey`/`contentHash`）
2. 与本地 `app_meta` 中记录的 `packVersion` 比对
3. 不一致 → 逐篇 upsert：`sourceKey` 存在则**只更新内容字段**，不存在则插入；**绝不覆盖** `note`/`vocab` 表
4. 写入新 `packVersion`
5. 全过程在一个事务内；失败回滚并保留旧版本可用

### 5.2 阅读位置恢复

每篇记录「上次滚动到的句子 id + 偏移」；进入阅读页时恢复到该句；用户手动回到顶部则清空。

### 5.3 笔记保存

输入停止 600ms → 写库；写库前把内容写 `localStorage` 草稿；成功后清草稿；失败保留草稿并显示「未保存，点此重试」。

### 5.4 生词收藏

以 `normalized`（小写、去首尾非字母数字、保留撇号和连字符）去重。已存在则只更新「最后出现位置」，不重复插入。

### 5.5 未收录内容的降级规则（**关键**）

内容包是预生成的，必然存在「这个词/这句没有被生成解析」的情况。规则：

1. **任意 token 都可点**——不存在「点不动」的词
2. 有解析 → 正常词卡
3. 无解析 → 词卡显示该词词形 + 明确灰字提示「本词暂无预置解析」，并提供「加入生词本」（仍可用）
4. 句子无解析同理：句卡显示「本句暂无预置解析」，但「本句重点词」列表仍可点
5. **不允许**静默无反应、不允许把未收录伪装成已收录

### 5.6 不做判分的视觉约束

题目选项**置灰 + 禁用光标**，题目区顶部固定一行「本应用只展示题目与答案，不做作答与判分」。点选项必须**零状态变化**（不选中、不弹提示）。

### 5.7 权限

无账号、无权限；不发起任何网络请求（可用网络面板验证）。

## 六、主要数据对象及关系

| 对象 | 关键字段 | 关系 |
|---|---|---|
| `article` | id, sourceKey, title, year, paper, section, wordCount, contentHash, packVersion | 1—N paragraph |
| `paragraph` | id, articleId, idx, text | 1—N sentence |
| `sentence` | id, paragraphId, idx, startOffset, endOffset, text | 1—N token；1—1 sentenceAnalysis |
| `token` | id, sentenceId, idx, startOffset, endOffset, surface, normalized, isWord | N—1 sentence；1—1 tokenAnalysis |
| `sentence_analysis` | sentenceId, translation, grammarJson, phrasesJson | 1—1 sentence |
| `token_analysis` | tokenId, phonetic, pos, senseInContext, collocationsJson, examplesJson, isCet4HighFreq | 1—1 token |
| `note` | id, targetType(sentence/token), targetId, content, updatedAt | 多态指向句/词 |
| `vocab` | id, normalized, surface, firstArticleId, firstSentenceId, senseInContext, state(new/learning/known/ignored), createdAt | 独立，按 normalized 唯一 |
| `app_meta` | key, value | packVersion、字号、阅读位置等 |

**偏移口径**：所有 offset 一律 **UTF-16 code unit**，句子偏移相对段落文本、token 偏移相对句子文本（沿用 docs ADR-008，前端 `slice` 天然一致）。

**为何 token 级要存「语境义」**：用户的原话是「单词在外面的意思和在具体的句子中的意思也不一样」。同一个 `address` 在两句里可以是「地址」和「应对」，所以释义挂在 **token（句子内位置）** 上，而不是挂在词形上。生词本聚合时才把该词最近一次的语境义带过去。

## 七、页面清单、页面状态与关键交互

### 7.1 文章库

- 正常：文章卡片列表（标题 / 年份 / 题型 / 词数 / 已收藏生词数）
- 空数据：内容包为空时显示「内容包缺失，请重新安装」
- 错误：读取失败显示错误码 + 重试

### 7.2 阅读页（核心）

布局：顶栏（返回 / 标题 / 字号）→ 题目区（折叠）→ 正文区 → 底部抽屉（按需）

- **句子**：正常段落文本，句末一个 12×12 的小「析」标记（灰色，可点区域 32×32）
- **点击语义**：点词 → 词卡；点「析」→ 句卡。二者互斥不冲突（用户已裁决）
- **已收藏的词**：加下划线 + 词后小圆点（**双通道**，不靠单一颜色）；图例在顶栏「?」里
- **有笔记的句子**：句子左侧 2px 竖线
- **抽屉**：高度 ≤ 55% 屏高，圆角顶部；打开时把被点的句/词滚动到抽屉上沿以上；下滑手势关闭；抽屉内**不再叠加任何浮层**（气泡/二次弹窗一律不做）
- **句卡内容顺序**：句译 → 语法拆解 → 短语与固定搭配 → 本句重点词（可点，点了切到词卡）
- **词卡内容顺序**：词形+音标 → 本句释义（最显眼）→ 词性/搭配/例句 → 加入生词本 → 笔记框
- 状态：正常 / 该句无解析（灰字提示）/ 加载中（骨架，本地数据通常不可见）/ 错误（错误码+重试）

### 7.3 生词本

- 正常：按文章分组，每条「词 + 本句片段 + 本句释义 + 展开更多」
- 空数据：「还没有生词，去阅读页点词收藏」
- 交互：点一条 → 跳回原文该句并高亮；左滑/长按移除

### 7.4 设置与关于

字号（小/中/大）、主题跟随系统、版本号、开源许可、内容说明与免责声明。

## 八、异常、空数据、无权限、处理中、失败恢复场景

| 场景 | 表现 | 恢复 |
|---|---|---|
| 内容包缺失/损坏 | 启动时提示「内容包异常」 | 提示重装；不进入空壳应用 |
| 数据库损坏 | 启动提示 + 备份路径 | 自动备份为 `app.db.bak-日期`，重建空库并保留备份可恢复 |
| 笔记保存失败 | 抽屉内红字「未保存，点此重试」 | 草稿在 localStorage，重试成功即清 |
| 词/句无解析 | 灰字「暂无预置解析」 | 仍可收藏、仍可写笔记 |
| 文章被内容包移除（未来） | 生词本里显示「原文已下架」 | 保留词条与释义，不丢用户数据 |
| 无网络 | 无任何影响 | 本产品不发起网络请求 |

## 九、接口、集成、性能、安全与部署约束

### 9.1 对外接口（Tauri commands，最小集）

`list_articles` / `get_article_content(articleId)` / `get_sentence_analysis(sentenceId)` / `get_token_analysis(tokenId)` / `upsert_note(targetType,targetId,content)` / `add_vocab(tokenId)` / `list_vocab(groupByArticle)` / `remove_vocab(vocabId)` / `get_reading_position` / `save_reading_position` / `get_app_meta` / `set_app_meta`

统一返回 `Result<T, CommandError{code,message}>`；前端只经 `src/lib/api.ts` 调用，不出现裸 `invoke` 字符串。

### 9.2 性能约束

| 指标 | 目标 |
|---|---|
| 冷启动到文章库可用 | < 3s |
| 点击词/「析」到抽屉内容可见 | < 300ms |
| 抽屉开合后原文位置偏移 | 0（锚点保持） |
| 安装包体积 | < 30MB |
| 单篇解析数据体积 | < 300KB（估算：约 25 句 × 200 字句译 + 重点词释义） |

### 9.3 安全与合规

- 全程无网络请求；无账号、无埋点、不上传
- 内容为外部真题素材，随包提供「内容来源与免责声明」，版权责任由使用者/分发者承担（沿用 docs R01 已接受风险）
- 读取文件仅限应用数据目录

### 9.4 部署

Windows 安装包（`.msi`/`.exe`）由 Tauri 构建；Android 为二期。无服务器、无后端。

| 编号 | 验收标准（可测） |

## 十一、风险与待决策事项

**风险**

| 风险 | 影响 | 应对 |
|---|---|---|
| AI 生成的解析质量不稳（误译、语法拆错） | 用户学着错的东西，比没有更糟 | 生成后抽样校对；抽样不过关不进包；每篇留「纠错反馈」入口（二期） |
| 预生成「漏标」 | 用户点词没反应，体验断裂 | 5.5 降级规则 + AC4 全量可点验证 |
| 内容包体积 | 装包超 30MB | 只对重点词生成词级解析；体积脚本卡口 |
| 抽屉遮挡原文 | 精读时上下文断掉 | 高度 ≤55% + 打开时滚动锚定；AC5 验证 |
| 桌面构建环境（MSVC） | 出不了安装包 | 已定位，用户补装后验证 cargo 编译 |

**待决策事项（设计决策清点输入）**

- Q3 解析内容的生成与抽检流程（谁跑、抽检比例、错了怎么改）
- Q4 生词本最小「回看」形态（无复习提醒时如何促使用户再看）
- Q5 产品名称
- Q6 题目选项是否允许点击（方案已定「不可点 + 常驻说明」，需用户确认）
- Q8 解析内容的详细度上限（每句语法要拆到什么粒度：只标主谓宾，还是标到从句层级）

## 十二、调研启示的采用/拒绝映射

| 外部发现 | 采用/拒绝 | 理由 | 影响 | 对应需求/页面/验收项 |
|---|---|---|---|---|
| Readlang 至今不做整句翻译（创始人 2025-12 官方声明） | 采用（作为差异化依据） | 句级解析是空白，不是跟随 | 产品定位成立 | F3 / 全文 |
| Readlang 同屏开气泡+侧栏两浮层 → 遮挡、位置错乱 | 拒绝该形态 | 双浮层必然互相打架 | 抽屉内不再叠任何浮层 | 7.2 / AC5 |
| Readlang 用分页翻页，所以开合侧栏不丢位置 | 拒绝分页，采用其「位置保持」目标 | 手机长滚动更符合阅读习惯 | 需显式做滚动锚点 | 7.2 / AC5 |
| Readlang 点词后自动生成闪卡（零摩擦收藏） | 采用 | 收藏动作要一步到位 | 词卡里「加入生词本」一键 | F4 / F6 |
| Readlang 生词条目自带原文出处片段 | 采用 | 无语境回看价值低 | 生词本每条带本句片段 | F6 / AC9 |
| 扇贝「单击查词 + 长按讲句」避冲突 | 部分拒绝 | 长按是隐藏操作，新用户发现不了 | 改用「点词直达 + 句尾析触点」（用户裁决） | 7.2 / AC1 |
| 扇贝短语白名单导致用户点不到未标注短语（用户投诉原话） | 采用其教训 | 预生成包必然漏标 | 任意 token 可点 + 未收录降级提示 + 覆盖率统计 | 5.5 / AC4 |
| 扇贝译文锁在会员后、每次点词弹会员提示 | 拒绝 | 本产品全免费全离线 | 无任何付费墙与提示 | 全文 |
| 扇贝缺字号调节与阅读位置恢复（用户点名） | 采用 | 精读常读长文，这是基础体验 | 首版就做字号 + 位置恢复 | 7.2 / F2 |
| LingQ 词本位、句子能力被隔离成独立模式，用户找不到句译入口 | 拒绝该结构 | 本产品以句为一级入口 | 句「析」触点必须显眼可见 | 7.2 / AC1 |
| LingQ 颜色编码单通道，用户抱怨看不懂蓝词黄词 | 采用其教训 | 只靠颜色=有色盲用户丢失信息 | 下划线+圆点双通道 + 图例 | 7.2 / AC7 |
| LingQ 抽屉 vs 气泡的容量权衡（建议 ≤50—60% 屏高 + 滚动锚定） | 采用 | 半屏塞不下五块内容 | 抽屉 ≤55% + 锚定 + 句卡内可滚动 | 7.2 / AC5 |
| LingQ 短语可追踪、系统未预置搭配讲解 | 采用「预留来源字段」 | 二期要加用户短语时不用改表 | `phrase` 表带 source(system/user) | 六 / 二期 |
| LingQ 生词四态（New/Learning/Known/Ignored） | 部分采用（仅建字段） | 首版 UI 简化，但表要能承载 | `vocab.state` 预留 | 六 / 二期 |
| 星火解析是判分下游的逐题定位式，无句级/语法证据 | 采用其教训 | 说明「不做判分 + 做句级解析」无直接竞争 | 定位成立 | 全文 |

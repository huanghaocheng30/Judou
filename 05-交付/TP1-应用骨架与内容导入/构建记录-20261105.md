## 六、异常与处置

1. **msi 安装包未产出（WiX 工具链下载停滞）**：默认目标的 msi 分支需下载 `wix314-binaries.zip`（41 MB），首次报 `failed to bundle project: Peer disconnected`，重试时手动下载进度停滞（3 分钟仅增 230 KB）。**处置**：显式 `--bundles nsis` 收窄目标，交付 NSIS 安装包。两形态安装体验一致，AC7 允许「`.msi` 或 `.exe`」，不构成不通过。后续若需要 msi：把 WiX 工具包放入 `%LOCALAPPDATA%\tauri\WixTools` 后重跑 `--bundles msi`。
2. **NSIS 工具链同样走网络**：首轮报 `timeout: global`。**处置**：手动下载 `nsis-3.13.zip`（2.36 MB）解压到 `%LOCALAPPDATA%\tauri\NSIS`，第二轮 bundler 复用本地副本成功（日志 `Info validating hash / extracting NSIS` 后直接 `Running makensis`），`nsis_tauri_utils-0.5.3.dll` 由 bundler 自行下载成功。
3. **构建器调用方式**：`cmd /c "脚本 > log 2>&1"` 与 `npx tauri` 在本机均失败（重定向写出 0 字节 / `could not determine executable to run`）。**处置**：改为 pwsh 内注入 vcvars 环境后直接 `node ./node_modules/@tauri-apps/cli/tauri.js build`，日志用 `*>` 全流重放落盘。
4. **dev 进程终止方式（评审要求记录）**：开发员 `pnpm tauri dev` 日志尾部有 `error: process didn't exit successfully … exit code: 1`，属验证后主动停止（Tauri dev 进程被 kill 时 cargo-run 包装器报非零），不是应用崩溃；本次构建后我另用 release 二进制独立跑通导入，进一步排除该疑点。

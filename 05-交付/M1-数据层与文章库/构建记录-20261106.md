## 六、异常与处置

### 6.1 本轮有意不产桌面安装包

沿用 M0 的收窄口径：本包 AC5 只要求「构建产物 + 测试入口说明」，**安装态观感与打包归 M7**。理由三条：
1. 本轮测试形态是 `npm run tauri dev`（源码运行），安装包对验证 M1 的功能无增益；
2. `tauri build` 属分钟级以上、且会重新拉依赖与签名配置（签名为 M7 前置，当前未就绪）——在 `02-代码/` 还会触发 vite watcher 的 `EBUSY` 已知问题；
3. `05-交付/安装包/CET4-阅读精读-v0.1.0/` 里那个 `setup.exe` 是 TP1（1.0 预设时代、产品旧名）的历史遗留，**不动它**，M7 会用新名字（句读）另建目录。

### 6.2 门禁清单的一处口径修正（本轮自查发现）

首次跑门禁时我把 `check-tables` 当成 npm script（`npm run check-tables` → `Missing script`，EXIT=1）。核查 `package.json` 后确认：**该脚本从 M0 起就没有 npm script**，一直是 `node scripts/check-tables.mjs` 直接调用；`check-icons` 同理。这不是回归、也不是本包缺陷，是我的命令写法错。已按正确方式重跑并覆盖日志（现 12/12 EXIT=0）。

> 顺带登记（不修，属 M0 遗留口径）：`check-tables` / `check-icons` 未登记为 npm script，`verify:*` 前缀覆盖不全。留待 M7 统一 CI 脚本时一起收。

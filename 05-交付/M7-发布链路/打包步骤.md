# 打包步骤 · 句读 v0.2.0（Windows NSIS 安装包）

> 面向：本机开发者（人工级操作）。**这是一次性人工动作，CI 不自动跑它**（`02 §四.4` 派工黑名单：交付级构建归用户）。
> 目标：一条命令出 `句读_0.2.0_x64-setup.exe`，中途不需要临时排错。

---

## ① 前置（开工前确认这四项）

| 项 | 怎么确认 | 期望 |
|---|---|---|
| Node.js 已装 | `node -v` | 有版本号（本仓库开发用 v20+） |
| Rust 工具链已装 | `rustc -V`；`cargo -V` | 两条都有版本号（`stable-x86_64-pc-windows-msvc`） |
| 前端依赖已装 | 在 `02-代码` 下跑 `npm ci`（或 `npm install`） | EXIT=0，生成 `02-代码/node_modules` |
| WebView2 运行时 | Win10/11 一般自带；缺了见 ⑤-1 | 能打开任意 Edge（同内核） |

> `npm ci` 只需在换机器 / 换 lockfile 后跑一次，不是每次打包都跑。

---

## ② 一条命令

在 **`E:\Judou\02-代码`** 目录下执行：

```
npm run tauri build
```

> 等价于 `npx tauri build`。`tauri.conf.json` 已把 `bundle.targets` 收紧为 `["nsis"]`，
> 所以**不需要**再手加 `--bundles nsis`，也不会顺带出 `.msi`（msi 需要 WiX 工具链，本机没装）。
> `beforeBuildCommand` 会自动先跑 `npm run build`（tsc + vite），无需手动构建前端。

```
02-代码/src-tauri/target/release/句读.exe                                  ← 主程序（免安装也能直接双击）
02-代码/src-tauri/target/release/bundle/nsis/句读_0.2.0_x64-setup.exe       ← 要交付的安装包
```

- 打包成功后终端最后几行会打印 `Finished 1 bundle at: ...\bundle\nsis\句读_0.2.0_x64-setup.exe`。

## ④ 预期耗时

| 场景 | 耗时 | 说明 |
|---|---|---|
| **首次全量编译** | **5~10 分钟** | Rust 依赖（tauri / rusqlite bundled / sha2）全量编一遍，期间终端长时间停在 `Compiling ...` 是正常的，**不要以为卡死** |
| 改代码后再打 | 1~3 分钟 | 增量编译 |
| 只改前端 | 30 秒~1 分钟 | Rust 侧全部命中缓存 |

> 判断「真卡住」还是「在编译」：看终端是否持续有新行输出（`Compiling <crate>` 逐个变），
> 以及任务管理器里 `rustc.exe` / `cargo.exe` 是否在吃 CPU。

## ⑤ 常见失败与修法（3 条）

### 1. 报 WebView2 相关错误（`WebView2 runtime not found` / 安装后白屏）

- **原因**：Windows 未预装 WebView2 运行时（老 Win10 / 精简系统）。
- **修法**：装微软官方 Evergreen 运行时
  <https://developer.microsoft.com/microsoft-edge/webview2/>（选 Evergreen Standalone Installer），装完重跑 ② 的命令。
- **安装包侧**：`currentUser` 模式下 NSIS 会在装的时候检测并引导装 WebView2，**不需要**你在 `tauri.conf.json` 里嵌离线安装器。

### 2. 报磁盘空间不足 / `No space left on device` / 链接失败 `LNK1104`

- **原因**：`target/release` 全量编译需要 **3~6 GB**（debug 与 release 各一套时更多）。
- **修法**：确认 `E:\` 可用空间 ≥ 10 GB；不够就先清 `02-代码/src-tauri/target/debug`（可安全删，下次编译重建）。
  彻底重来：删整个 `target` 目录后重跑（代价=再等一次 5~10 分钟全量）。

### 3. 中文路径 / 中文项目名导致编译或打包失败

- **原因**：MSVC 链接器与部分构建脚本对非 ASCII 路径敏感；本仓库路径 `E:\Judou` 本身是纯 ASCII，但
  `target` 目录若被指到含中文的路径（如 `C:\用户\...\桌面`）就会炸；另 NSIS 脚本对 `productName`（`句读`）是 UTF-8 处理的，正常。
- **修法**：确认 `CARGO_TARGET_DIR` 未被设成含中文/空格的路径（`echo $env:CARGO_TARGET_DIR` 应为空）；
  若必须改输出目录，用纯 ASCII 绝对路径，例如 `E:\build-target`。**不要**为了绕开它去改 `productName` 或 `identifier`
  ——`identifier`（`com.judou.app`）改了等于换一个应用，用户数据目录会丢。

## ⑥ 装完怎么验（4 步）

1. **双击** `句读_0.2.0_x64-setup.exe` → 因 `installMode: currentUser`，**不弹 UAC**，直接装到
   `%LOCALAPPDATA%\句读`（或安装向导里显示的当前用户目录）。
2. **从开始菜单启动「句读」** → 主窗口能正常出现（1200×800，无白屏、无 WebView2 报错）。
3. **翻内置 12 篇**：侧栏「文章库」应列出 12 篇内置文章，任选 3 篇点开 → 正文能渲染、生词能点、精读面板不报错。
   （判据：12 篇**全部**都在列表里、且能打开；只验 1 篇不算过。）
4. **卸载干净**：设置 → 应用 → 「句读」→ 卸载 → 确认 `%LOCALAPPDATA%\句读` 目录已清；
   若你之前用过开发版，用户数据在 `%APPDATA%\com.judou.app`（**卸载不删它，属预期**——避免误删用户笔记）。

> 验完把结果回一句「安装包验过，12 篇能读」或具体问题描述即可，不用截图。

## 附：本文件对应的配置现状（改配置的人看这里）

| 配置项 | 值 | 为什么 |
|---|---|---|
| `bundle.targets` | `["nsis"]` | `"all"` 会在 Windows 上连带 `msi`，需 WiX 工具链与本地化缓存 → 大概率打包失败 |
| `bundle.windows.nsis.installMode` | `currentUser` | 免 UAC、装到用户目录、卸载干净（不用管理员权限） |
| `bundle.windows.nsis.languages` | `["SimpChinese"]` | 只出简体中文安装向导，不做多语言资源 |
| `bundle.windows.nsis.displayLanguageSelector` | `false` | 只有一种语言，不弹语言选择框 |
| `version` | `0.2.0` | 与 `package.json` / `src-tauri/Cargo.toml` **三处一致**（由 `npm run verify:release` 断言） |
| `identifier` | `com.judou.app` | **不动**：改了等于换应用、丢用户数据 |

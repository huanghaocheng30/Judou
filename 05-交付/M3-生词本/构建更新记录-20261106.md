## 六、一个已修的环境坑（留账，供下次构建参考）

**现象**：首次 `cargo test --offline` 返回 **EXIT=1**，但 `test result: ok. 31 passed; 0 failed` 已经打出。

**根因**：失败发生在 **Doc-tests** 阶段，rustdoc 报
`error: extern location for rusqlite does not exist: target\debug\deps\librusqlite-e0f293dd5f0144ef.rlib`
—— `target/deps` 里该 rlib 缺失，属**构建产物缓存不一致**，不是代码缺陷（本项目 doctest 实为 0 个）。

**处置**：先 `cargo build --offline`（EXIT=0，补齐 rlib）→ 再 `cargo test --offline` → **EXIT=0**。

**教训**：`cargo test` 的 EXIT 码会被 doc-test 阶段污染；判「单测是否全过」要看 `test result:` 行，判「门禁是否绿」要看 EXIT 码——两者不一致时必须查清是哪一阶段。这条已记入构建记录的留账，**不是产品问题、不需回滚**。

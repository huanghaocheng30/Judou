## 二、修了什么

**用户原话**：「M4 中只有『今日到期 0 篇』，没有之后的计划欸，至少得有明天的安排吧，是不是没有设计完整啊」

**根因：设计缺口**（不是代码 bug）。04 §八 的复习页只设计了「无到期 / 有到期 N 篇 / 已完成今日」三态，**没有「未来计划」视角** → 计划在未来的文章在界面上完全不可见。

**更讽刺的是**：修复时的 F0 实测发现库里已有 **6 条 active 计划，全部在未来**——用户有 6 篇待复习安排，界面上却一篇都不显示。

**修法**（2 文件 +117/−8，零新命令）：

| 段 | 内容 |
|---|---|
| 今日到期（N 篇） | 现状不变 |
| **接下来（新增）** | `listReviewPlans()` 里 `status='active' && nextReviewAt > today`，按日期升序（同日按 `articleId` 稳定排序）；每行：标题 / 相对标签（明天、3 天后）/ `MM-DD` / 第 N/4 次 /「待到期」；**不可开始复习**（未到期就允许复习会让四档失去意义） |
| 已完成 | 现状不变（可重新加入复习） |

**空态分级也修了**（AC-R4②，这是原设计的第二个问题）：原来「今天没有到期的复习」在**有未来安排**时也会显示 → 用户以为没安排。现在 `upcoming > 0` 时改显示「今天没有到期的复习，**接下来的安排在下面**」。

## 五、⚠ 一条判据失效（本包发现的教训，必须留账）

**AC-R3 原文**：`upcoming 段内 [data-review-start] 计数 = 0`。

**问题**：`data-review-start` 这个属性**在源码里从来不存在**——到期行的「开始复习」实际是 `className="btn review-start"`，是**类名**，不是 `data-*` 属性。所以选择器 `[data-review-start]` 选的是**空集**，`count = 0` **恒真**——这条判据**没有任何区分力**。

**性质**：与 M2 的「Esc 用合成事件测 57/57 全绿，但真实 Esc 从未绑上」是**同一类错误**：**判据在形式上通过，因为它什么都没测**。

**补救**：AC-R3 的实质已由更强证据成立——审核员源码级核了 `upcoming` 段的 `<a>`、`href=`、`onClick` **全部为 0**（这比数一个不存在的 data 属性可靠）。判据文本待改。

**登记债务 D-M4-7**：M4 的 02 与 cdp 脚本里 `[data-review-start]` 应统一改为 `.review-start`（类名）。**下次触碰 M4 判据时必修。**
